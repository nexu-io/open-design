# Open Design 报错体验设计方案(v1 · 请评审)

> 这是一套完整的设计,不是选择题:每个场景写清**什么时候出现、出现在哪、长什么样、点了之后怎样**,并附界面内效果图。觉得哪里不对,直接在那一段评论。  
> 依据(代码、埋点、飞书原话)在附录:https://powerformer.feishu.cn/docx/DFCKdpcvhoBwQPxqL9bcZbkBnx1。「每月 N 次」= 近 30 天埋点;「飞书 N 条」= 近 30 天群里反馈。要排先做哪个,直接看文末《线上频次与优先级》那张表(8 月 24 日重新拉的数,统一口径 + 环比)。

## 1. 五条原则

1. **能在发送前知道的,不让发**:没装、没登录、没配 key、没余额、并发满,都在发送前说,不产生失败。
2. **系统能自己救的,不打扰**:限速等一会儿、断线接着跑、会话过期重建,用户最多看到一行「正在重试」。
3. **等待要有回音**:超过 60 秒没动静,转圈旁边要说「在等什么、等了多久」;不到超时不报错。
4. **「重试」只在有用时出现**:额度用完、账号被封、CPU 不支持这类重试无效的场景,不给重试,给真正能解决问题的按钮。
5. **文案说人话,说清不怪用户,给下一步**:标题一句话说发生了什么,正文一两句说为什么和怎么办。

## 2. 报错显示在哪

| 显示方式 | 位置 | 什么时候 |
|-|-|-|
| 发送前提示 | 输入框上方一条,或 agent / 模型选择器里 | 点发送之前就能判定 |
| 对话里的报错卡 | 对话流里,跟在失败的那条回复后面 | 跑到一半失败,需要用户做点什么 |
| 进行中提示 | 对话流里,替代转圈那一行 | 还在跑但慢,或正在重连 |
| 顶部横幅 | 整个窗口顶部 | 账号或环境的问题,不属于某一次对话 |
| 弹窗 | 居中 | 必须打断:余额、启动失败、更新 |
| 右下角小提示 | 右下角,几秒消失 | 一次性小失败 |
| 预览区内提示 | 右侧预览区里 | 预览本身加载不出来 |

**按钮一共这些**:重试 / 继续运行 / 登录 / 授权并重试 / 去充值 / 升级套餐 / 通知管理员 / 更换模型 / 新建对话 / 去设置 / 查看安装指引 / 稍后重试(倒计时)/ 导出日志 / 联系支持。一张卡一个主按钮,最多加一个次按钮。

## 3. 统一规则

| 规则 | 设计 |
|-|-|
| 自动重试 | 模型服务商报错、断线、空输出:在还没任何输出时自动重试 2 次(间隔 1s、3s),对话里只显示一行「正在重试 2/2」;有输出后不再自动重试,改给「继续运行」 |
| 等待 | 60 秒没新输出显示「上游响应慢,已等 N 秒」+〔停止〕;10 分钟(Cloud 30 分钟)没输出才报超时 |
| 限速 | 服务商给了恢复时间的,按钮倒计时、到点自动重试一次;没给的只倒计时;并发满自动排队 |
| 推荐 Open Design 智能体 | 只在「本地 agent 没登录」和「供应商额度用完」两张卡上出现;Cloud 用户自己不出现 |
| 团队 vs 个人 | 钱相关的卡分两版:个人看「去充值」,团队成员看「通知管理员」(能管账单的人才看到「去充值」) |
| 付费用户余额 0 | 个人付费套餐余额 0 = 不限量,不拦;团队工作区按钱包拦 |
| 原始错误 | 每张报错卡可展开看原始错误;一行都没有时显示「没有更多信息」并给「导出日志」 |
| 做了一半 | 有没做完的待办:加「继续运行」;文件生成了但进程报错:算成功,加一行「过程中报过错,文件已生成,可查看日志」 |

## 4. 以前待定的 14 件事,这版的决定

| 事项 | 决定 | 为什么 |
|-|-|-|
| 报错要不要分几种显示方式 | 分(第 2 节的七种),工程上只新做「顶部横幅」「进行中提示」两样 | 今天的问题不是卡不够,是该拦的没拦、该说的没说 |
| 发送前拦不拦 | 拦:没装、没登录、没配 key、没余额、并发满 | 这些失败每月约 2 万次,发送前都能知道 |
| 「重试」给谁 | 只给重试有用的场景 | 额度用完 2.3 万次点重试全是白点 |
| 推荐 Open Design 智能体 | 只在没登录、供应商额度用完两处 | 这是用户最愿意换的时刻;别处是噪音 |
| 团队成员额度不够 | 看「通知管理员」 | 今天跳到个人充值页,充了也不是团队的钱 |
| 付费余额 0 | 不限量,不拦 | 后端和套餐页已按不限量处理,只有客户端还在拦 |
| 套餐变了 | 顶部横幅说一次 | 今天什么都不说,用户以为坏了 |
| 限速到点自动重试 | 有恢复时间的自动 | 用户不该盯着倒计时 |
| 断线重连显示 | 接设计稿里的「正在重新连接 2/5」;「本地服务不可达」合成一条横幅 | 今天零显示、5 处 5 种说法 |
| 客户端起不来 | 做启动失败页 | 每天 100–190 台设备无声消失 |
| 账号被封 | 只给「联系支持」 | 重试没意义 |
| 内容被拒 | 能识别的四种单独说,其它不变 | 重试也没用,要改提示词 |
| 做了一半 | 前者给「继续运行」,后者算成功加一行提示 | 改成失败会把一堆无害报错变成失败潮 |
| 先做哪些 | 第 6 节 | 按影响人数 × 我们能改 |

## 5. 场景设计

每个场景:**时机**(什么时候出现)/ **位置** / **显示**(文案与按钮,见图)/ **点了之后** / 多常见 / 今天。

### 一、发之前就拦住

#### S01 · 本地 agent 没安装

> **效果图**(见飞书原文):这张图是Open Design报错体验的场景设计配图，对应“发之前就拦住”的S01场景，展示了本地agent未安装时的界面。界面里明确提示“还没装{智能体}——这台电脑上找不到{智能体}的命令行工具，装好后点「重新检测」就能用”，设有“重新检测”“查看安装指引”两个按钮，和上下文描述的显示内容、交互功能完全匹配，呈现了对应报错场景的实际界面样式。

**时机**:打开 agent 选择器、或选中一个没装的 agent 时;已选中的 agent 被卸载了,点发送时。  
**位置**:输入框上方(选择器里同样标「未安装」)。  
**显示**:还没装 {智能体} —— 这台电脑上找不到 {智能体} 的命令行工具,装好后点「重新检测」就能用。〔查看安装指引 | 重新检测〕  
**点了之后**:安装指引开文档;重新检测刷新探测,装好了提示消失。  
多常见:每月 2,357 次 · 占失败 1.8% · 1,062 台设备 · 环比 ↓42% · P2。今天:发出去才失败,显示「Agent not installed」+ 重试。  
对应工程条目:R-006、R-020

#### S02 · 本地 agent 没登录 / 登录过期

> **效果图**(见飞书原文):图片展示的是Open Design报错体验设计方案中“本地agent没登录”场景的原型界面。左侧为原型界面，显示“智能体还没登录”，提示在终端运行登录命令登录一次，推荐Open Design智能体，可去这一步，有“重试”和“在终端登录”按钮。下方有“接着改点什么...”输入框及“Opus 5”标识。右侧是“index.html”预览界面，呈现多个灰色矩形区域。该图片与文档中“本地agent没登录”场景设计内容相关，直观呈现了报错时的界面样式及交互提示。

**时机**:发送前探测到没登录就拦;跑到一半发现登录过期,对话里出卡。  
**位置**:发送前在输入框上方;运行中在对话里。  
**显示**:{智能体} 还没登录 —— 在终端运行 {登录命令} 登录一次,回来就能继续。非 Cloud 用户多一句:推荐 Open Design 智能体,省去这一步。〔在终端登录 | 重试〕  
**点了之后**:能拉起终端的 agent 直接拉起并填好命令;登录后重试。  
多常见:每月 14,519 次 · 占失败 11.4% · 5,395 台设备 · 环比 ↓40% · P1。今天:「Sign-in required」+ 英文 + 重试 + 切换卡。  
对应工程条目:R-007、R-075

#### S03 · Open Design 账号登录过期

> **效果图**(见飞书原文):图片展示的是Open Design账号登录过期的报错体验设计方案。左侧为消息提示框，显示“登录已过期，登录后才能看到你的项目和继续对话”，并有“登录”按钮。右侧是商品列表页的预览界面，包含多个商品卡片。该图片与文档中“S03·Open Design账号登录过期”场景设计相关，直观呈现了报错时的界面样式及登录后可看到的项目内容，辅助说明报错时机、位置及点击后的效果。

**时机**:任何请求返回未登录时。  
**位置**:窗口顶部横幅,页面不跳走。  
**显示**:登录已过期,登录后才能看到你的项目和继续对话。〔登录〕  
**点了之后**:原地弹登录,完成后回到原页面,横幅消失。  
多常见:埋点里没有独立分类,只能按飞书估:17 条 · P2。今天:直接跳到登录页,本地项目「消失」没解释。  
对应工程条目:R-004、R-103

#### S04 · Open Design 智能体没登录 / 授权过期

> **效果图**(见飞书原文):这是Open Design报错体验设计方案相关的场景原型图，对应S04“Open Design智能体没登录/授权过期”的场景。图左侧是商城原型编辑区域，红色提示内容为“先登录Open Design智能体，登录后这个任务会自动继续”，搭配“授权并重试”按钮，呈现拦截未授权状态的设计；上方还有“把这一屏重做成能调的原型，再加一个视觉风格一致的设置页”的标注，当前已完成进度为12%，右下角标注有Opus 5标识。

**时机**:发送前检查到没授权就拦;运行中失效出卡。  
**位置**:对话里(今天的位置)。  
**显示**:先登录 Open Design 智能体 —— 登录后这个任务会自动继续。〔授权并重试〕  
**点了之后**:对话里完成授权,自动接着跑(今天已经这样)。  
多常见:并入 S02 的登录类一起计,不单独统计 · 随 S02(P1)。今天:已有,只是英文。  
对应工程条目:R-008

#### S05 · 自带 API key 没配好

> **效果图**(见飞书原文):图片展示的是Open Design报错体验设计方案中“自带API key没配好”场景的界面。左侧为“商城原型”，显示“商品列表页和设置页都做完了，商品卡已经做成共享组件”，并提示“还差API key没填，填好就能开始”，有“去设置”按钮。右侧是“预览 - index.html”，呈现商品列表样式。该图片与上下文紧密相关，直观呈现了发送前因自带API key没配好而被拦住的报错场景，辅助说明报错时机为点发送时，位置在输入框上方，显示“还差API key没填,填好就能开始”，并有“去设置”按钮，多常见于发送前拦住，不产生失败。

**时机**:点发送时。  
**位置**:输入框上方。  
**显示**:还差 {API key / 模型 / 服务地址} 没填,填好就能开始。〔去设置〕  
**点了之后**:打开设置并聚焦到缺的那一项。  
多常见:发送前就拦住了,不产生失败,所以埋点里看不到 —— 这是好事 · P2。今天:已拦,提示是写死的英文。  
对应工程条目:R-009

#### S06 · 余额不够 / 为 0

> **效果图**(见飞书原文):图片展示的是“余额不够/为0”场景设计中“发之前就拦住”部分的居中弹窗原型。弹窗显示“额度用完了”，并说明充值或升级套餐后任务会自动开始，有“先不了”“升级套餐”“去充值”三个按钮。该图片与上下文紧密相关，直观呈现了发之前就拦住时机为点发送时，余额不足时的弹窗样式及操作选项，帮助理解该场景的设计内容。

> **效果图**(见飞书原文):这张图片展示的是Open Design报错体验设计方案中S06场景的原型效果，对应付费团队的余额/额度不足报错弹窗场景。该弹窗在用户点击发送时触发，以居中形式展示，内容为“团队额度用完了，需要管理员充值，到账后这个任务会自动继续”，弹窗提供“先不了”和“通知管理员”两个操作选项，呈现了该场景的交互反馈原型。

**时机**:点发送时。付费个人套餐余额 0 不拦;刚购买还没到账不拦,显示「套餐开通中」。  
**位置**:居中弹窗。  
**显示**:个人:额度用完了 —— 充值或升级套餐后,这个任务会自动开始。〔去充值 | 升级套餐 | 先不了〕 团队成员:这个团队的额度用完了 —— 需要管理员充值,到账后这个任务会自动继续。〔通知管理员 | 先不了〕  
**点了之后**:充值 / 升级页面开新标签,到账后弹窗自动关闭、任务自动开始;「通知管理员」复制一段带链接的话。  
多常见:同样发送前拦住,埋点看不到;飞书 20 条 + 26 条支付争议 · P1(涉及钱)。今天:余额 ≤ \$0 弹窗拦,不分套餐、不分个人团队。  
对应工程条目:R-010、R-102

#### S07 · 模型不在套餐里 / 已下线 / 并发满

> **效果图**(见飞书原文):该图片展示了Open Design发之前就拦住的场景设计相关内容，对应模型不在套餐里/已下线/并发满的报错提示界面。界面左侧的编辑区中，有明确的提示文本“《原模型》当前不可用，这次用《默认模型》完成”，对应上下文里换模型不可用时的处理说明，即提示用户原模型不可用，本次使用默认模型完成操作。编辑区还可见已完成进度、输入框及相关功能控件，右侧为网页预览区域，整体呈现了该报错场景的落地设计效果。

> **效果图**(见飞书原文):图片展示的是Open Design报错体验设计方案中“发之前就拦住”场景下S07“模型不在套餐里/已下线/并发满”时的界面。左侧显示“商城原型”已完成12s，商品列表页和设置页已做完，商品卡已做成共享组件。下方提示并发满，同时最多跑N个任务，等一个结束再发，或升级套餐，还有“稍后重试（排队自动发）”选项。右侧是“预览 - index.html”界面，显示多个空白矩形框。该图片直观呈现了报错提示样式及预览效果，与上下文对报错显示内容的描述相契合。

**时机**:选模型时锁定;运行时换了模型立刻提示;并发满在点发送时。  
**位置**:锁定在模型选择器里;换模型提示在对话里一行;并发满在输入框上方。  
**显示**:换了模型:{原模型} 当前不可用,这次用 {默认模型} 完成。 并发满:同时最多跑 {N} 个任务,等一个结束再发,或升级套餐。〔稍后重试(排队自动发)| 升级套餐〕  
**点了之后**:排队自动发,有空位就发出去。  
多常见:并发满与套餐锁定发生在发送前或选择器里,埋点无独立分类;飞书 13 条 · P2。今天:换模型不提示;并发满跑到一半才报错。  
对应工程条目:R-011、R-012

### 二、跑到一半,模型服务商那边出问题

#### S08 · 供应商额度用完

> **效果图**(见飞书原文):该图片是Open Design报错体验设计方案中，对应“供应商额度用完”场景的原型界面。界面中明确提示用户“{供应商}的额度用完了”，并说明此额度无法通过重试恢复，为用户提供了“去充值”“换一个key”或“换一个模型”的解决方案，同时配有“去设置”“更换模型”两个操作按钮；针对非Cloud用户，还会补充提示“用Open Design智能体不用自己管额度”，并提供“切到Open Design智能体”的操作选项，直观呈现了该场景下的报错反馈及功能指引。

**时机**:服务商返回额度用完,立刻出卡,不自动重试。  
**位置**:对话里。  
**显示**:{供应商} 的额度用完了 —— 这是你在 {供应商} 那边的额度,重试不会恢复。可以去充值、换一个 key,或换一个模型继续。〔更换模型 | 去设置〕 非 Cloud 用户多一句「用 Open Design 智能体不用自己管额度」+〔切到 Open Design 智能体〕。  
**点了之后**:更换模型直接打开模型选择器,选完自动重跑;切到 Open Design 智能体后自动重跑。  
多常见:每月 23,333 次 · 占失败 18.2% · 9,220 台设备 · 环比 ↑55% · **P0,最大的一类,而且还在涨**。今天:「Quota exhausted」,一个按钮都没有。

## 附:线上频次与优先级(2026-08-24 拉的数)

上面每个场景旁边的频次口径不统一(有的是次数、有的是飞书条数),不好横向比。这张表把它们放到同一个尺子上,用来排先做哪个。

**尺子怎么定的。**次数大不等于优先级高 —— 一个每月两万次但**用户点一下就能自己解决**的问题,比一个每月八千次但**用户完全没办法、只能来投诉的问题更不着急。所以这张表按两件事排:量**(每月次数、占失败总量、影响多少台设备)× **今天用户拿不到什么**(有没有可操作的下一步)。

**数据来源。**近 30 天 `run_finished` 埋点(共 127,873 次失败,失败率 12.34%;上一个 30 天是 210,163 次、15.65% —— 失败率在降)。「设备数」是去重设备,用来区分「一台机器刷屏」和「广泛影响」;同一场景归入多个失败类型时,设备数取其中最大的一类(设备会重叠,不能相加)。

### 三件顺带查出来的事

**一、用户自己按了停止,被记成了「失败」。**`interrupted` 这一类每月 3,040 次、1,716 台设备,而且从 7 月 19 日起由每周约 30 次涨到每周约 900 次。它既把失败率算高了,也意味着**用户主动停止之后可能看到了一张不该出现的报错卡** —— 这应该走 S24「做了一半」,不是报错。建议单独查一下这条链。

**二、有 12 个场景埋点里根本看不到,这本身是优先级信息。**分两种:

- **发送前就拦住了**(S05 没配 key、S06 余额不够、S07 并发满)—— 看不到是**好事**,说明拦住了,不产生失败。
