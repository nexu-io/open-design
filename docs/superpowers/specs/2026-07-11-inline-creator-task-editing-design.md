# 创作者任务卡片内编辑设计

## 目标

让 Creator Workbench 中人工创建的任务可以在原卡片内更新标题、说明、阶段、状态和优先级；当任务被标记为阻塞时，要求记录当前阻塞原因，并把每一次变更写入项目活动流。

## 范围

- 仅处理持久化的人工任务（ID 前缀为 `creator-task:`）。
- 旧的项目/运行状态推导任务维持只读：可打开所属项目，但不可编辑或推进。
- 不在本次加入删除、多人协作、提醒、评论、附件或任务历史详情页。

## 用户界面

每张人工任务卡保留已有的 `Advance` 与 `Open`，并增加 `Edit`。

点击 `Edit` 后，卡片下方原地展开表单，不使用弹窗。表单包含：

- 标题（必填）
- 说明（可选）
- 阶段：`topic`、`material`、`editing`、`release`、`review`
- 状态：`todo`、`ready`、`blocked`、`done`
- 优先级：`low`、`medium`、`high`
- 阻塞原因（仅当状态为 `blocked` 时显示，必填）

表单提供 `Save` 和 `Cancel`。保存期间禁用按钮，保存失败时沿用页面现有错误区域显示错误，原有表单内容不丢失。取消不发送请求，并恢复卡片的普通展示。

`Advance` 仍是无需编辑表单的快捷动作：依序把阶段从 `topic` 推到 `review`；在 `review` 阶段执行推进时，阶段保持 `review`，状态变为 `done`。快捷推进会清除任务的当前阻塞原因，因为任务已经重新开始推进。

## 数据合同与持久化

在 `CreatorTaskRecord`、`CreateCreatorTaskRequest` 和 `UpdateCreatorTaskRequest` 中加入可选字段：

```ts
blockerNote?: string;
```

存储层规则：

- 创建任务时忽略空白的 `blockerNote`。
- 更新任务时，`blockerNote` 可以显式清除；因此更新请求需要能区分“字段缺失”（不改变）和“传入空字符串”（清除）。
- 更新为 `blocked` 时，非空的 `blockerNote` 必须存在，否则拒绝请求并返回 400。
- 更新为任意非 `blocked` 状态时，`blockerNote` 不保留。
- 读取旧 JSON 文件时，缺少 `blockerNote` 仍视为有效兼容数据。

现有 `PATCH /api/projects/:id/creator-tasks/:taskId` 路由继续承担更新，不新增重复接口。路由继续先验证项目存在，存储继续按项目文件隔离并使用临时文件 + rename 原子写入。

## 活动记录

一次成功的编辑保存后，前端再请求现有的 `POST /api/projects/:id/creator-activities`，写入一条与任务关联的活动。

活动标题固定表达变更结果：

- 标记阻塞：`{任务标题} 已阻塞`
- 解除阻塞：`{任务标题} 已解除阻塞`
- 其他保存：`{任务标题} 已更新`

若存在阻塞原因，活动 `summary` 写入该原因。活动类别使用保存后的任务阶段。若任务更新成功但活动写入失败，页面显示错误并在刷新后保留已成功保存的任务；不会回滚任务更新。

## 可访问性与状态

- 编辑按钮使用原生项目 `Button` 组件，名称为 `Edit`。
- 原地展开区域以任务 ID 建立关联，使读屏软件可以理解它属于哪张任务卡。
- 保存后关闭编辑区域并刷新任务与活动。
- 取消时把焦点返回触发编辑的按钮。

## 验收标准

1. 人工任务可原地编辑标题、说明、阶段、状态、优先级。
2. 标记为阻塞且未填写阻塞原因时，后端拒绝更新；填写原因后保存成功。
3. 将阻塞任务改为其他状态后，任务不再包含阻塞原因。
4. 每次成功保存会生成项目活动；阻塞原因出现在对应活动摘要中。
5. 推导任务不出现 `Edit` 或 `Advance`。
6. 创建、更新、跨项目隔离和无效请求均有 daemon 测试覆盖；卡片编辑、阻塞校验、活动写入与取消行为均有页面测试覆盖。

## 非目标

本设计不改变 Creator Focus 的语义选择、动作策略或路由策略；它们继续以已有的 typed policy 为准。
