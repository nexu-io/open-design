# Pricing 页新增 DeepSeek V4 Flash Vision Exp 设计说明

## 目标

在 OpenDesign 公开 Pricing 页的个人套餐区域中新增 `DeepSeek V4 Flash Vision Exp`，并明确它在 Go、Plus、Pro 和 Max 四个套餐中都可无限量使用。页面展示、展开后的模型对比表和产品内无限量标记必须保持一致。

## 已确认的产品规则

- 展示名称为 `DeepSeek V4 Flash Vision Exp`。
- 内部模型 ID 暂按 `deepseek-v4-flash-vision-exp` 实现。
- 图标沿用现有 DeepSeek 图标。
- 新模型排在热门模型列表的第一位。
- 套餐卡片仍只预览 3 个模型；新模型显示在第一行，其余模型按既有顺序后移。
- 各档无限量热门模型数量从 `3 / 4 / 5 / 8` 调整为 `4 / 5 / 6 / 9`。
- “对比各套餐的全部模型”中，热门模型数量从 8 调整为 9，顶部新增该模型一行，Go、Plus、Pro、Max 均显示“∞ 无限量”。
- “热门模型无限使用”预估次数图表也要新增该模型，每 5 小时预计可用次数为 `8,000`，按数值降序排在 MiMo V2.5 Pro（11,000）与 DeepSeek V4 Pro（4,300）之间。

## 实现方案

采用定向的最小一致性改动，不重构 Pricing 页数据架构。

1. 在 `pricing-individual-plans.astro` 的热门模型数据中将新模型放在首位，并将它加入四个套餐的无限量集合。
2. 保留现有卡片的 3 项预览交互，让新的排序自然更新首屏内容。
3. 将热门模型对比表计数更新为 9，并使新模型在四个套餐列中均返回无限量状态。
4. 在 `amr-unlimited-models.ts` 中将新 ID 纳入 Go 的基础无限集合，Plus、Pro 和 Max 通过现有层级逻辑继承该权益。
5. 更新 Pricing 与 workbench 跨应用一致性测试中的展示名到 ID 映射及数量断言。
6. 将新模型以 `8,000` 加入 `usageRows`，按数值大小保持图表降序。

## 数据流与状态

Pricing 页使用展示名称和图标渲染公开页面；workbench 使用模型 ID 判断是否显示“无限量”并是否可跳过余额预检。跨应用测试作为翻译层，确保两端对四个套餐的模型集合给出相同答案。后端 Vela 仍是实际权益和用量的最终权威，本改动不修改后端计费逻辑。

## 错误与边界处理

- 未知套餐、Free 套餐和 Team 套餐不因此改动获得无限量标记。
- 带 provider 前缀的模型 ID 继续通过现有归一化逻辑匹配最后一段 slug。
- 如果暂定 ID 后续与 Vela 真实 ID 不一致，必须同时更新 workbench 集合和跨应用映射，不得只修改页面文案。
- 图表中的新数值必须使用已确认的 `8,000`，不从其他模型的比例推算。

## 验证

- Pricing 卡片的预览行数仍为 3，首行是新模型。
- Go、Plus、Pro、Max 的无限量数量分别是 4、5、6、9。
- 热门模型对比表有 9 行，新模型在四档均为无限量。
- workbench 对 `deepseek-v4-flash-vision-exp` 在四个个人套餐均返回无限量，对 Free、Team 和未知套餐返回否。
- Landing Page 套件测试、web 相关单测试和 Pricing 跨应用一致性测试通过。
- 验证图表新行的文案、DeepSeek 图标、`8,000` 数值、长度和降序位置。

## 非目标

- 不修改 Vela 后端的套餐配置、计费或限额。
- 不改动 Team 套餐的权益逻辑。
- 不重构 Pricing 页的整体数据模型、视觉风格或交互。
