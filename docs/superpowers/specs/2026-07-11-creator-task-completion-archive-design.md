# 创作者任务完成归档与恢复设计

## 目标

让 Creator Workbench 默认聚焦当前可执行任务，同时保留完成任务的可追溯记录，并允许用户恢复误完成的人工任务。

## 用户界面

任务面板顶部提供三段筛选：`进行中`、`已完成`、`全部`。

- 默认选中 `进行中`，包含状态 `todo`、`ready`、`blocked`。
- `已完成` 只包含状态 `done`，按 `updatedAt` 降序排列。
- `全部` 显示所有任务，保持已有任务排序逻辑。
- 任务数量与空状态对应当前筛选结果。

人工完成任务显示 `恢复` 按钮，不显示 `Advance`。点击恢复后，将任务状态更新为 `ready`，保留原阶段、标题、说明、优先级和阻塞原因清除规则。

推导任务保持只读：不显示 `Edit`、`Advance` 或 `恢复`。

## 数据流

不新增任务字段或路由。恢复通过既有 PATCH：

```ts
{ status: 'ready', blockerNote: '' }
```

PATCH 成功后，页面写入既有项目活动：

```ts
{ taskId, category: task.stage, title: `${task.title} 已恢复进行中` }
```

活动写入失败时不回滚状态更新，刷新任务列表并显示既有错误提示。

## 验收标准

1. 初次打开任务面板只显示进行中任务。
2. 已完成筛选只显示完成任务，全部筛选显示两者。
3. 人工完成任务可恢复，恢复请求为 `ready`，并有对应活动记录。
4. 推导任务没有恢复按钮。
5. 页面交互测试、Web 类型检查和生产构建通过。
