## Open Design என்றால் என்ன

🎨 **உள்ளக-முதன்மை, திறந்த மூல [Claude Design][cd] மாற்று.** &nbsp;🖥️ **macOS மற்றும் Windows-க்கான native desktop app.** &nbsp;⚡ **100+ திறன்கள்** · ✨ **150 brand-தரமுள்ள `DESIGN.md` அமைப்புகள்** · 📦 **261 பயன்படுத்தத் தயாரான plugins.** &nbsp;🖼️ **வலை · desktop · மொபைல் prototypes**, **live dashboards / artifacts**, **decks**, **படங்கள்**, **வீடியோ**, மற்றும் **HyperFrames** அசைவு வரைகலை ஆகியவற்றை உருவாக்குகிறது.** 🔒 Sandboxed iframe முன்னோட்டம் · HTML / PDF / PPTX / MP4 ஏற்றுமதி. &nbsp;🤖 **Claude Code · OpenClaw · Codex · Cursor · OpenCode · Qwen · Copilot · Amp · Hermes · Kimi · Antigravity மற்றும் 22 உள்ளக CLIs-ல் ஓடுகிறது**, அல்லது BYOK வழியாக எந்த OpenAI-இணக்கமான endpoint.

Open Design என்பது Anthropic-ஆல் Claude Design உடன் வழங்கப்பட்ட **agent-native** சுழற்சி — brief-ஐக் கண்டறி, திசையைப் பூட்டு, artifact-ஐ stream செய், விமர்சித்து, ஒப்படை — மூடப்பட்டிருப்பதை நிறுத்தி, உங்கள் மடிக்கணினியில் ஏற்கனவே இருக்கும் coding agents படிக்க, எழுத, மற்றும் மறுகலப்பு செய்யக்கூடிய **திறன்கள், வடிவமைப்பு அமைப்புகள், மற்றும் plugins-ன் filesystem** ஆக மாறும்போது கிடைப்பது. உங்கள் CLI வடிவமைப்பு இயந்திரமாகிறது, உங்கள் மடிக்கணினி studio ஆகிறது, மற்றும் உங்கள் குழுவின் `DESIGN.md` brand ஒப்பந்தமாகிறது.

இது **agent காலத்திற்கான Figma மாற்றும்** — ஒரு canvas-ல் pixels-ஐத் தள்ளுவதற்கு பதிலாக, இது நிகழ் CSS, நிகழ் எழுத்துருக்கள், நிகழ் components இல் single-page artifacts-ஐ வழங்குகிறது, HTML / PDF / PPTX / MP4-க்கு நேரடியாக ஏற்றுமதி செய்யப்படுகிறது — ஏற்கனவே உங்கள் வடிவமைப்பு அமைப்பால் வடிவமைக்கப்பட்டு, நீங்கள் தினமும் பயன்படுத்தும் agent-க்குள் ஏற்கனவே ஓடக்கூடியதாக.

## தயாரிப்பு சுற்றுப்பயணம்

Open Design என்ன மற்றும் என்ன செய்கிறது என்பதன் ஒரு விரைவு பார்வை. **Home**-லிருந்து தொடங்கு, **Automation** உடன் மறு பணிப்பாய்வுகளை இசைவாக்கு, **Design System**-ல் ஒரு brand ஒப்பந்தத்தை வடித்து, **Plugins** மற்றும் ஒருங்கிணைப்புகளுடன் விரிவாக்கு; ஏதேனும் திட்டத்தின் **Studio**-க்குள், அதே வடிவமைப்பு அமைப்பு prototypes, live artifacts, HyperFrames, decks, மற்றும் படங்களை stream செய்கிறது.

## தளம் இணக்கம்

> Open Design **திறன்கள், ஒரு CLI, மற்றும் ஒரு MCP சேவையகமாக** வருகிறது, அவற்றை முக்கிய coding agents native-ஆகப் பயன்படுத்துகின்றன. **எந்த CLI நிறுவப்படவில்லையா?** `POST /api/proxy/{anthropic,openai,azure,google,ollama,senseaudio}/stream`-ல் உள்ள BYOK ப்ராக்ஸி அதே சுழற்சியைத் தருகிறது (எந்த process spawn-ம் இல்லை) — `baseUrl` + `apiKey` + `model` ஒட்டு, OpenAI, Anthropic, Azure OpenAI, Google Gemini, Ollama, LM Studio, vLLM, அல்லது எந்த OpenAI-இணக்கமான endpoint-க்கும் ஆதரவுடன். இலக்கு-வாரியான SSRF பாதுகாப்பு daemon edge-ல் உள்ளக IPs / link-local / CGNAT-ஐத் தடுக்கிறது.

அடாப்டர் ஒப்பந்தம் மற்றும் stream parsers [`apps/daemon/src/agents.ts`](../../apps/daemon/src/agents.ts)-ல் உள்ளன. ஒரு புதிய CLI சேர்ப்பது ஒரு உள்ளீடு — [`docs/agent-adapters.md`](../../docs/agent-adapters.md)-ஐப் பார்.

## ஏன் Open Design

> **ஏப்ரல் 2026-ல், Anthropic [Claude Design][cd]-ஐ வெளியிட்டது — ஒரு LLM உரைநடை எழுதுவதை நிறுத்தி நேரடியாக வடிவமைப்பு artifacts-ஐ வழங்கத் தொடங்கிய முதல் முறை.** இது வைரல் ஆனது. ஆனால் இது மூடிய-மூல, கட்டணம்-மட்டும், மேகம்-மட்டும், Anthropic-ன் model, Anthropic-ன் திறன்கள், Anthropic-ன் மேற்பரப்புக்கு பூட்டப்பட்டிருந்தது. எந்த checkout இல்லை, எந்த self-host இல்லை, எந்த Vercel deploy இல்லை, உங்கள்-சொந்த-agent-ஐ-மாற்று இல்லை.

Open Design (OD) திறந்த-மூல மாற்று. அதே சுழற்சி, அதே artifact-முதல் மனதாதார மாதிரி, எந்த பூட்டுதலும் இல்லை:

- 🤖 **Agent-native, model-நடுநிலை.** நாங்கள் ஒரு agent-ஐ வழங்குவதில்லை. உங்கள் `PATH`-ல் ஏற்கனவே உள்ள `claude` / `codex` / `cursor-agent` / `copilot` / `hermes` / `kimi` வடிவமைப்பு இயந்திரம். ஒரு கிளிக்கில் மாற்று.
- 🧠 **இயல்பாகவே brand-தரம்.** ஒவ்வொரு render-ம் செயலில் உள்ள `DESIGN.md`-ஐப் படிக்கிறது — palette, type, spacing, motion, voice, anti-patterns-ஐ உள்ளடக்கிய ஒரு 9-பிரிவு schema. 150 அமைப்புகள் repo-உடன் வருகின்றன (Linear, Stripe, Vercel, Airbnb, Apple, Tesla, Notion, Anthropic, Cursor, Supabase, Figma…). ஒரு கோப்புறையை விடு, picker அதைக் கண்டுபிடிக்கும்.
- 🖥️ **உள்ளக-முதன்மை, ஒவ்வொரு அடுக்கிலும் BYOK.** macOS (Apple Silicon + Intel) மற்றும் Windows (x64)-க்கான native desktop apps. விருப்பப்பட்ட release lane-ல் Linux AppImage. எந்த telemetry இல்லை, எந்த மேகம் round-trip இல்லை. daemon தரவு பாதைகளை விவரிப்பதற்கு முன், contributors மற்றும் operators `AGENTS.md` → **Daemon data directory contract**-ஐப் படிக்க வேண்டும். இந்த README அதை மறுசொல்லக் கூடாது.
- 🌍 **மூன்று தளங்களில் composable.** **Plugins** ஓடக்கூடிய பணிப்பாய்வுகளைச் சுமக்கின்றன · **திறன்கள்** agent-ன் வடிவமைப்பு ருசியைச் சுமக்கின்றன · **வடிவமைப்பு அமைப்புகள்** brand-ஐச் சுமக்கின்றன. மூன்றும் யார் வேண்டுமானாலும் உருவாக்க, பதிப்பு, மற்றும் வெளியிடக்கூடிய plain files.
- 🔁 **ஏற்கனவே உள்ள codebase-ஐ புதுப்பி.** ஒரு `git` repo + `DESIGN.md`-ஐ agent-க்குக் கொடு, அது உங்கள் நிகழ் components-ஐ brand spec-க்கு refactor செய்யும். அர்ப்பணிக்கப்பட்ட plugins Figma / Pencil பணிப்பாய்வுகளை React / Next.js / Vue code-ஆக migrate செய்கின்றன.
- 🔒 **தத்துவார்த்தத்தால் தனியுரிமை.** எல்லாம் உங்கள் தரவு இருக்கும் இடத்தில் ஓடுகிறது — உங்கள் மடிக்கணினி, உங்கள் குழுவின் சேவையகம், உங்கள் Vercel திட்டம். பிணையம் தேவைப்படும்போது, BYOK ப்ராக்ஸி SSRF-பாதுகாக்கப்பட்டது.

Open Design-ஐப் பயன்படுத்த விரைவான வழி. எந்த Node இல்லை, எந்த pnpm இல்லை, எந்த clone இல்லை.

- **macOS** (Apple Silicon · Intel x64) → [**open-design.ai**](https://open-design.ai/) அல்லது [GitHub Releases](https://github.com/nexu-io/open-design/releases)
- **Windows** (x64) → [**open-design.ai**](https://open-design.ai/) அல்லது [GitHub Releases](https://github.com/nexu-io/open-design/releases)
- **Linux** (AppImage, விருப்பப்பட்ட lane) → [GitHub Releases](https://github.com/nexu-io/open-design/releases)

நிறுவலுக்குப் பிறகு: app உங்கள் `PATH`-ல் உள்ள ஒவ்வொரு coding-agent CLI-ஐயும் தானாகக் கண்டறியும், 100+ திறன்கள் மற்றும் 150 வடிவமைப்பு அமைப்புகளை ஏற்றும், மற்றும் entry view-ல் ஒரு brief-ஐத் தட்டச்சு செய்ய அனுமதிக்கும்.

### ஒரு முழு பணிப்பாய்வு — brief-இலிருந்து artifact வரை

`brief → plugin → direction → design system → artifact → handoff → memory`

1. **ஒரு PM ஒரு brief-ஐச் சமர்ப்பிக்கிறார்.** Plugin picker landing page · pitch deck · dashboard · social post · PM spec · OKR scorecard… வழங்குகிறது.
2. **ஒரு வடிவமைப்பாளர் (அல்லது agent) திசையைப் பூட்டுகிறார்.** Brand இல்லையா? 5 curated directions-இலிருந்து தேர். Brand உண்டா? ஒரு screenshot / URL விடு → agent GitHub-ஐ இணைக்கிறது, Figma-ஐ இறக்குமதி செய்கிறது, மற்றும் ஒரு மறுபயன்பாட்டு `DESIGN.md`-ஐ codify செய்கிறது.
3. **Agent முதல் `<artifact>`-ஐ வெளியிடுகிறது.** Plugin + திறல் + `DESIGN.md` பிணைக்கப்பட்டுள்ளன. இது ஒரு sandboxed iframe-ல் stream ஆகிறது, இடத்திலேயே திருத்தக்கூடியது — "scratch-இலிருந்து regenerate செய்" அல்ல.
4. **Engineering-க்கு ஒப்படை.** Artifact நிகழ் HTML/CSS — code-ஆக கட்டியகொண்டே இருக்க Cursor, Codex, அல்லது Claude Code-ல் விடு. அல்லது PPTX / PDF / MP4-ஐ நேரடியாக marketing-க்கு ஏற்றுமதி செய்.
5. **நீங்கள் பயன்படுத்தியதால் Open Design புத்திசாலியாகிறது.** உங்கள் screenshots, எழுத்துருக்கள், palettes, மற்றும் உறுதிப்படுத்தப்பட்ட artifacts அடுத்த அமர்வுக்கான இயல்புநிலைகளாக சேருகின்றன. குறைவான rework, குறைவான drift.

## உங்கள் coding agent-இலிருந்து Open Design-ஐப் பயன்படுத்து

Open Design ஒரு **stdio MCP சேவையகம்** மற்றும் per-agent **நிறுவல் scripts**-ஐ வழங்குகிறது. வேறொரு repo-ல் உள்ள எந்த MCP-இணக்கமான agent-ம் உங்கள் உள்ளக Open Design திட்டங்களிலிருந்து நேரடியாக files-ஐப் படிக்க முடியும் — tokens CSS, JSX components, entry HTML — பெயரால் வினவக்கூடிய ஒரு structured API ஆக. Agent எப்போதும் live file-ஐப் பார்க்கிறது, பழைய ஏற்றுமதியை அல்ல.

```bash
# One-line install (16+ CLIs supported):
curl -fsSL https://open-design.ai/install.sh | sh -s <agent>

# Then the agent can:
od search-files "primary button"      # search files across projects
od get-file design-systems/linear-app/DESIGN.md
od get-artifact <slug>                # latest rendered artifact
od plugin run web-prototype --brief "..."
od skill list --scenario marketing
```

**ஏன் MCP?** ஒவ்வொரு iteration-லும் ஒரு zip-ஐ ஏற்றுமதி செய்து மறு-இணைப்பது ஓட்டத்தை உடைக்கிறது. MCP வடிவமைப்பு மூலத்தை நேரடியாக வெளிப்படுத்துகிறது — agent எப்போதும் live file-ஐப் பார்க்கிறது.

**ஒரு agent scratch-இலிருந்து தொடங்கினால்,** installer `~/.config/<agent>/open-design.json` (அல்லது platform equivalent) மற்றும் ஒரு copy-paste MCP snippet-ஐ வைக்கிறது. Cursor ஒரு ஒரு-கிளிக் deeplink பெறுகிறது; Claude Code ஒரு `claude mcp add-json` ஒரு-வரி பெறுகிறது; மற்ற ஒவ்வொரு agent-ம் அதன் config எதிர்பார்க்கும் schema-ல் JSON பெறுகிறது. முழு per-agent flow → desktop app-ல் **Settings → MCP server**, அல்லது [`docs/agent-adapters.md`](../../docs/agent-adapters.md).

**பாதுகாப்பு model.** இயல்புநிலையாக read-only, daemon `127.0.0.1`-க்கு பிணைக்கிறது, மற்றும் SSRF ப்ராக்ஸி edge-ல் தடுக்கப்படுகிறது. LAN வெளிப்பாடு ஒரு வெளிப்படையான `OD_BIND_HOST` மற்றும் `OD_ALLOWED_ORIGINS` தேவை. Connector credentials மற்றும் live-artifact முன்னோட்ட பாதைகள் எதுவாக இருந்தாலும் loopback-மட்டுமே இருக்கும்.

- 🛠️ **ஏற்கனவே உள்ள codebase-ஐ brand spec-க்கு புதுப்பி** — ஒரு plugin-ஐ ஒரு `git` repo + `DESIGN.md`-க்கு சுட்டிக்காட்டு, ஒரு PR பெறு. [`od-code-migration`](../../plugins/_official/scenarios/od-code-migration/)-ஐப் பார்.
- 💾 **தனிப்பயன் பணிப்பாய்வுகளை persist செய்** — உங்கள் குழுவின் மறுபயன்பாட்டு templates வழங்கப்பட்டவற்றுடன் அருகில் உள்ளன.

### Plugins-ஐப் பயன்படுத்துதல்

Plugins **வலை UI** மற்றும் **`od` CLI** இரண்டிலும் முழு parity-இல் உள்ளன — அதே `/api/plugins` endpoints, பொருத்ததைத் தேர்.

**Desktop / வலை app-ல்:** marketplace-ஐ உலாவ **Plugin** பக்கத்தைத் திறந்து **Install**-ஐ கிளிக் செய்; ஒரு திட்டத்தின் Studio-க்குள், plugins நீங்கள் apply செய்ய கிளிக் செய்யும் composer chips-ஆக தோன்றுகின்றன (அவை அறிவிக்கும் inputs உடன்).

**Command line-ல்** (UI இல்லாமல் ஓடுகிறது — இது வெளிப்புற agents பயன்படுத்தும் பாதை):

```bash
od plugin list                       # list installed plugins (--task-kind / --mode / --tag filters)
od plugin search "landing page"      # search by keyword
od plugin info od-default            # inspect a plugin's metadata, inputs, capabilities
od plugin install od-figma-migration # install from a registry; also accepts ./local-folder or an https://… link
od plugin apply od-default --input brief="a one-page pitch for our seed round"
od plugin upgrade od-default         # upgrade
od plugin uninstall od-default       # uninstall
```

ஒவ்வொரு command-ம் `--json`-ஐ ஆதரிக்கிறது, எனவே நீங்கள் இதை `jq` / `xargs` வழியாக தானியக்கத்திற்கு pipe செய்யலாம்.

### ஒரு plugin-ஐ உருவாக்குதல்

ஒரு plugin-க்கு **குறைந்தபட்சம் ஒரு `SKILL.md` மட்டுமே தேவை**; Open Design marketplace-ல் பட்டியலிட, ஒரு `open-design.json` சேர்:

```
my-plugin/
├── SKILL.md            ← required: YAML frontmatter (name · description) + trigger phrasing + workflow (aim for < 500 lines)
├── open-design.json    ← needed to list: marketplace metadata + inputs + pipeline + capabilities
├── README.md           ← optional: usage, install, registry links
├── preview/            ← optional: index.html / poster.png (strongly recommended for visual plugins)
└── examples/           ← optional: concrete use cases
```

முக்கிய `open-design.json` புலங்கள்: `specVersion` (தற்போது `1.0.0`), `name` (stable ID), `version` (semver), `compat.agentSkills[].path` (`./SKILL.md`-க்கு சுட்டுகிறது), `od.kind` (`skill` / `scenario` / `atom` / `bundle`), `od.taskKind` (`new-generation` / `figma-migration` / `code-migration` / `tune-collab`), `od.mode` (வெளியீட்டு மேற்பரப்பு, எ.கா. `prototype` / `deck` / `live-artifact` / `image` / `video` / `hyperframes` / `audio` / `design-system` / `scenario`), `od.capabilities[]` (**குறைந்தபட்சத்தை அறிவி** — ஒரு restricted நிறுவல் இயல்புநிலையாக வெறும் `prompt:inject`-ஐ மட்டுமே வழங்குகிறது), `od.inputs[]` (apply-time அளவுருக்கள்).

Scaffold + உள்ளமை validate:

```bash
od plugin scaffold --id my-plugin --title "My Plugin"   # generate the skeleton
od plugin validate ./my-plugin                          # check manifest / file layout
pnpm guard && pnpm --filter @open-design/plugin-runtime typecheck
```

முழு புலம் தொகுப்பு மற்றும் runtime ஒப்பந்தம் → [`plugins/spec/SPEC.md`](../../plugins/spec/SPEC.md); ஒரு coding agent உடன் plugin உருவாக்க → [`plugins/spec/AGENT-DEVELOPMENT.md`](../../plugins/spec/AGENT-DEVELOPMENT.md); copy-paste குறைந்தபட்ச templates → [`plugins/spec/examples/`](../../plugins/spec/examples/).

### ஒரு plugin-ஐ பங்களிப்பது

1. Plugin கோப்புறையை [`plugins/community/`](../../plugins/community/)-ல் விடு (மூன்றாம்-தரப்பு plugins), அல்லது — அதை Open Design உடன் bundled செய்ய — [`plugins/_official/`](../../plugins/_official/)-ன் பொருந்தும் tier-ல் விடு.
2. Validation-ஐ கடக்கு: `od plugin validate`, `pnpm guard`, `pnpm --filter @open-design/plugin-runtime typecheck`.
3. [`plugins/spec/CONTRIBUTING.md`](../../plugins/spec/CONTRIBUTING.md)-ல் உள்ள template-ஐப் பயன்படுத்தி PR-ஐ நிரப்பு (ID, version, lane, mode, capabilities, trigger உதாரணங்கள்; visual plugins-க்கு ஒரு screenshot / preview இணை).
4. ஒரு வெளிப்புற registry-க்கு வெளியிட (skills.sh / ClawHub / standalone GitHub) → [`plugins/spec/PUBLISHING-REGISTRIES.md`](../../plugins/spec/PUBLISHING-REGISTRIES.md).

Plugin registry endpoint: `GET /api/plugins`. Directory overview → [`plugins/README.md`](../../plugins/README.md) ([简体中文](../../plugins/README.zh-CN.md)).

## கட்டமைப்பு

```
┌────────────────── browser (Next.js 16) / Electron shell ──────────────┐
│  chat · file workspace · iframe preview · settings · import · MCP     │
└──────────────┬─────────────────────────────────────┬─────────────────┘
               │ /api/*                              │
               ▼                                     ▼
   ┌─────────────────────────────────┐   /api/proxy/{provider}/stream (SSE)
   │  local daemon (Express+SQLite)  │   ─→ any OpenAI-compatible BYOK,
   │                                  │       SSRF-guarded at the edge
   │  /api/skills    /api/plugins    │
   │  /api/design-systems            │
   │  /api/chat (SSE)   /api/proxy/* │
   │  /api/projects/:id/files/...    │
   │  /api/artifacts/{save,lint}     │
   │  /api/import/claude-design      │
   │  MCP stdio server                │
   └─────────┬───────────────────────┘
             │ spawn(cli, [...], { cwd: managed project cwd })
             ▼
   ┌──────────────────────────────────────────────────────────────────┐
   │  claude · codex · cursor-agent · copilot · openclaw · antigravity ·│
   │  gemini · opencode · qwen · qoder · hermes (ACP) · kimi (ACP) ·    │
   │  pi (RPC) · kiro · kilo · vibe (ACP) · cline · trae · deepseek     │
   │  reads SKILL.md + DESIGN.md, writes artifacts to disk             │
   └──────────────────────────────────────────────────────────────────┘
```

| Layer | Stack |
|---|---|
| Frontend | Next.js 16 App Router + React 18 + TypeScript |
| Daemon | Node 24 · Express · SSE streaming · `better-sqlite3` |
| Storage | daemon storage பாதைகளை மாற்றுவதற்கு முன் அல்லது ஆவணப்படுத்துவதற்கு முன், நீங்கள் `AGENTS.md` → **Daemon data directory contract**-ஐப் படிக்க வேண்டும். இந்த README அதை மறுசொல்லக் கூடாது. |
| Preview | Sandboxed `srcdoc` iframe + streaming `<artifact>` parser |
| Export | HTML (inlined) · PDF (browser print) · PPTX (agent-driven) · ZIP · Markdown · MP4 (HyperFrames) |
| Desktop | Electron shell + sandboxed renderer + sidecar IPC (STATUS · EVAL · SCREENSHOT · CONSOLE · CLICK · SHUTDOWN) |
| Lifecycle | ஒரு நுழைவு புள்ளி: `pnpm tools-dev` (start / stop / run / status / logs / inspect / check) |

முழு கட்டமைப்பு → [`docs/architecture.md`](../../docs/architecture.md). திறல் protocol → [`docs/skills-protocol.md`](../../docs/skills-protocol.md). Agent adapter ஒப்பந்தம் → [`docs/agent-adapters.md`](../../docs/agent-adapters.md).

### 🤖 ஒரு agent ஆகப் பங்களிப்பது

*நீங்கள் இதைப் படிக்கும் agent என்றால்*, விரைவான பாதை:

```bash
# 1. Boot locally
git clone https://github.com/nexu-io/open-design.git
cd open-design && corepack enable && pnpm install
pnpm tools-dev run web

# 2. Find a good-first-issue and assign yourself
gh issue list --label "good first issue" --state open --limit 20
gh issue develop <number>   # create a branch and worktree

# 3. Make the change, run the checks
pnpm guard && pnpm typecheck
pnpm --filter @open-design/<package> test

# 4. Open the PR
gh pr create --fill
```

முழு agent-நட்பு பங்களிப்பு flow, code style, மற்றும் PR bar → [`CONTRIBUTING.md`](../../CONTRIBUTING.md) ([Deutsch](../../docs/i18n/CONTRIBUTING.de.md) · [Français](../../docs/i18n/CONTRIBUTING.fr.md) · [简体中文](../../docs/i18n/CONTRIBUTING.zh-CN.md) · [日本語](../../docs/i18n/CONTRIBUTING.ja-JP.md) · [Português](../../docs/i18n/CONTRIBUTING.pt-BR.md)).
