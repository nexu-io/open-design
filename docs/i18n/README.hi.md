## Open Design क्या है

🎨 **लोकल-फ़र्स्ट, ओपन-सोर्स [Claude Design][cd] विकल्प.** &nbsp;🖥️ **macOS और Windows के लिए नेटिव डेस्कटॉप ऐप.** &nbsp;⚡ **100+ स्किल** · ✨ **150 ब्रांड-ग्रेड `DESIGN.md` सिस्टम** · 📦 **261 उपयोग के लिए तैयार प्लगइन.** &nbsp;🖼️ **web · desktop · mobile प्रोटोटाइप**, **लाइव डैशबोर्ड / आर्टिफैक्ट**, **डेक**, **इमेज**, **वीडियो**, और **HyperFrames** मोशन ग्राफ़िक्स जनरेट करता है. 🔒 सैंडबॉक्स्ड iframe प्रीव्यू · HTML / PDF / PPTX / MP4 एक्सपोर्ट. &nbsp;🤖 **Claude Code · OpenClaw · Codex · Cursor · OpenCode · Qwen · Copilot · Amp · Hermes · Kimi · Antigravity और 22 लोकल CLI पर चलता है**, या BYOK द्वारा किसी भी OpenAI-संगत एंडपॉइंट पर।

Open Design वही है जो मिलता है जब Anthropic द्वारा Claude Design के साथ शिप किया गया **एजेंट-नेटिव** लूप — ब्रीफ़ खोजें, दिशा लॉक करें, आर्टिफैक्ट स्ट्रीम करें, समीक्षा करें, डिलीवर करें — बंद होना बंद कर देता है और **स्किल, डिज़ाइन सिस्टम और प्लगइन के फ़ाइलसिस्टम** में बदल जाता है जिन्हें आपके लैपटॉप पर पहले से मौजूद कोडिंग एजेंट पढ़, लिख और रीमिक्स कर सकते हैं। आपका CLI डिज़ाइन इंजन बन जाता है, आपका लैपटॉप स्टूडियो बन जाता है, और आपकी टीम का `DESIGN.md` ब्रांड अनुबंध बन जाता है।

यह **एजेंट युग का Figma विकल्प** भी है — कैनवास पर पिक्सेल धकेलने के बजाय, यह असली CSS, असली फ़ॉन्ट, असली कंपोनेंट में सिंगल-पेज आर्टिफैक्ट डिलीवर करता है, सीधे HTML / PDF / PPTX / MP4 में एक्सपोर्ट — पहले से आपके डिज़ाइन सिस्टम से आकार ग्रहण किए हुए, पहले से उस एजेंट के अंदर रनने योग्य जिसका आप हर दिन उपयोग करते हैं।

## प्रोडक्ट टूर

एक त्वरित झलक कि Open Design क्या है और क्या करता है। **होम** से शुरू करें, **ऑटोमेशन** से दोहराव वाले वर्कफ़्लो ऑर्केस्ट्रेट करें, **डिज़ाइन सिस्टम** में ब्रांड अनुबंध आकार दें, और **प्लगइन** तथा **एकीकरण** से विस्तार करें; किसी भी प्रोजेक्ट के **स्टूडियो** के अंदर वही डिज़ाइन सिस्टम प्रोटोटाइप, लाइव आर्टिफैक्ट, HyperFrames, डेक और इमेज स्ट्रीम करता है।

## प्लेटफ़ॉर्म संगतता

> Open Design **स्किल, एक CLI और एक MCP सर्वर** के रूप में शिप होता है जिन्हें मुख्याधार की कोडिंग एजेंट नेटिव रूप से उपयोग करते हैं। OD इंस्टॉल होने के बाद, एक सिंगल `od mcp install <agent>` MCP सर्वर को उस एजेंट के कॉन्फ़िग में जोड़ देता है, और आप किसी भी एजेंट के अंदर से वही टूल कॉल करते हैं।

**कोई CLI इंस्टॉल नहीं?** `POST /api/proxy/{anthropic,openai,azure,google,ollama,senseaudio}/stream` पर BYOK प्रॉक्सी आपको वही लूप देता है (कोई प्रोसेस स्पॉन नहीं) — `baseUrl` + `apiKey` + `model` पेस्ट करें, OpenAI, Anthropic, Azure OpenAI, Google Gemini, Ollama, LM Studio, vLLM, या किसी भी OpenAI-संगत एंडपॉइंट के समर्थन के साथ। प्रति-लक्ष्य SSRF सुरक्षा डेमन एज पर आंतरिक IP / link-local / CGNAT को ब्लॉक करती है।

## Open Design क्यों

> **अप्रैल 2026 में Anthropic ने [Claude Design][cd] रिलीज़ किया — पहली बार कोई LLM गद्य लिखना बंद करके सीधे डिज़ाइन आर्टिफैक्ट डिलीवर करने लगा।** यह वायरल हो गया। लेकिन यह क्लोज़ड-सोर्स, सिर्फ़ पेड, सिर्फ़ क्लाउड, Anthropic के मॉडल, Anthropic की स्किल, Anthropic के सतह तक सीमित रहा। कोई चेकआउट नहीं, कोई सेल्फ़-होस्ट नहीं, कोई Vercel डिप्लॉय नहीं, कोई अपना-एजेंट-लगाना नहीं।

Open Design (OD) ओपन-सोर्स विकल्प है। वही लूप, वही आर्टिफैक्ट-फ़र्स्ट मानसिक मॉडल, बिना किसी लॉक-इन के:

- 🤖 **एजेंट-नेटिव, मॉडल-अज्ञेयवादी.** हम एजेंट शिप नहीं करते। आपके `PATH` पर पहले से मौजूद `claude` / `codex` / `cursor-agent` / `copilot` / `hermes` / `kimi` ही डिज़ाइन इंजन हैं। एक क्लिक से बदलें।
- 🧠 **डिफ़ॉल्ट से ब्रांड-ग्रेड.** हर रेंडर सक्रिय `DESIGN.md` पढ़ता है — पैलेट, टाइप, स्पेसिंग, मोशन, आवाज़, एंटी-पैटर्न कवर करने वाला 9-सेक्शन स्कीमा। 150 सिस्टम रेपो के साथ शिप होते हैं (Linear, Stripe, Vercel, Airbnb, Apple, Tesla, Notion, Anthropic, Cursor, Supabase, Figma…)। एक फ़ोल्डर डालें, पिकर उसे ढूंढ लेता है।
- 🖥️ **लोकल-फ़र्स्ट, हर लेयर पर BYOK.** macOS (Apple Silicon + Intel) और Windows (x64) के लिए नेटिव डेस्कटॉप ऐप। वैकल्पिक रिलीज़ लेन पर Linux AppImage। कोई टेलीमेट्री नहीं, कोई क्लाउड राउंड-ट्रिप नहीं। डेमन डेटा पाथ का वर्णन करने से पहले योगदानकर्ताओं और ऑपरेटरों को `AGENTS.md` → **Daemon data directory contract** पढ़ना आवश्यक है। इस README में इसे दोहराया नहीं जाना चाहिए।
- 🌍 **तीन तलों पर कंपोज़ेबल.** **प्लगइन** रनने योग्य वर्कफ़्लो ले जाते हैं · **स्किल** एजेंट की डिज़ाइन समझ ले जाते हैं · **डिज़ाइन सिस्टम** ब्रांड ले जाते हैं। तीनों सादे फ़ाइलें हैं जिन्हें कोई भी लिख, वर्ज़न और प्रकाशित कर सकता है।
- 🔁 **किसी मौजूदा कोडबेस को रिफ़्रेश करें.** एजेंट को एक `git` रेपो + `DESIGN.md` दें और यह आपके असली कंपोनेंट को ब्रांड स्पेक में रीफ़ैक्टर कर देता है। समर्पित प्लगइन Figma / Pencil वर्कफ़्लो को React / Next.js / Vue कोड में माइग्रेट करते हैं।
- 🔒 **दृढ़ता से प्राइवेसी.** सब कुछ वहीं चलता है जहां आपका डेटा है — आपका लैपटॉप, आपकी टीम का सर्वर, आपका Vercel प्रोजेक्ट। जब नेटवर्क चाहिए, BYOK प्रॉक्सी SSRF-सुरक्षित है।

इंस्टॉल के बाद: ऐप आपके `PATH` पर हर कोडिंग-एजेंट CLI को ऑटो-डिटेक्ट करता है, 100+ स्किल और 150 डिज़ाइन सिस्टम लोड करता है, और एंट्री व्यू में ब्रीफ़ टाइप करने देता है।

```bash
# One-line install into the agent you're using:

# <agent> = claude | codex | cursor | copilot | openclaw | antigravity | gemini
#         | pi | vibe | hermes | cline | kimi | trae | opencode
```

फिर, एजेंट के अंदर:

```
> Use open-design to generate a landing page with the Linear design system
```

एजेंट `skills/` पढ़ता है, सही `SKILL.md` चुनता है, आपके द्वारा नामित `DESIGN.md` को बाइंड करता है, और एक `<artifact>` देता है जो `http://localhost:7456` पर प्रीव्यू करने योग्य है।

```bash
git clone https://github.com/nexu-io/open-design.git
cd open-design/deploy
cp .env.example .env
echo "OD_API_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose up -d
# open http://localhost:7456
```

Node `~24`, pnpm `10.33.x`। Windows यूज़र्स [`docs/windows-troubleshooting.md`](../../docs/windows-troubleshooting.md) देखें। पूरा क्विकस्टार्ट, env वेरिएबल, Nix flake और पैकेज्ड बिल्ड फ़्लो → [`QUICKSTART.md`](../../QUICKSTART.md)।

### एक पूरा वर्कफ़्लो — ब्रीफ़ से आर्टिफैक्ट तक

`ब्रीफ़ → प्लगइन → दिशा → डिज़ाइन सिस्टम → आर्टिफैक्ट → हैंड-ऑफ़ → मेमोरी`

1. **एक PM ब्रीफ़ सबमिट करता है.** प्लगइन पिकर लैंडिंग पेज · पिच डेक · डैशबोर्ड · सोशल पोस्ट · PM स्पेक · OKR स्कोरकार्ड… ऑफ़र करता है।
2. **एक डिज़ाइनर (या एजेंट) दिशा लॉक करता है.** ब्रांड नहीं? 5 क्यूरेटेड दिशाओं में से चुनें। ब्रांड है? स्क्रीनशॉट / URL डालें → एजेंट GitHub कनेक्ट करता है, Figma इंपोर्ट करता है, और पुनः उपयोग योग्य `DESIGN.md` कूटबद्ध करता है।
3. **एजेंट पहला `<artifact>` देता है.** प्लगइन + स्किल + `DESIGN.md` बाइंड होते हैं। यह एक सैंडबॉक्स्ड iframe में स्ट्रीम होता है, जगह पर एडिट करने योग्य — "शुरू से दोबारा जनरेट" नहीं।
4. **इंजीनियरिंग को हैंड-ऑफ़ करें.** आर्टिफैक्ट असली HTML/CSS है — इसे Cursor, Codex या Claude Code में डालकर कोड के रूप में बनाना जारी रखें। या PPTX / PDF / MP4 सीधे मार्केटिंग को एक्सपोर्ट करें।
5. **Open Design उपयोग करते हुए समझदार होता है.** आपके स्क्रीनशॉट, फ़ॉन्ट, पैलेट और पुष्ट किए आर्टिफैक्ट अगले सत्र के डिफ़ॉल्ट के रूप में जमा होते हैं। कम रीवर्क, कम ड्रिफ़्ट।

## अपने कोडिंग एजेंट से Open Design उपयोग करें

Open Design एक **stdio MCP सर्वर** और प्रति-एजेंट **इंस्टॉल स्क्रिप्ट** शिप करता है। किसी अन्य रेपो में कोई भी MCP-संगत एजेंट आपके लोकल Open Design प्रोजेक्ट से सीधे फ़ाइलें पढ़ सकता है — टोकन CSS, JSX कंपोनेंट, एंट्री HTML — नाम से क्वेरी करने योग्य संरचित API के रूप में। एजेंट हमेशा लाइव फ़ाइल देखता है, पुराना एक्सपोर्ट नहीं।

```bash
# One-line install (16+ CLIs supported):
curl -fsSL https://open-design.ai/install.sh | sh -s <agent>

# Then the agent can:
od search-files "primary button"      # search files across projects
od get-file design-systems/linear-app/DESIGN.md
od get-artifact <slug>                # latest rendered artifact
od plugin run web-prototype --brief "..."
od skill list --scenario marketing
```

**MCP क्यों?** हर इटरेशन पर zip एक्सपोर्ट करके दोबारा अटैच करना फ़्लो तोड़ता है। MCP डिज़ाइन सोर्स को सीधे उजागर करता है — एजेंट हमेशा लाइव फ़ाइल देखता है।

**शुरुआत से शुरू करने वाले एजेंट के लिए,** इंस्टॉलर `~/.config/<agent>/open-design.json` (या प्लेटफ़ॉर्म समतुल्य) और एक कॉपी-पेस्ट MCP स्निपेट रखता है। Cursor को वन-क्लिक डीपलिंक मिलता है; Claude Code को `claude mcp add-json` वन-लाइनर मिलता है; हर दूसरे एजेंट को उसके कॉन्फ़िग द्वारा अपेक्षित स्कीमा में JSON मिलता है। पूरा प्रति-एजेंट फ़्लो → डेस्कटॉप ऐप में **Settings → MCP server**, या [`docs/agent-adapters.md`](../../docs/agent-adapters.md)।

**सुरक्षा मॉडल.** डिफ़ॉल्ट से रीड-ओनली, डेमन `127.0.0.1` पर बाइंड होता है, और SSRF प्रॉक्सी एज पर ब्लॉक किया जाता है। LAN एक्सपोज़र के लिए स्पष्ट `OD_BIND_HOST` साथ `OD_ALLOWED_ORIGINS` चाहिए। कनेक्टर क्रेडेंशियल और लाइव-आर्टिफैक्ट प्रीव्यू रूट चाहे जो हो, लूपबैक-ओनली रहते हैं।

### प्लगइन उपयोग करना

प्लगइन **web UI** और **`od` CLI** दोनों पर पूर्ण समानता के साथ हैं — वही `/api/plugins` एंडपॉइंट, जो फ़िट बैठे उसे चुनें।

**डेस्कटॉप / web ऐप में:** मार्केटप्लेस ब्राउज़ करने के लिए **Plugin** पेज खोलें और **Install** क्लिक करें; किसी प्रोजेक्ट के स्टूडियो के अंदर, प्लगइन कंपोज़र चिप के रूप में दिखते हैं जिन्हें आप लागू करने के लिए क्लिक करते हैं (वे जो इनपुट घोषित करते हैं उनके साथ)।

**कमांड लाइन पर** (बिना UI चलता है — यह रास्ता बाहरी एजेंट उपयोग करते हैं):

```bash
od plugin list                       # list installed plugins (--task-kind / --mode / --tag filters)
od plugin search "landing page"      # search by keyword
od plugin info od-default            # inspect a plugin's metadata, inputs, capabilities
od plugin install od-figma-migration # install from a registry; also accepts ./local-folder or an https://… link
od plugin apply od-default --input brief="a one-page pitch for our seed round"
od plugin upgrade od-default         # upgrade
od plugin uninstall od-default       # uninstall
```

हर कमांड `--json` समर्थन करता है, इसलिए आप इसे `jq` / `xargs` के माध्यम से ऑटोमेशन में पाइप कर सकते हैं।

### प्लगइन बनाना

एक प्लगइन को **न्यूनतम रूप से केवल एक `SKILL.md` चाहिए**; Open Design मार्केटप्लेस में सूचीबद्ध करने के लिए, एक `open-design.json` जोड़ें:

```
my-plugin/
├── SKILL.md            ← required: YAML frontmatter (name · description) + trigger phrasing + workflow (aim for < 500 lines)
├── open-design.json    ← needed to list: marketplace metadata + inputs + pipeline + capabilities
├── README.md           ← optional: usage, install, registry links
├── preview/            ← optional: index.html / poster.png (strongly recommended for visual plugins)
└── examples/           ← optional: concrete use cases
```

मुख्य `open-design.json` फ़ील्ड: `specVersion` (वर्तमान में `1.0.0`), `name` (स्थिर ID), `version` (semver), `compat.agentSkills[].path` (`./SKILL.md` की ओर इशारा), `od.kind` (`skill` / `scenario` / `atom` / `bundle`), `od.taskKind` (`new-generation` / `figma-migration` / `code-migration` / `tune-collab`), `od.mode` (आउटपुट सतह, जैसे `prototype` / `deck` / `live-artifact` / `image` / `video` / `hyperframes` / `audio` / `design-system` / `scenario`), `od.capabilities[]` (**न्यूनतम घोषित करें** — प्रतिबंधित इंस्टॉल डिफ़ॉल्ट से केवल `prompt:inject` देता है), `od.inputs[]` (लागू-करने के समय के पैरामीटर)।

स्कैफ़ोल्ड + लोकल रूप से वैलिडेट करें:

```bash
od plugin scaffold --id my-plugin --title "My Plugin"   # generate the skeleton
od plugin validate ./my-plugin                          # check manifest / file layout
pnpm guard && pnpm --filter @open-design/plugin-runtime typecheck
```

पूरा फ़ील्ड सेट और रनटाइम अनुबंध → [`plugins/spec/SPEC.md`](../../plugins/spec/SPEC.md); किसी कोडिंग एजेंट के साथ प्लगइन विकसित करना → [`plugins/spec/AGENT-DEVELOPMENT.md`](../../plugins/spec/AGENT-DEVELOPMENT.md); कॉपी-पेस्ट न्यूनतम टेम्पलेट → [`plugins/spec/examples/`](../../plugins/spec/examples/)।

### प्लगइन योगदान देना

1. प्लगइन फ़ोल्डर को [`plugins/community/`](../../plugins/community/) (थर्ड-पार्टी प्लगइन) में डालें, या — Open Design के साथ बंडल शिप करने के लिए — [`plugins/_official/`](../../plugins/_official/) के मैचिंग टियर में।
2. वैलिडेशन पास करें: `od plugin validate`, `pnpm guard`, `pnpm --filter @open-design/plugin-runtime typecheck`।
3. [`plugins/spec/CONTRIBUTING.md`](../../plugins/spec/CONTRIBUTING.md) के टेम्पलेट का उपयोग करके PR भरें (ID, version, lane, mode, capabilities, trigger examples; विज़ुअल प्लगइन के लिए स्क्रीनशॉट / प्रीव्यू संलग्न करें)।
4. किसी बाहरी रजिस्ट्री (skills.sh / ClawHub / स्टैंडअलोन GitHub) पर प्रकाशित करने के लिए → [`plugins/spec/PUBLISHING-REGISTRIES.md`](../../plugins/spec/PUBLISHING-REGISTRIES.md)।

प्लगइन रजिस्ट्री एंडपॉइंट: `GET /api/plugins`। डायरेक्टरी ओवरव्यू → [`plugins/README.md`](../../plugins/README.md) ([简体中文](../../plugins/README.zh-CN.md))।

## आर्किटेक्चर

```
┌────────────────── browser (Next.js 16) / Electron shell ──────────────┐
│  chat · file workspace · iframe preview · settings · import · MCP     │
└──────────────┬─────────────────────────────────────┬─────────────────┘
               │ /api/*                              │
               ▼                                     ▼
   ┌─────────────────────────────────┐   /api/proxy/{provider}/stream (SSE)
   │  local daemon (Express+SQLite)  │   ─→ any OpenAI-compatible BYOK,
   │                                  │       SSRF-guarded at the edge
   │  /api/skills    /api/plugins    │
   │  /api/design-systems            │
   │  /api/chat (SSE)   /api/proxy/* │
   │  /api/projects/:id/files/...    │
   │  /api/artifacts/{save,lint}     │
   │  /api/import/claude-design      │
   │  MCP stdio server                │
   └─────────┬───────────────────────┘
             │ spawn(cli, [...], { cwd: managed project cwd })
             ▼
   ┌──────────────────────────────────────────────────────────────────┐
   │  claude · codex · cursor-agent · copilot · openclaw · antigravity ·│
   │  gemini · opencode · qwen · qoder · hermes (ACP) · kimi (ACP) ·    │
   │  pi (RPC) · kiro · kilo · vibe (ACP) · cline · trae · deepseek     │
   │  reads SKILL.md + DESIGN.md, writes artifacts to disk             │
   └──────────────────────────────────────────────────────────────────┘
```

| परत | स्टैक |
|---|---|
| फ़्रंटएंड | Next.js 16 App Router + React 18 + TypeScript |
| डेमन | Node 24 · Express · SSE स्ट्रीमिंग · `better-sqlite3` |
| स्टोरेज | डेमन स्टोरेज पाथ बदलने या प्रलेखित करने से पहले, आपको `AGENTS.md` → **Daemon data directory contract** पढ़ना आवश्यक है। इस README में इसे दोहराया नहीं जाना चाहिए। |
| प्रीव्यू | सैंडबॉक्स्ड `srcdoc` iframe + स्ट्रीमिंग `<artifact>` पार्सर |
| एक्सपोर्ट | HTML (इनलाइन) · PDF (ब्राउज़र प्रिंट) · PPTX (एजेंट-चालित) · ZIP · Markdown · MP4 (HyperFrames) |
| डेस्कटॉप | Electron shell + सैंडबॉक्स्ड रेंडरर + साइडकार IPC (STATUS · EVAL · SCREENSHOT · CONSOLE · CLICK · SHUTDOWN) |
| लाइफ़साइकिल | एक एंट्री पॉइंट: `pnpm tools-dev` (start / stop / run / status / logs / inspect / check) |

पूरा आर्किटेक्चर → [`docs/architecture.md`](../../docs/architecture.md)। स्किल प्रोटोकॉल → [`docs/skills-protocol.md`](../../docs/skills-protocol.md)। एजेंट एडाप्टर अनुबंध → [`docs/agent-adapters.md`](../../docs/agent-adapters.md)।

## योगदान

Open Design इसलिए आगे बढ़ता है क्योंकि योगदानकर्ता — डिज़ाइनर, इंजीनियर, प्रॉम्प्ट लेखक — लगातार सामने आते हैं। सबसे ज़्यादा उपयोग की जाने वाली कई स्किल, डिज़ाइन सिस्टम और प्लगइन कोर टीम के बाहर के लोगों ने लिखे हैं।

### 🎯 कहां से शुरू करें (अधिकतम प्रभाव, न्यूनतम बदलाव)

| शिप करना चाहते हैं… | कैसे | कहां |
|---|---|---|
| एक नई **स्किल** | `SKILL.md` + `assets/` + `references/` के साथ एक फ़ोल्डर डालें | [`skills/`](../../skills/) · स्पेक [`docs/skills-protocol.md`](../../docs/skills-protocol.md) में |
| एक नया **डिज़ाइन सिस्टम** | 9-सेक्शन स्कीमा का उपयोग करके एक `DESIGN.md` डालें | [`design-systems/<brand>/`](../../design-systems/) |
| एक नया **प्लगइन** | किसी श्रेणी फ़ोल्डर के अंतर्गत `open-design.json` + मैनिफ़ेस्ट डालें | [`plugins/community/`](../../plugins/community/) · स्पेक [`plugins/spec/SPEC.md`](../../plugins/spec/SPEC.md) में · एजेंट देव गाइड [`plugins/spec/AGENT-DEVELOPMENT.md`](../../plugins/spec/AGENT-DEVELOPMENT.md) में |
| एक नए **coding-agent CLI** का समर्थन | एक एडाप्टर एंट्री + स्ट्रीम पार्सर | [`apps/daemon/src/agents.ts`](../../apps/daemon/src/agents.ts) |
| बग ठीक या UI पॉलिश | [`good-first-issue`](https://github.com/nexu-io/open-design/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) लेबल ब्राउज़ करें | [Issues →](https://github.com/nexu-io/open-design/issues) |
| डॉक्स अनुवाद | `README.<lang>.md` फ़ाइलें अपडेट करें | [`TRANSLATIONS.md`](../../TRANSLATIONS.md) |

### 🤖 एजेंट के रूप में योगदान

अगर *आप यह पढ़ने वाला एजेंट हैं*, तो सबसे तेज़ रास्ता है:

```bash
# 1. Boot locally
git clone https://github.com/nexu-io/open-design.git
cd open-design && corepack enable && pnpm install
pnpm tools-dev run web

# 2. Find a good-first-issue and assign yourself
gh issue list --label "good first issue" --state open --limit 20
gh issue develop <number>   # create a branch and worktree

# 3. Make the change, run the checks
pnpm guard && pnpm typecheck
pnpm --filter @open-design/<package> test

# 4. Open the PR
gh pr create --fill
```

पूरा एजेंट-फ़्रेंडली योगदान फ़्लो, कोड स्टाइल, और PR बार → [`CONTRIBUTING.md`](../../CONTRIBUTING.md) ([Deutsch](../../docs/i18n/CONTRIBUTING.de.md) · [Français](../../docs/i18n/CONTRIBUTING.fr.md) · [简体中文](../../docs/i18n/CONTRIBUTING.zh-CN.md) · [日本語](../../docs/i18n/CONTRIBUTING.ja-JP.md) · [Português](../../docs/i18n/CONTRIBUTING.pt-BR.md))।
