## 결정
- 라우팅 = 매니페스트 트리거 + 데몬 단일 지점(접근법 A) — 근거: 결정적·테스트 가능·CLI dual-track 자동 충족, LLM 분류는 v2 후보 (사용자 A 승인)
- 자연어 직행이 1차, 라우터 폼은 폴백 — 근거: 사용자 "칩 선택 없이 자연어로만 요청했을 때 각 플러그인으로 이어지도록" 요구
- 기본 라우터 설정 = 설치 전역 app-config `defaultRouterPluginId` — 근거: 팀원 각자 설치, 온보딩 1회 설정 (사용자 선택)
- 핸드오프 = 재매칭 (별도 프로토콜 없음): 라우터 폼 옵션 value 슬러그가 버티컬 트리거에 매칭 → run-level pluginId 주입 → 기존 resolve가 re-pin — 근거: linkSnapshotTo*가 무조건 UPDATE 덮어쓰기(코드 검증), 메커니즘 1개로 진입·핸드오프 겸용
- fallbackRoute는 폼 답변 마커 게이트 — 근거: 최초 run의 원 프롬프트 재매칭이 none→od-default로 새면 라우터 폼이 아예 안 뜸 (셀프리뷰 발견)
- 자유입력 게이트에 프롬프트 존재 조건 배제 — 근거: 첨부-only 제출의 od-default 폼 현행 UX 보존 (셀프리뷰 발견)
