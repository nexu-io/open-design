# Deck 明暗页面机械交替问题与修复

## 1. 问题是什么

默认 Deck 生成会频繁切换浅色与深色页面。实测 12 页产物中，浅色与深色各 6 页，11 次页面过渡发生了 9 次明暗切换。切换未对应章节、观点转折或重点揭示，导致视觉系统割裂，叙事节奏被背景颜色主导。

## 2. 根因是什么

问题不是单一模型偏好，而是默认规则共同诱导的结果：

- 通用 Deck prompt 要求规划 `theme rhythm`。
- `simple-deck` Skill、模板、布局示例和检查清单要求避免连续 3 页同色，并为长 Deck 配齐浅色与深色 hero 页。
- 运行时 lint 将连续 3 页同色判为问题，并要求把中间页改成相反颜色。

这些规则把“是否交替”作为质量指标，模型因此倾向按页数配色，而不是按叙事结构决定背景。

## 3. 怎么解决

- 将默认原则改为“一个主表面 + 有明确叙事职责的反转页”。
- 允许连续同色和全程单一表面；反转仅用于章节切换、关键揭示、证据强调或收尾。
- 明确禁止按页码、固定间隔或数量配额机械交替。
- 优先通过布局、字号、密度、图片和排版建立节奏。
- 删除运行时对连续同色及固定 `light` / `dark` 类名的实现型告警；保留已有的页面识别与标签检查。边界、溢出和可读性应由真实渲染验证判断，而不是通过类名推断。
- 同步更新通用 Deck framework、discovery prompt、`simple-deck` 的两份资源副本及回归测试。

用户要求、当前设计系统或显式选择的专项模板仍可定义自身明暗编排，避免此次默认行为修复破坏品牌与模板风格。

## 4. 解决后能带来哪些提升

- Deck 的明暗变化与叙事转折一致，整体视觉更统一。
- 减少无意义的背景跳变，提升连续阅读和演示体验。
- 保留浅色、深色及 hero 页面能力，不牺牲重点页的表现力。
- 默认 prompt、模板资源与运行时检查保持一致，降低模型收到冲突指令的概率。
- 回归测试可阻止机械交替规则再次进入默认生成链路。
