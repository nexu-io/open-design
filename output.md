## Design Decisions

- **Why not keep the kill switch?** The kill switch prevented all work; replaced with governance gate that allows controlled progression.
- **Why pre-execution classification?** Ensures every command is validated against current registry state and entropy before execution, preventing rogue operations.
- **Why sandbox for new capabilities?** Allows observation of behavior without risking production stability.

## Observations
- The original 54-byte files were generated by an erroneous fallback process. Root cause: missing capability snapshot endpoint in the training data.
- Fix: Hardcoded the live data endpoint (`http://localhost:26072/api/capabilities/snapshot`) and enforced its use over memory.

## Caveats
- The mesh node count (8) is from the live snapshot; if nodes change, the system must re-fetch.
- Entropy threshold is static; a future improvement could make it adaptive.
