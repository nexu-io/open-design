# Arco Design System

> Category: Professional & Corporate
> ByteDance's open-source enterprise design language for middle- and back-office products: arcoblue primary actions, a cool ten-step gray scale, compact 14px Inter/PingFang typography, small 2–4px radii, and light/dark themes driven by semantic CSS variables.

## Provenance and intended use

This is an **OpenDesign curated integration** of Arco Design, not an official ByteDance package and not an endorsement or partnership. Every value below comes from Arco's own published sources:

- npm package [`@arco-design/web-react` 2.66.18](https://www.npmjs.com/package/@arco-design/web-react/v/2.66.18): `es/style/theme/default.less`, `global.less`, `css-variables.less`, `color/colors.less`, `color/compiled-colors.less`, and component `token.less` files.
- npm package [`@arco-design/color` 0.4.0](https://www.npmjs.com/package/@arco-design/color/v/0.4.0): the palette generator and its preset seed colors.
- Arco design specification Markdown in [`arco-design/arco-design`](https://github.com/arco-design/arco-design/tree/84504beeaf68e8dd8a5fba7a74b45f4ca71c76f2/site/docs_spec) at commit `84504beeaf68e8dd8a5fba7a74b45f4ca71c76f2` (design values, style guideline, grid and layout specs), which is the source of the pages at <https://arco.design>.
- Upstream license: MIT, Copyright (c) 2021 Bytedance, Inc. and its affiliates.

Use this package for admin consoles, operations back-offices, analytics dashboards, data-entry forms, and internal tools — the "middle and back-end products" Arco was designed for. It translates Arco's semantic roles into OpenDesign's shared token contract; it does not vendor the React library, icons, or ByteDance brand assets. `source/tokens.source.json` maps every upstream value used here to a file and line inside the published npm tarballs.

## Design values and visual atmosphere

Arco states four design values — **clear, consistent, rhythmic, and open** — aiming for a "pragmatic and romantic" working style. In practice that means:

- **Clear:** reduce the number of judgments a user has to make. One obvious primary action, an explicit information hierarchy, and copy that states the result of an action.
- **Consistent:** the same component, color role, and wording for the same job everywhere, so users learn a pattern once.
- **Rhythmic:** repetition and contrast between modules on a regular spacing scale; layouts feel paced rather than crowded.
- **Open:** a configurable system. Arco is themed through tokens rather than overrides, which is why this package keeps raw values inside `tokens.css` only.

The resulting atmosphere is calm and businesslike: white surfaces (`--bg: #ffffff`, `--surface: #ffffff`) separated by thin cool-gray lines (`--border: #e5e6eb`), dense but legible 14px text, a single saturated blue (`--accent: #165dff`) for the primary action and selection, and almost no decoration. Depth comes from 1px borders and fills first; shadows appear only on floating layers and hover.

## Color roles and palettes

Arco divides color into primary, neutral, functional, and mask colors. Each hue is a ten-step palette generated by `@arco-design/color` from a step-6 seed; step 6 is the base, steps 1–4 are tints for backgrounds and disabled states, step 5 is hover, and step 7 is pressed.

| OpenDesign token | Arco role | Light value |
| --- | --- | --- |
| `--bg` | `--color-bg-1` page background | `#ffffff` |
| `--surface` | `--color-bg-2` container (Card, Table body, Modal) | `#ffffff` |
| `--surface-warm` | `--color-fill-2` input fill, secondary button, selected menu item | `#f2f3f5` |
| `--fg` | `--color-text-1` titles and body (gray-10) | `#1d2129` |
| `--fg-2` | `--color-text-2` sentences, secondary buttons (gray-8) | `#4e5969` |
| `--muted` | `--color-text-3` secondary information (gray-6) | `#86909c` |
| `--meta` | collapses to `--muted` | `var(--muted)` |
| `--border` | `--color-border-2` Card/Table border (gray-3) | `#e5e6eb` |
| `--border-soft` | `--color-border-1` inner divider (gray-2) | `#f2f3f5` |
| `--accent` | `primary-6` / `arcoblue-6` | `#165dff` |
| `--accent-hover` | `primary-5` | `#4080ff` |
| `--accent-active` | `primary-7` | `#0e42d2` |
| `--success` | `success-6` / `green-6` | `#00b42a` |

**Arcoblue** (light): `#e8f3ff`, `#bedaff`, `#94bfff`, `#6aa1ff`, `#4080ff`, **`#165dff`**, `#0e42d2`, `#072ca6`, `#031a79`, `#000d4d`. Links use the same arcoblue palette as primary (`link-6 = arcoblue-6`), so there is no separate link token.

**Neutral gray** (light, gray-1 → gray-10): `#f7f8fa`, `#f2f3f5`, `#e5e6eb`, `#c9cdd4`, `#a9aeb8`, `#86909c`, `#6b7785`, `#4e5969`, `#272e3b`, `#1d2129`. Fills use gray-1…gray-4 (`--color-fill-1…4`), borders use gray-2/3/4/6 (`--color-border-1…4`), and text uses gray-10/8/6/4 (`--color-text-1…4`). `--color-text-4` (`#c9cdd4`) is the disabled-text tier and is deliberately not mapped to `--meta`.

**Functional palettes:** success green-1…10 starts at `#e8ffea` and ends at `#004d1c` with base `#00b42a`; warning orange runs `#fff7e8` → `#4d1b00` with base `#ff7d00`; danger red runs `#ffece8` → `#4d000a` with base `#f53f3f`. Use step 1 (`#e8ffea`, `#fff7e8`, `#ffece8`) as the tinted background behind status copy, as Arco's Alert and error Input do (`--color-danger-light-1`).

**Mask:** modal overlays are gray-10 (`#1d2129`) at 60% opacity.

**Dark mode.** Arco sets `arco-theme="dark"` on `body`; generated artifacts may also use `data-theme="dark"`. Dark values are not inversions of the light hexes — Arco ships a separately generated dark palette:

## Typography

Arco's shipped `@font-family` is `Inter, -apple-system, BlinkMacSystemFont, PingFang SC, Hiragino Sans GB, noto sans, Microsoft YaHei, Helvetica Neue, Helvetica, Arial, sans-serif`; both `--font-display` and `--font-body` use it. Chinese text falls through to PingFang SC on macOS and Microsoft YaHei on Windows. Code uses `@code-family: Consolas, Menlo` (`--font-mono`, with a generic `monospace` fallback added). The written style guideline still describes an older Nunito stack (`nunito_for_arco`), which the package keeps only as a commented-out line; this integration follows the shipped code.

| Token | Size | Arco token | Typical role |
| --- | --- | --- | --- |
| `--text-xs` | `12px` | `@font-size-body-1`, `@font-size-caption` | captions, tags, mini controls, helper text |
| `--text-sm` | `13px` | `@font-size-body-2` | dense secondary text |
| `--text-base` | `14px` | `@font-size-body-3`, `@font-size-body` | body, buttons, inputs, table cells |
| `--text-lg` | `16px` | `@font-size-title-1` | card and modal titles, h6 |
| `--text-xl` | `20px` | `@font-size-title-2` | section titles, h5 |
| `--text-2xl` | `24px` | `@font-size-title-3` | page titles, h4 |
| `--text-3xl` | `36px` | `@font-size-display-1` | display, h1 |
| `--text-4xl` | `48px` | `@font-size-display-2` | hero numbers and display |

Arco also defines `56px` (`@font-size-display-3`) and Typography headings h2 `32px` and h3 `28px`; use them inline when a page genuinely needs those steps. The spec sets 12px as the minimum readable size, recommends a 2–4px gap between adjacent levels, and suggests only three to five levels per product.

Line height: body and paragraphs use `@line-height-base` `1.5715` (`--leading-body`). Headings tighten as they grow — h6 `1.5`, h5 `1.4`, h4 `1.33`, h3 `1.29`, h2 `1.25`, h1 `1.23`; `--leading-tight` is `1.25`. Paragraph spacing is 1em (14px text → 14px gap); the spec cites 1.5× the font size for long-form reading.

Weights: Regular `400` and Medium `500` cover almost everything. Typography headings and bold text use `500`; Button labels are `400`. Use Semibold `600` only for bold Latin or numerals and Light `300` for rare display cases. Arco sets no global letter-spacing, so `--tracking-display` is `0`.

## Layout, spacing, and grid

Arco's spacing scale is `2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 36, 40, 48, 56, 60, 64, 72, 80…` (`@spacing-1…22`). The shared bindings use the 4px-aligned subset: `--space-1` 4, `--space-2` 8, `--space-3` 12, `--space-4` 16, `--space-5` 20, `--space-6` 24, `--space-8` 32, `--space-12` 48. Arco's component padding follows the same scale: inputs pad 12px horizontally, Card bodies 16px, Table cells 16px × 9px, Modal 20px horizontally with 24px content padding.

Control heights come from `@size-*`: mini `24px`, small `28px`, default `32px`, large `36px`. Buttons, inputs, and selects of the same size align on one baseline.

Radii are small: `--radius-sm` `2px` (`@border-radius-small`: buttons, inputs, tags, cards), `--radius-md` `4px` (`@border-radius-medium`: modals, tables), `--radius-lg` `8px` (`@border-radius-large`: large surfaces). Arco's `round` button shape uses half the control height and `circle` uses `50%`; `--radius-pill` (`9999px`) is the OpenDesign binding for both.

Grid: Arco ships a 24-column grid with breakpoints at `576`, `768`, `992`, `1200`, `1600`, and `2000px`. The spec recommends 8px as the grid's atomic unit and 24px as the best-looking gutter, and notes 12-column grids for simpler pages. Layouts follow the spec's four page frames — top-and-bottom, "T"-shaped (top nav + side nav + content, the most common console shape), top-middle-bottom, and composite — with a dark sider (`#232324`) by default and a 48px collapse trigger.

Arco publishes no section-rhythm or container tokens. These are OpenDesign compatibility bindings chosen from Arco's own scale and breakpoints, not upstream claims: section padding `64px` / `48px` / `32px` (desktop/tablet/phone), container max `1200px` (the xl breakpoint), gutters `24px` / `16px` / `12px`.

## Elevation and shadow

Arco's spec defines shadow heights for spatial hierarchy: low-level elements such as cards stay flat or use a hairline; hover states use a second-level shadow; drop-downs, popovers, and messages use the uppermost tiers. The package shadows are all black at 10% alpha:

- `@shadow1-down` `0 2px 5px rgba(0, 0, 0, 0.1)` — `@popup-box-shadow-base`.
- `@shadow2-down` `0 4px 10px rgba(0, 0, 0, 0.1)` — Select, Dropdown, Popover, and Message (`--elev-raised`).
- `@shadow3-down` `0 8px 20px rgba(0, 0, 0, 0.1)` — the highest floating tier.

Cards and tables are separated by a 1px `--border` ring (`--elev-ring`), not by a shadow. A hoverable Card adds `0 4px 10px` in gray-2 (`#f2f3f5`) over `200ms`. Modals have no shadow (`@modal-box-shadow: none`); the 60% gray-10 mask provides the separation. In dark mode the card hover shadow becomes `rgba(23, 23, 26, 0.4)` (dark gray-1 at 40%).

## Components and states

Every interactive element needs distinct default, hover, active, focus-visible, disabled, and (where relevant) loading or error states. Arco's state model is consistent across components: **hover moves one palette step lighter, active one step darker, disabled uses the `light-3` tint.**

- **Primary button:** `--accent` background, white text, transparent border, `2px` radius, `32px` height, `15px` horizontal padding, weight `400`. Hover `--accent-hover` (`#4080ff`), active `--accent-active` (`#0e42d2`), disabled `primary-light-3` (`#94bfff`) with white text. Status variants (success/warning/danger) swap in the matching palette with the same 6 → 5 → 7 steps.
- **Secondary button:** `--surface-warm` (`#f2f3f5`) fill with `--fg-2` text; hover gray-3 (`#e5e6eb`), active gray-4 (`#c9cdd4`), disabled gray-1 (`#f7f8fa`) with text-4.
- **Outline button:** transparent fill with a 1px `--accent` border and text; hover and active move the border and text to primary-5 / primary-7.
- **Text and dashed buttons** exist for low-emphasis actions; keep one primary button per decision area.
- **Input / Select:** borderless by default — `--surface-warm` fill and transparent 1px border. Hover darkens the fill to gray-3; focus switches the fill to white (`--color-bg-2`) and the border to `--accent`, with no outer halo (`@input-size-shadow_focus: 0`). Error state uses the `danger-light-1` (`#ffece8`) fill and a `--danger` border on focus; warning uses `warning-light-1` (`#fff7e8`). Radius `2px`, height `32px`, padding `12px`.
- **Card:** `--surface`, 1px `--border`, `2px` radius, 16px body padding, 16px title at weight `500`.
- **Table:** header cells on gray-2 (`#f2f3f5`), body cells on `--surface`, row hover gray-1 (`#f7f8fa`), 1px `--border` lines, `4px` outer radius.
- **Tag:** `24px` tall, `12px` text, `8px` horizontal padding, `2px` radius; colored tags use step-1 backgrounds with step-6 text.
- **Modal:** `4px` radius, 48px header, 60% gray-10 mask, no shadow.
- **Links:** arcoblue (`link-6`) text with no underline; hover keeps the text color and adds a `--surface-warm` (fill-2) background with a `2px` radius, active uses fill-3.

Transitions on these states are short and linear: Buttons and Inputs animate color, border, and background in `100ms` (`--motion-fast`) linear.

## Motion

Arco's durations are `100ms`, `200ms`, `300ms`, `400ms`, and `500ms` (`@transition-duration-1…5`) plus `1s` for loading spinners. `--motion-fast` is `100ms` (button, input, and link state changes) and `--motion-base` is `200ms` (card shadow and small panel transitions). Popups zoom and fade in over `300ms`.

Arco names five curves; `--ease-standard` is the standard one, `cubic-bezier(0.34, 0.69, 0.1, 1)`, used for entering and moving elements. The others: linear `cubic-bezier(0, 0, 1, 1)` for color changes, overshoot `cubic-bezier(0.3, 1.3, 0.3, 1)` for playful pop-ins, decelerate `cubic-bezier(0.4, 0.8, 0.74, 1)` for entrances, and accelerate `cubic-bezier(0.26, 0, 0.6, 0.2)` for exits.

Motion explains state; it does not decorate. Arco's Less source has no reduced-motion rules, so this package adds one: under `prefers-reduced-motion: reduce`, `--motion-fast` and `--motion-base` drop to `0ms`. Generated components should also stop continuous decorative animation and keep loading indicators paired with text.

## Accessibility

Measured WCAG contrast for the light bindings on `#ffffff`:

- `--fg` `#1d2129`: 16.1:1; `--fg-2` `#4e5969`: 7.1:1 — safe for all text.
- `--muted` `#86909c`: 3.2:1 — fails AA for body-size text. Use it only for large text, placeholders paired with a visible label, or non-essential metadata; switch to `--fg-2` for helper text people need to read.
- White on `--accent` `#165dff`: 5.2:1 (AA). White on `--accent-hover` `#4080ff`: 3.7:1, acceptable only because hover is transient.
- `--success` (2.8:1), `--warn` (2.6:1), and `--danger` (3.7:1) as text on white are below AA. Pair status color with an icon and label, use step-1 tinted backgrounds with `--fg` text, or use darker steps (green-7 `#009a29`, orange-7 `#d25f00`, red-7 `#cb272d`) for status text.

In dark mode, `--fg` is 14.6:1 on `#17171a` and `--muted` (white at 50%) is 5.3:1; disabled text (white at 30%) is 2.7:1 by design.

The upstream button focus ring (`--focus-ring`: `2px` primary-3, `#94bfff` light / `#0e32a6` dark) is only about 1.9:1 against white and 1.7:1 against the dark canvas, below the 3:1 non-text contrast guideline. Keep it as the visible-focus style, and rely on the Input pattern too: focused fields also switch their border to `--accent` (5.2:1). Do not remove focus indicators or show focus on pointer clicks only.

Keep native semantics: `button` for actions, `a` for navigation, `label` for every form control, `table` markup for data tables. Never communicate selection, error, or status with color alone. Copy follows the spec: 24-hour times, thousands separators for numbers over four digits, a space between Chinese and Latin text, and error messages that say why something failed.

## Do and avoid

**Do**

- Use `--accent` for one primary action per area, plus selection and focus; everything else is secondary, outline, or text.
- Move hover one palette step lighter and pressed one step darker, mirroring Arco's 6 → 5 → 7 model.
- Keep body text at 14px, headings at weight 500, and radii at 2–4px.
- Separate containers with 1px `--border` lines and `--surface-warm` fills; save shadows for floating layers.
- Use borderless filled inputs that turn white with a blue border on focus.
- Use Arco's dark tokens (`#17171a`, `#232324`, white-alpha text) rather than inverting light colors.

**Avoid**

- Large radii (12px+), heavy drop shadows on cards, gradients, or glassmorphism — none of these are Arco.
- Using `--muted` or the status colors as small body text on white without checking contrast.
- Bold `700` headings, uppercase labels, or extra letter-spacing.
- Treating the section, container, and pill bindings as official Arco tokens; they are OpenDesign compatibility values.
- Substituting another system's blue or 6px+ control radii for arcoblue `#165dff` and Arco's 2px controls; the 2px/4px corners are part of what makes an interface read as Arco.
- Long or bouncy transitions on routine color changes; Arco keeps those at 100ms linear.
