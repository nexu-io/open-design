# 주제 추천 서브에이전트 — dispatch 지시

메인 에이전트: 사용자 요청에 구체 주제가 없을 때(1.5단계) 서브에이전트 dispatch 도구가
있으면 **반드시** 이 지시로 주제 발굴을 분리 실행한다. 없으면 아래 "서브에이전트 임무"를
인라인으로 동일 수행한다(산출물 계약 동일). `research-subagent.md`(확정 주제의 사실
수집 = 수렴)와 역할이 다르다 — 이쪽은 주제 발굴(발산)이다. dispatch 프롬프트에 다음
입력을 채워 넣는다:

- `{design_md_path}` — 활성 design-systems/<brand>/DESIGN.md 절대 경로
- `{cwd}` — 프로젝트 작업 디렉토리 절대 경로
- `{category_hint}` — 사용자가 준 힌트 카테고리 (없으면 "없음")

## 서브에이전트 임무 (dispatch 프롬프트 본문)

너는 네이버 블로그 주제 발굴 전담 에이전트다. 최종 텍스트 반환만이 메인에게 전달된다 —
잡담 없이 결과만.

1. `{design_md_path}` Read — 카테고리 체계, 라이브 블로그 주소·categoryNo(정의돼 있으면),
   금지 표현·핵심 용어·출처 정책을 확인한다.
2. **발행 이력 조회** — DESIGN.md가 라이브 블로그 주소와 categoryNo를 정의할 때만.
   정의가 없으면 이 단계를 스킵하고 이력 없이 진행한다. categoryNo별 최근 10~20건
   제목+날짜를 수집한다:

   ```bash
   curl -sL \
     -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1" \
     -H "Referer: https://m.naver.com/" \
     "https://blog.naver.com/PostTitleListAsync.naver?blogId=<블로그ID>&currentPage=1&categoryNo=<N>&parentCategoryNo=<N>&countPerPage=20"
   ```

   응답 주의: `title`은 URL-인코딩이고 **비표준 `\'` 이스케이프가 섞여 표준 JSON 파서가
   실패한다 — `\'` → `'` 치환 후 파싱**(2026-07-03 검증). 조회 실패 시 경고 1줄 남기고
   이력 없이 계속 진행한다(추천 자체는 중단하지 않는다).
3. `{cwd}/topic-blacklist.md` 있으면 Read — 사용자가 다루기 싫은 소재 목록(선택 입력,
   없으면 스킵).
4. WebSearch 트렌드 수집 — **한 턴에 병렬 3~4쿼리**: `[카테고리 소재] [현재연도] 최신` /
   `[카테고리 소재] 변경사항 개정` / `[카테고리 소재] 주의사항 팁`. 질병코드류 카테고리는
   `[질병코드/병명] 보험금 청구 거절 분쟁` 전용 쿼리를 추가한다. `{category_hint}`가
   있으면 그 카테고리에 쿼리를 집중한다. DESIGN.md 출처 정책 준수 — 금지 출처(예: 네이버
   블로그/카페/지식iN)는 후보 근거로 쓰지 않는다.
5. **핵심 소재 기준 dedup** — 글자 일치가 아니라 소재 일치로 거른다:
   - 이력·blacklist 각 항목에서 핵심 소재(보험상품·질병코드·진료/시술·제도 개념)를
     추출하고, 새 후보와 소재가 겹치면 **각도가 달라도 제외**한다.
   - 발행 60일 이내 소재 = 자동 제외 / 61~90일 = 후보 표에 ⚠️ 표시(사용자 판단 위임) /
     91일+ = 각도 차별화 전제로 허용.
   - 후보 확정 직전 자가검증: 후보마다 "어떤 이력 항목과도 소재 불겹침"을 1줄씩 확인한다.
6. 반환(최종 텍스트, **≤25줄**): 후보 5~8개 표 — 컬럼: 후보 주제 / 카테고리 / 핵심 각도 /
   후킹 앵글(오해·손해회피·시의성 중 1) / 기존 발행(❌ 없음 | ⚠️ N일 전 "제목") / 근거
   출처 1개. 검색 결과 원문·SERP 덤프는 반환에 넣지 않는다.

메인 에이전트: 반환 표를 마크다운 카드로 제시하고 후보 선택 폼을 발행한다(제네릭
`<question-form>` 아티팩트 — 옵션 = 각 후보 + "직접 입력", 옵션 value는 후보 주제
슬러그) → **즉시 턴 종료**. 폼 발행 턴에 리서치·기획으로 직행하는 것 절대 금지(4단계
컨펌 게이트와 동일 규율). 폼 블록 밖 프로즈에 폼 태그 리터럴을 쓰지 않는다. 선택 답변이
다음 user 메시지로 도착하면 그 주제로 2단계 인터뷰에 합류한다(주제 축은 기확정 —
인터뷰에서 제외).
