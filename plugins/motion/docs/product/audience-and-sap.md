# 人群与 SAP 目标画像

更新：2026-11-04。状态：基于当前产品能力与已提出需求形成的画像初稿，尚未经过用户访谈或付费实验验证。

术语说明：沿用需求中的“SAP 目标画像”称呼，本轮先按目标用户/客户画像组织角色、场景、目标、行为和购买决策。SAP 的既定英文含义尚未确认；确认后在本页和 [需求记录](changes.md) 同步更新。这里的编号是本仓库的画像索引。

## 已有证据与判断边界

目前明确的需求包括多 Agent 接入、统一弹框、真实成片预览、可跳转出处、简短复刻指令，以及原帖热度和分类。这些证据支持“已有 Agent 用户需要更顺畅的视频发现与制作链路”这一方向。

需求提出者的偏好尚不能证明某类客户规模、使用频率、预算或购买意愿。下表的优先级是用于指导验证的工作假设，后续根据真实使用结果调整。

## 人群分层

| 画像 | 工作优先级 | 典型触发 | 任务与期望结果 | 使用者 / 决策者 | 待验证重点 |
| --- | --- | --- | --- | --- | --- |
| SAP-01：使用 Agent 的独立开发者与创始人 | 优先验证 | 发布产品、更新功能、准备演示 | 用已有产品事实和参考快速完成可编辑发布视频 | 常为同一人，也可能由合伙人决定支出 | 是否能独立激活、是否反复制作、愿意为哪部分省时付费 |
| SAP-02：小型产品与增长内容团队 | 第二优先 | 多渠道发布、活动与版本更新 | 在品牌一致的前提下持续产出、复用和修改 | PMM/增长/设计使用，团队负责人决策，工程人员可能协助接入 | 品牌复用、审阅协作和产能是否构成高频需求 |
| SAP-03：视频自由职业者与内容工作室 | 探索 | 客户要求参考同款、交付多个版本 | 减少重复制作和修改，保留可交接工程 | 制作者使用，工作室负责人或客户决定服务预算 | 原生 HTML 工程是否适合其交付，质量与修改效率是否达标 |
| SAP-04：Agent 工具开发者与集成团队 | 探索 | 希望在自身工具链中加入视频产出 | 通过稳定 MCP/API 管理工程、渲染与验证 | 工程团队使用，产品/技术负责人决策 | 本机集成需求、可维护性和支持成本 |

当前入口需要安装本地运行环境或插件。完全没有 Agent 和本地配置经验的人群需要额外验证接入成本。企业采购、托管协作、权限管理等需求先作为候选方向记录，不能据此描述当前产品已具备企业能力。

## SAP-01：首要验证画像

| 维度 | 工作画像 | 证据状态 |
| --- | --- | --- |
| 角色与环境 | 已用 Codex、Claude Code 或 DeepSeek Harness 编写/修改产品的开发者或创始人 | 与当前接入能力匹配，实际占比待采集 |
| 目标 | 为一个真实产品做出可发布、可再修改的演示或宣传视频 | 来自已有制作与复刻需求 |
| 触发 | 新品、功能更新、发布帖、产品展示 | 场景假设，需访谈与任务观察 |
| 输入 | 产品链接、截图、文案、品牌素材或参考视频 | 当前工程与制作流程支持此类输入 |
| 痛点 | 选参考难、复刻指令长、配置打断创作、得到的视频不便修改 | 已提出需求直接支持 |
| 理想首次价值 | 接入成功，选中参考后在同一工作区看到可编辑初稿 | 产品目标，完成时间基线待采集 |
| 质量门槛 | 事实准确、画面与参考目标一致、内容可改、最终文件可播放 | 已有制作与验证规范 |
| 购买角色 | 使用者本人或其团队预算负责人 | 假设，需核对真实决策链 |
| 付费触发 | 重复制作时的时间节省、托管计算、稳定交付或专业支持 | 待验证，不代表已愿意购买 |
| 可能流失点 | 安装失败、Agent 无法完成复刻、初稿质量差、工程修改困难 | 待观察并按失败原因记录 |

## SAP-02 与 SAP-03 的差异

团队用户更需要验证品牌、资产、审批与多人交接的价值；个人制作者更需要验证可交付质量与反复修改效率。两类需求不应仅以“高级用户”合并，因为使用者、预算负责人、付费单位和成功标准可能不同。

候选团队流程应说明谁提供产品事实、谁制作、谁审核、谁确认成片；候选工作室流程应说明项目输入、验收边界、可编辑工程格式及修改轮次。当前本地共享工程不等同于多人云端协作，原生 Hyperframes 工程也不等同于其他剪辑软件的项目文件。

## 用户目标与观察方法

| 要验证的问题 | 观察方法 | 应留下的证据 |
| --- | --- | --- |
| 是否存在明确、高频的制作任务？ | 请用户描述并实际完成最近一次任务 | 触发、频率、原有步骤与真实交付物 |
| 接入是否顺畅？ | 观察首次安装、工具验证和工程打开 | 失败点、需要的协助与完成时间 |
| 模板是否帮助完成作品？ | 记录选参考到编辑初稿的全过程 | 选中 ID、参考理由、复刻结果与返工原因 |
| 可编辑工程是否有价值？ | 让用户完成一次具体修改或交接 | 修改内容、是否需要重做、交接结果 |
| 用户愿意为何付费？ | 展示明确的增值方案并验证实际承诺 | 买方、预算来源、可接受单位、未购买原因 |

目前没有可报告的访谈样本数、转化率或付费意愿比例。新增证据时记录日期、来源、观察窗口和匿名角色；访谈原文或客户素材按适当权限保存，本仓库只沉淀可共享结论。

## 后续需求如何补充画像

每条需求至少关联一个现有画像，或说明新增画像的理由。新增信息应明确属于哪个角色、什么场景、哪项证据，避免直接改写为整个市场的共性。

新增画像使用稳定编号，并补充：角色与环境、触发、要完成的任务、当前做法、痛点、成功标准、使用频率、使用者/买方/决策者、预算状态、发现渠道、采用阻力、证据与下一步验证。预算未知时保留未知。

画像变化影响 [产品架构](architecture.md) 的流程或 [商业化策略](commercialization.md) 的买方、套餐和渠道时，同批更新并记录在 [需求与决策记录](changes.md)。
