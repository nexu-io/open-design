# 把导演判断落实到素材、时间和状态

用于含截图、跨段复现对象、多段强 Motion，或已有逐页展示/状态回退问题的任务。复用动作脚本和审片记录，不新增必填表。它约束判断与实现的一致，不指定风格、镜头数、速度或具体转场。

## 素材职责决定它如何占用时间

使用素材前明确它当前承担：事实证据、关系图解、主要表演、阅读内容，还是氛围。一个素材可以换职责，但新的职责需要在画面中成立。

截图能证明界面存在，裁切能揭示原来不可见的重点；两张截图切换可以展示两个状态。若要声称“正在修改”“结果随操作改变”，画面还需要可追踪的变化证据。只有静态截图时，可选准确的局部重建、明确标注的概念图解、取得真实操作素材，或收窄主张；根据实际工具与授权选择。真实证据不必独占一整个功能章节。

在粗稿中看截图从重点被识别，到下一次有效变化之间发生了什么。若既不增加可读信息，也不建立有意的期待、情绪或节奏，应缩短、重编上下文或换表达材料。不能仅因预计给该卖点七秒，就把静态画面推近七秒。此处七秒只是失败示例，不是时长阈值；复杂阅读任务也可能需要更长时间。

“不展示截图”本身不是目标。脱离截图后，如果只剩标题、任意圆点或装饰漂移，仍没有解决表达。

## 复现的是对象当前版本，不只是相同名字

同一对象在修改、对照、总结或交付中再次出现时，明确它引用哪个状态。只记录影响理解的属性，如内容、相对布局、关键数值、选中项、形态，或本次改变的动作时长、顺序与声画关联；不要求把所有 CSS 都复制进表格。

程序化制作优先让这些语义属性来自同一个数据/组件/状态定义，再把它放进不同景别或版式。示意：

```text
object.initial = 初始内容与布局
object.revised = 在 initial 上应用已展示的修改
resultView.render(object.revised, framing)
```

具体引擎可用共享对象、渲染函数、组件参数、预合成或同一实例；不强制一套架构。不同镜头可以改变取景、整体缩放和环境，但不能因重写一个缩略图就把修改结果无意恢复。若需要撤销、换版本或回忆，给出可理解的依据。

核对实际的“修改落定帧”和“稍后再现帧”，必要时对齐对象局部、排除整体缩放，检查语义状态是否保留。相邻接点无缝不能证明十秒后的状态仍正确；源码参数一致也不能替代最终画面。

检查方式跟随被修改的属性。布局和颜色可用成对帧；时长、节奏、动作顺序等时间状态，需要实际动态片段或可定位的事件回归。静态缩略图可以用于交付展示，但不能单独证明这些动态修改已延续。多个表现同一作品的播放视图应引用同一当前内容与时间状态，避免只共享字号/颜色、却另写一套旧动画。无需在成片里重复每个动作；按观看目的选择合适的再现，并保留足以验证关键修改的输出证据。

## 整片粗稿查时间分配，不只查最精彩的段落

粗稿可复用当前引擎，以低成本材质和少量细节呈现全片；主要动作和接点用实际时间表达，不用仅含终态的静态分镜代替。目标是便宜地改变结构，不是新增一套交付仪式。

重点查较长、重复或已被指出平淡的区间：主要信息何时已建立；之后哪次变化继续推进观看；两者之间是否有实际阅读、期待、情绪或其他职责。若主要动作早已结束，只是在等章节时间耗尽，应调整这一段和相邻段的关系。不是把全片加速，也不是让所有对象永远运动。

保留同一片子的不同组织方式：连续对象表演、剪辑蒙太奇、文字节奏、固定构图中的关系发展、真实操作等都可用。判断空间、尺度与时间变化是否来自内容，而非强行给每段分配一种特效。

## 审片失败要回到具体实现

只记录当前最影响目标的少量问题，用已有“观测→原因候选→修改→验证”记录推进。若已写“状态连续”，实际却回退，查再现对象的创建代码和状态来源；若已写“避免 PPT”，实际仍是长截图，查它被赋予的表达职责及粗稿时间分配。修改原因对应的表示或编排，再看实际输出。

修正预算优先用于本次核心质量问题。修字号、重叠、编码与工具警告是必要技术工作，但不证明主体发展、全片节奏或声画叙事已通过。不能把旧问题重命名为“克制”“阅读”“有意错拍”来回避证据；这些选择可以成立，但应有与委托一致的实际观看收益。

比较多版时保留有效变化，不为显得新颖全部重做。有实质收益就保留；同一错误没有新依据时先查日志、表示或工具能力，不在几个缓动值之间盲目循环。迭代上限依本次用户要求或任务预算，不把固定轮数设为所有创作的常规。

## 声画共用关键事件

需要精确同步时，让相关动作和音效引用同一事件时间或从同一事件表生成，避免两份独立时间数字随修订漂移。事件应指向视觉感知重点；音频文件自身的起音偏移需另核对。音乐、预告声和跨段尾音可以不锁定动作起点，不强制每次变化卡拍。

有意错位需要实际听看判断是否成立，不能仅凭合成代码把任何延迟解释为设计。当前能力不能审听时，完成可做的时序与技术验证，同时保留听感未知。

## 依据与适用边界

整片粗稿用于提前检查时间、节奏与构图，参考 [School of Motion 的制作流程](https://schoolofmotion.com/blog/guide-completing-motion-design-project)。以时间线组织关联动作可使用当前引擎的既有能力，例如 [GSAP Timeline](https://gsap.com/docs/v3/GSAP/Timeline/)。上面的状态延续与失败诊断是针对实际错误归纳的通用实现建议，不是这些来源已证明本 Skill 有效果；仍须用实际产物验证。
