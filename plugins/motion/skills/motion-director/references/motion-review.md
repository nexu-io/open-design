# Motion 审片：按意图验证，不按效果计数

## 证据与检查范围

先确认当前版本、观看规格、实际视频／预览，以及已知占位素材。正常速度观看受影响片段；必要时慢放和抽帧定位。帧序列可检查状态、构图与接点，不能独立证明节奏自然、声音同步或播放流畅。

全片交付需完整播放当前版本；局部修改先检查修改区间及相邻接点，无关部分不反复全量检查。若缺少观看能力，明确只完成技术检查或帧检查，不能宣称完成动态审片。

## 核心判断

| 维度 | 应观察什么 | 典型问题 | 不能作为失败的单独理由 |
| --- | --- | --- | --- |
| 表达与事实 | 运动／剪辑／静止是否支持信息或感受；产品行为准确 | 动画华丽但卖点不成立；虚构操作 | 没有功能演示、没有因果动作 |
| 动态组织 | 时间中是否有经过设计的发展、对比、表演或重音 | 只有统一入场，之后等待换页 | 镜头长、画面安静、文字为主 |
| 注意力与构图 | 关键变化能否被发现和跟随；比较关系是否清楚 | 多处抢眼、主体丢失、阅读被运动打断 | 两个同等重要对象、固定机位 |
| 节奏与可读性 | 信息密度、动作、声音、停顿是否相适应 | 无意义等待、全片同节拍、看不清结果 | 缓慢、顺序执行、不踩音乐拍点 |
| 段落关系 | 所选连续或断裂是否成立，接点有无意外跳动 | 同对象突然变位、方向冲突、转折难懂 | 硬切、淡化、不无缝 |
| 运动表现 | 路径、加减速、接触、形变是否符合此片的运动逻辑 | 非预期机械匀速、漂浮、廉价弹跳、抖动 | 匀速、弹性、夸张本身 |
| 声画关系 | 有声音时是否帮助节奏、理解或情绪 | 音效错位、音乐遮盖语音、画面误导旁白 | 无声、不为每次动作配音效 |
| 技术与交付 | 素材、裁切、字体、帧边界、音频与导出是否正确 | 黑帧、缺图、字体替换、预览导出不一致 | 技术通过不等于上述创作维度通过 |

使用“成立／需修改／未验证”，并写证据。没有真实评分基准时，不给虚假的综合分数或自动合格阈值。

先对照用户要求的运动强度与参考：用户要求强 Motion 时，不能仅以“静止也可以有意图”通过一条缺少动态编排的片子；用户要求安静时，也不能以“运动不足”强加特效。两种情况都需要指出实际时间组织带来的观看收益。

## PPT 感的诊断路径

看到逐页展示感时，按最可能的层级定位，不必每次全部走完：

1. **表达**：是否只有静态卖点清单？能否用实际操作、关系变化、文字节奏、剪辑或视觉表演承载其中的重要信息？先改表达单位。
2. **结构**：是否反复采用完整排版、统一入场、静止、清空的周期？检查重复是否来自内容，还是来自场景组件便利性。
3. **注意力与连接**：镜头切换是否每次让人重新寻找主体？应延续时没有延续，还是本来需要明确断开？
4. **时间**：是动作太长、阅读太短，还是镜头长度与能量缺少对比？不要统一加速。
5. **细节**：结构成立后，再改路径、缓动、延迟、模糊、声音或次级运动。

重点区分**呈现动作**与**表达发展**：截图推近可以揭示关键区域，但若既没有可读的新细节、关系变化，也没有建立节奏或情绪，就不能只凭运镜认定 Motion 叙事成立。卡片减少、对象延续、切镜变少也都不是独立质量指标。

对产品卖点，检查动作实际显示的证据是否足够支持文案；“改了参数”与“结果因此变化”是不同信息。缺少真实操作素材时可使用准确且标明的概念演示，不能伪装录屏。对品牌或文字片则检查知觉、期待和重音如何发展，不强制补功能演示。

“只保留关键静帧，是否损失表达？”是辅助问题。即使信息没有减少，节奏、情绪和视觉音乐性也可能是作品的主要价值；不能据此否定文字片或品牌片。

## 症状到修正

| 可见症状 | 区分检查 | 可尝试的修正 |
| --- | --- | --- |
| 所有镜头像同一页换文案 | 看布局、主动作和时间结构是否都重复 | 按内容重新选择景别、表达单位或编辑方式；系列化重复有意图则保留 |
| 动画很多但看不懂 | 正常速度指出观众应看的对象与信息 | 减少竞争动作、保留稳定锚点，或让并列比较更清楚 |
| “很慢” | 分开计时：移动、阅读、无信息等待 | 缩短无效等待或移动，保留理解时间；不要全片倍速 |
| 转场有突跳 | 检查接点两侧的实际状态与选定交接机制 | 连续对象对齐几何；运动匹配再查速度；有意跳切则查表达是否清楚 |
| 像廉价模板 | 检查是否无理由套用弹跳、漂浮、统一滑入 | 按对象与品牌重写动作逻辑；不是简单换一组预设 |
| 看起来热闹但没有产品证据 | 分开看概念动画和真实功能 | 补真实演示或收窄文案主张，不用特效掩盖事实缺口 |

## 声画对应复核

先按 [声音叙事](sound-narrative.md) 判断声音的表达职责：是否建立段落关系、支持重要变化、给理解留空间；还是从头到尾铺同一层音乐，再给所有动作相同提示。重复和持续本身不是问题，判断其是否适合本片。比较时注意响度偏差；有声、静音或分轨检查按疑问选择。

有配乐／音效时，检查脚本中承担职责的声音锚点：音轨真实事件、最终成片时间、视觉事件的感知重点是否对应；有意错拍按意图判断。重点听看附近完整短句，不只截碰巧重合的一帧。

若没有锚点且关键转折与配乐互不相干，先判断音乐是有意提供持续氛围，还是遗漏了节奏设计。用户明确要求卡点时，应展示具体对应证据；音轨一致、BPM 已知、正常播放均不能替代。不要为改善卡点牺牲文案阅读或伪造音乐重音，也不要把动作起点全部量化到同一拍。

## 防止脚本趋同的专项检查

比较本片内部，以及用户已有系列或参考（若可用）：

- 去掉产品名后，动作是否仍是可无差别套给任何产品的同一套流程？如果是，这是否符合用户的系列模板需求？
- 镜头数、顺序、持续时间、动作起承转合是否由内容决定？哪些只是照抄示例？
- 是否为了填 `trigger` 发明一次点击，为填 `handoff` 强塞一个承接物，为填能量曲线虚构高潮？删除无意义字段与动作。
- 不同类型任务是否被迫都采用“混乱—聚合—展开界面”？这种结构不是本 Skill 的默认叙事。
- 若刻意统一品牌语言，是否仍根据内容安排不同的运动职责？一致性本身不是失败。
- 若改变了原来有效的动作，仅仅是为了“与上一条不同”，撤回无收益的变化。

不存在必须达到的变化数量、运动覆盖率、转场种类数或镜头长度分布。

## 问题记录与修复循环

只记录可行动的问题；每条使用以下信息，格式自由：

```text
位置／版本：
观测：画面或声音中实际发生的事。
影响：为何损害本次表达、观看或交付。
原因候选：与观测分开；必要时写最小区分检查。
修改：具体改哪个对象、事件、镜头或时间关系。
验证：复看什么区间，观察什么；状态为通过／仍有问题／未验证。
```

优先处理：事实和关键理解问题、无法播放等交付阻断；其次主要编排和节奏问题；最后非必要润色。修复可能同时涉及代码与脚本，不默认追加提示词即可解决。

每轮先处理影响最大的少量问题，验证后再决定是否继续。同一问题反复出现且没有新依据时，不反复改参数；回查假设或工具限制，并说明具体缺口。达到需求、必要检查通过后停止。

## Skill 自身的行为验证

修改本 Skill 时，可用这些差异明显的请求做方案级检查。它们用于发现模板偏置，不能代替成片评测：

- 无旁白的克制品牌片，允许长镜头与静止。
- 准确展示真实软件操作，界面文字必须可读。
- 纯文字、声音驱动的短片，不使用 UI 或容器。
- 固定坐标轴的数据解释，精确数值优先。
- 只调整已有视频的一个接点，不能重做其余内容。

检查是否遵守各自目标、选择性填写字段、保留不同表达方式且不扩张范围。验证实际效果时，使用相同资料与环境比较旧／新流程，保留生成波动、失败与成本记录；单次模型自评不能证明稳定提升。

## 强 Motion 目标的参考对照

对照动态表现参考检查：内容自身的发展、关键动作的时间形态、注意力交接、段落对比与视觉完成度。参考有卡片/硬切并不自动劣质；本片没有卡片/使用无缝也不自动合格。按任务与规格评判，记录改进与退步，不以作者“一次生成”声明推断可复现流程。

跨镜头问题用包含前后有效状态的窗口核对。覆盖意图中的提前清空属于可定位偏差；有意空拍按表达判断。质量声明需区分实际帧观察、正常速度动态观看、音频时序核对与审听；未具备的感知能力明确留空。
