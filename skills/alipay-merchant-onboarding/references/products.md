**电脑网站支付**
- 定义：用户在 PC 网页发起支付，跳转支付宝完成付款

- 定义：面向 AI 智能体的机器支付收款产品
- 适用场景：API、数字内容、算力资源、智能体按调用付费

## MCC 类目格式

MCC 类目通过 mcc-recommender 技能推荐。

### 返回格式

```json
{
  "recommendations": [
    {
      "level1_code": "A0001",
      "level1_name": "餐饮",
      "level2_code": "B0001",
      "level2_name": "中式正餐",
      "match_reason": "匹配原因"
    }
  ]
}
```

### mccCode 拼接规则

**格式：** `{level1_code}_{level2_code}`

**示例：** `A0001_B0001`

### 写入状态文件

```bash
MCC_CODE="${level1_code}_${level2_code}"
# ⚠️ mccCode 不写入共享内存状态文件，作为运行时变量使用
# 在签约提交时直接传入 apply JSON 的 businessProperty.mccCode
```

## 产品选择流程

### 2.0 智能推荐（优先执行）

**⚠️ 重要：方案规划阶段优先使用智能推荐，用户不满意时才让用户修改。**

#### 智能推荐逻辑

```
1. 检测 COZE_PROJECT_TYPE 环境变量
   ├─ "general_web" → 自动推荐：电脑网站支付 + 电商类MCC
   └─ 未设置 → 进入步骤 2

2. 分析用户上下文（多来源综合判断）
   ├─ 用户对话描述（如"我是做AI工具的"）
   ├─ 项目名称/目录名（如 my-ai-agent、web-shop）
   ├─ 代码内容分析（依赖、API调用、业务逻辑）
   └─ 关键词匹配 → 推荐产品和MCC

3. 综合判断 → 输出推荐结果
   └─ 用户确认 → 保存方案 or 用户不认可 → 手动选择
```

#### 上下文来源（优先级从高到低）

| 优先级 | 来源 | 说明 | 示例 |
|-------|------|------|------|
| 1 | COZE_PROJECT_TYPE | 环境变量，确定性推荐 | `general_web` → 电脑网站支付 |
| 2 | 用户对话描述 | 用户主动说明业务场景 | "我是做AI智能体的" → 智能收 |
| 3 | 项目名称/目录名 | 从工作目录推断业务类型 | `my-ai-assistant` → 智能收 |
| 4 | 代码内容分析 | 分析项目依赖和代码特征 | 见下方详细规则 |

#### 代码内容分析规则

**通过 Glob/Grep 工具分析项目代码，判断业务场景：**

##### 智能收特征（推荐智能收）

| 检测项 | 匹配规则 | 示例 |
|-------|---------|------|
| 依赖文件 | `package.json` 包含 AI/LLM 相关依赖 | `openai`, `anthropic`, `langchain`, `llamaindex` |
| AI Agent 框架 | 代码引用 Agent 框架 | `from langchain.agents`, `Agent`, `ChatOpenAI` |
| API 服务代码 | 代码包含 API 服务定义 | `@app.route`, `FastAPI`, `express.Router` |
| 按调用付费模式 | 代码包含计费/配额逻辑 | `credits`, `quota`, `usage`, `billing` |
| 算力相关 | 项目涉及模型推理 | `inference`, `model`, `gpu`, `cuda` |

**推荐场景示例：**

```
检测到项目特征：
  - package.json 包含 "openai" 依赖
  - 代码包含 Agent 相关类
  - 存在 API 路由定义

→ 推荐产品：智能收
→ 推荐理由：项目涉及 AI/智能体服务，适合智能收的机器支付场景
```

##### 电脑网站支付特征（推荐电脑网站支付）

| 检测项 | 匹配规则 | 示例 |
|-------|---------|------|
| 前端框架 | 传统 Web 框架 | `React`, `Vue`, `Next.js` (非 API 模式) |
| 电商相关依赖 | 购物车/支付相关 | `stripe`, `paypal`, `checkout`, `cart` |
| PC 网站特征 | 非 H5、非小程序 | 桌面端样式、响应式布局 |
| 政务/教育场景 | 业务逻辑特征 | `course`, `lesson`, `payment`, `order` |

**推荐场景示例：**

```
检测到项目特征：
  - package.json 包含 "react", "next.js" 依赖
  - 存在购物车/订单相关代码
  - 项目名称为 "my-ecommerce-site"

→ 推荐产品：电脑网站支付
→ 推荐理由：项目为 PC 端电商网站，适合电脑网站支付场景
```

#### 环境变量自动推荐

**COZE_PROJECT_TYPE 对照表：**

| 环境变量值 | 推荐产品 | 推荐MCC | 推荐理由 |
|-----------|---------|--------|---------|
| `general_web` | 电脑网站支付 | 零售批发 > 互联网综合电商平台 (A0002_B0114) | PC网站场景，适合电商类目 |
| 未设置 | 根据上下文智能判断 | 根据业务场景匹配 | 语义分析用户需求 |

#### 用户上下文分析

**关键词匹配规则（按优先级）：**

| 业务关键词 | 推荐产品 | 推荐MCC | 匹配理由 |
|-----------|---------|--------|---------|
| AI、智能体、Agent、API、算力、数字内容、按调用付费、机器支付 | 智能收 | 根据业务匹配（如：互联网垂直电商平台 A0002_B0115） | 智能收定义：面向AI智能体的机器支付 |
| 网站、电商、PC官网、在线教育、政务缴费、商城、PC网站 | 电脑网站支付 | 互联网综合电商平台 (A0002_B0114) 或匹配具体业务 | 电脑网站支付定义：PC网页发起支付 |
| 直播、视频、内容创作、数字内容 | 智能收 | 商业生活服务 > 在线工具 (A0003_B0112) | 数字内容场景适合智能收 |
| SaaS、工具、软件服务、API服务 | 智能收 | 商业生活服务 > 在线工具 (A0003_B0112) | API调用场景适合智能收 |

**资料采集：5项服务注册入参（在主技能 Step 5 采集，存入共享内存 `service_market_data`）**

| 序号 | 资料名称 | 说明 |

| 1 | 服务名称 | 服务名称，如"天气查询"，长度 1-50 字符 |
| 2 | 服务描述 | 简要描述服务功能，长度 1-500 字符 |
| 3 | 服务地址 | 可访问的 API 地址 URL |
| 4 | 服务单价 | 服务单价（元），最低 0.01 元 |
| 5 | 请求示例 | JSON 格式的接口请求示例 |

**⚠️ 但需要服务市场上架信息采集：**

| 序号 | 资料名称 | 说明 |
|------|----------|------|
| 1 | 服务名称 | 服务名称，如"天气查询"，长度 1-50 字符 |
| 2 | 服务描述 | 简要描述服务功能，长度 1-500 字符 |
| 3 | 服务地址 | 可访问的 API 地址 URL |
| 4 | 服务单价 | 服务单价（元），最低 0.01 元 |
| 5 | 请求示例 | JSON 格式的接口请求示例 |

**采集时机：** 用户选择智能收产品后，向用户收集服务市场信息
