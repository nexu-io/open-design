# 01 · 拆解：拿到一段动画，一小时内拆到能写成代码

目标不是写观后感，是产出**能直接照着编程的规格**：每段的起止帧、转场机制和参数、镜内动作清单、计数器/字幕的数值曲线、构图坐标、音轨的网格与配器。文字是索引，数字和接触表才是正文。

第一次实战：2026-10-04 拆 X 上的 15 秒「Art History Speedrun」（16 个艺术时代、15 个转场），全流程约 1.5 小时（分镜 agent 79 分钟、音轨 agent 22 分钟，并行）。

## 一、先摸物理参数（5 分钟）

```sh
ffprobe -v error -show_entries format=duration:stream=codec_type,width,height,r_frame_rate,sample_rate -of default=nw=1 src.mp4
```
X 的视频从 syndication 接口拿最高档（`video_info.variants` 里挑最高码率），不要录屏。原片 60fps 就按 60fps 拆，帧号是之后所有规格的公共语言（秒 = 帧/60）。

## 二、全貌三张图（10 分钟）

1. **接触表**：4fps × 480 宽，30 帧一张，标时间戳。看一眼知道有几段、每段是什么。
2. **关键帧总览**：每段挑一张最干净的整帧拼成 4×5。后面所有工作的地图。
3. **频谱图**：`ffmpeg -lavfi showspectrumpic=s=1600x400:legend=1`。一眼看出音乐是否按段换配器、有没有坠落滑音、碎裂瞬态、拍点。谐波干净、16kHz 一刀切 = 代码合成＋AAC。

## 三、量出转场与节奏（15 分钟）

**逐帧灰度差**：缩到 192×108 灰度，相邻帧平均绝对差。静止段 <2，转场段 10–37。阈值 5 ＋ 去抖 12 帧，一次找全转场起点。存成 `diff.npy` 给所有 agent 共用。

找到起点后**拟合网格**：起点间隔如果是常数的整数倍，就有 BPM 网格（本片：起点 = 84 + 14.06·n 帧，残差 < 0.45 帧，= 128 BPM 八分音符）。网格一旦确认，画面和音乐的所有时间都写成「第几个八分音符」。

**每个转场一张 60fps 接触表**：从起点前 2 帧开始，每 2 帧取一张，取 0.5 秒，15 格。机制只能从这里看出来——「8 条竖条依次落下回弹」「20px 方块绕竖轴翻转、从猫的位置向外扩散」这种描述，粗看 4fps 图只会写成「方块转场」。

**参考帧取「转场开始前最后一帧」**，不是你觉得好看的那一帧。取早了会把上一段转场的余波（碎石块）当成画面内容（埃及第一版踩到）。

## 四、镜内运动：每段里到底什么在动（15 分钟）

运动热图：每段静止区间内逐像素取最大帧差，红色叠在灰度底图上，标出「运动面积占比」。

本片的结论推翻了第一印象：以为「每段就是一张画」，实际每段都有 2.5%–34% 的面积在动——岩画动物两张姿态交替奔跑、圣甲虫推太阳球、回纹带滚动、维苏威冒烟、金箔高光扫过、扑翼机飞过、四宫格换色……**没做这一步就开工，做出来就是「图片之间的转场」，会丢掉场景内部的连续运动。**

热图告诉你「哪里动」，再到 60fps 帧里看「怎么动」（周期、幅度、是两帧交替还是连续）。

## 五、分工给 agent 时的写法

- 分镜 agent 和音轨 agent 并行，各给一份完整说明：素材路径、已知事实（帧率、时长、粗看的段落表）、要的产物（分镜表.md / spec.json / 接触表目录 / 音轨拆解.md / 合成脚本）、方法要求（用数据证实，不凭想象）、回复格式（摘要＋最不确定的 3 处）。
- 让它们**先修正你的清单**。本片我把「1993→2026 的光圈转场」认成了一个「孟菲斯时代」，分镜 agent 第一条就纠正了。
- 全模态模型「听」音轨只当候选：乐器判断可信，BPM（报 120，实为 128）、动机音数、「每段一记嗖声」都是错的，必须用起音检测回校。

## 六、产物清单（拆完应该有）

| 产物 | 用途 |
|---|---|
| `分镜表.md` + `spec.json` | 每段起止帧、转场机制参数、镜内动作、计数器曲线、构图坐标 |
| `转场/T*.jpg`（60fps 接触表） | 写转场代码时逐帧对照 |
| `镜内运动/运动热图.jpg` | 每段动什么、动多大 |
| `结尾动作/`（如有角色表演） | 逐帧质心、轨迹、物理参数（重力 px/帧²） |
| `音轨拆解.md` + `synth.py`（模板：`scripts/audio/synth_艺术史速通.py`） | BPM 网格、每段八分音符数、动机、配器、音效序列 |
| `关键帧总览.jpg` + `生图/ref/*.png` | 构图地图、每段参考帧 |

脚本：`scripts/analyze/`（接触表、灰度差、转场接触表、运动热图），命令见各脚本 docstring。

# 02 · 机制：「艺术史速通」为什么好看

这一页是「速通/穿越」类片子的机制：同一个场景，换一路风格或年代（艺术史速通、一座城市的 100 年、一个人从十八岁到八十岁）。这类题材都能照这五层搭；解说片、故事片、单一风格的短片不照它搭，构图按题材设计。

## 五层机制

**1. 一个固定的场景骨架。** 16 个时代，窗、桌、猫、人、年份牌的位置几乎不动（±40px）。观众的眼睛有锚点，才看得清「变的是风格」。也因为位置固定，转场可以用画内物体当原点（马赛克从猫的位置扩散、光圈从杯子展开）。
→ 做法（速通/穿越类专用）：先定这支片子的构图坐标，所有时代对齐到它。代码里是一份常量，不是每段各画各的。别的题材不沿用这间屋的坐标。

**2. 每个时代是一幅活的画。** 停留 0.25–1.4 秒，但画里一直在动：主角一个连续动作（端杯喝茶）＋ 2–4 个**取自那个时代自己视觉母题**的小循环——岩画动物用「两张姿态交替」跑（这就是岩画多腿表示奔跑的动画化）、埃及圣甲虫推太阳、希腊回纹带滚动、罗马火山冒烟、哥特金箔高光、文艺复兴扑翼机、浮世绘巨浪、梵高星空旋转、包豪斯指针、波普四宫格换色。
→ 做法：每段列「这个时代最有辨识度的 3 个形式元素」，让它们动起来。动作要在停留窗口里看得出来（短段节奏要快）。

**3. 转场 = 下一个时代的签名语言。** 进埃及是石块/挂毯落下、进希腊是陶瓶滚筒转面、进罗马是马赛克砖翻面、进哥特是羊皮纸翻页、进文艺复兴是神光、进浮世绘是神奈川巨浪横扫、进印象派是笔触色点铺满、进梵高是星空漩涡、进新艺术是金边有机形生长、进立体主义是几何碎片、进包豪斯是红黄蓝几何旋转放大、进波普是闪电＋网点、进 8-bit 是像素化、进光追是绿色线框→逐行渲染、进 2026 是三色同心环光圈。
→ 做法：转场不从转场库里挑通用的，从「新风格最有辨识度的形式元素」里长出来。每个转场第一帧加镜头冲击（场景层放大到 1.03，约 20 帧回到 1.0，年份牌不缩放）——拍点上的那一下顿挫感来自它。

**4. 节拍网格加速。** 128 BPM 不变，每段占的八分音符数递减：6 → 4×5 → 3×4 → 2×3 → 1×3 → 结尾放长到 9＋。速度没变，听感和看感越来越急；最后一段放长给笑点留位置。转场时长跟着缩（0.4s → 0.13s），年份滚动也跟着缩（0.55s → 0.07s）。
→ 做法：先列每段想要的时长，四舍五入到八分音符，再整体微调成规律的递减。所有剪点、音乐起音、音效都落在网格上。

**5. 一个连续的叙事锚＋结尾角色梗。** 年份计数器是全片唯一连续的东西：数值只由全局时间决定，转场时新旧两层显示同一个滚动中的数字，各用各的字体（40,000 BC 的岩画手写 → 1350 BC 的芦苇笔 → … → 2026 的几何无衬线）。结尾给角色一个梗（猫三次拍杯把杯子推下桌，少女惊呼，签名写出），用预备、挤压拉伸、跟随、二次动作把它演足——前面 11 秒是「看」，这 4 秒是「笑」，笑点让人转发。

## 补充（2026-10-04 迁移测试 A–D）

- **主角动作跨段连续**：叙事锚不只是计数器，主角的动作也要按全片时间走；每段重做一遍动作，观众看到的是「举杯五次」而不是「同一瞬间换了五种画风」。
- **计数器用年份时段落必须按年代排**；不能重排就把角标换成序号或风格名（引擎角标可插拔）。转场中点硬切新旧角标，避免叠字。
- **第一段没有转场可借时，让画「自己画出来」**（笔触写出、套色一版版落、像素一行行点亮）。
- **签名转场越复杂，时长越长**：原片形状简单所以 0.4s 够；金箔、色带、飘带这类要 0.48–0.5s。

## 换题材时怎么用

| 层 | 本片 | 换成「一座城市的 100 年」可以是 |
|---|---|---|
| 骨架 | 窗/桌/猫/人 | 同一个街角：路灯、店招、行人、天际线 |
| 活的画 | 时代母题小循环 | 每个年代的交通工具驶过、招牌字体闪烁、天上的东西（风筝→飞机→无人机） |
| 转场 | 下一时代的签名语言 | 下一年代的媒介：胶片烧边、电视雪花、像素、扫描线 |
| 节拍 | 128 BPM 递减 | 同 |
| 锚＋梗 | 年份计数器＋猫拍杯 | 年份计数器＋同一只鸽子每个年代都在偷吃东西 |

## 不要学歪的地方

- 不要把「16 个时代」当配额。速通/穿越类的机制是「风格在变、骨架不变」，3 个时代也成立；它不是所有题材的机制。
- 不要逐像素复刻原片。复刻是学机制的手段，交付物是你理解后的版本（花叔选了金发少女＋橘白猫，就是在原片骨架上换角色）。

# 03 · 一帧先行，再让它动：四条路线

涉及生图或角色图片时，先按[图片能力指南](images.md)选择当前可用工具或导入现有素材；私人角色素材和平台选择不作为所有用户的默认。

花叔要的方法：先设计一帧有艺术感的画面，再按要求让这帧动起来。2026-10-04 一个项目里四条路都实跑过，各有适用场景。

| 路线 | 画面谁画 | 动作谁做 | 实测 | 什么时候选 |
|---|---|---|---|---|
| **A 纯代码** | Canvas 程序化绘制＋风格渲染器 | 代码（编舞曲线、IK、粒子、沸腾线） | 艺术史复刻主线（花叔选定） | 要证明「模型直接用代码产出艺术动画」；要精确控制每个元素的运动；要换几十种风格（换渲染器就换风格）；要和口播逐帧对齐 |
| **B AI 分层素材＋代码动** | 生图模型按图层画（绿幕、保留原画面坐标） | 代码（位移、弧线、挤压、物理、特效） | 2026 结尾段 11 张素材一次合成到位 | 画质要最高、角色要复杂表演；画风是写实/插画、代码画不出来时 |
| **C 视频模型首尾帧** | 生图模型画一帧 | Seedance 首尾帧（首尾同一张） | Lovart Seedance 2.0 梵高试片：少女放杯再端起、星空转、猫甩尾，构图全程守住 | 要「整幅画都在流动」的有机感，又不要精确控制；示例/氛围镜头 |
| **D 混合** | 背景用 B/C，角色用 A，或反过来 | 代码统一编排时间轴 | — | 大片：背景要质感、角色要可控 |

## 共同的第一步：一帧设定稿

不管走哪条路，先有一帧「对的画面」：
- **有参考片**：把参考片该段「转场开始前最后一帧」当参考图喂给 gpt-image，prompt 写「完全保持参考图的构图、镜头、每件物品的位置和大小、配色和笔触，只改两处：……」。实测与原片 50% 叠加几乎逐像素重合，构图锁定靠参考图，不靠文字写坐标。
- **没有参考片**：先按题材设计构图（主体是什么、在画面哪里、镜头往哪走），出白模截图当参考图。只有速通/穿越类片子才先定一份固定的场景骨架（标准构图坐标），所有段对齐到它。
- **三方向硬门**：角色诠释（本片：时代女装 / 同一人穿越 / 原装换头）在同一帧上出三张给人挑。选原片是男性角色的那一帧，差别最拉得开。

设定稿的坑（都踩过）：
- 写未成年角色（17 岁）＋任何「短裙」字样会被审核判 sexual 整张拒绝。服装一律写长款，加「服装端庄」。
- 毛色写到部位：「橘白猫（头顶、背部和尾巴橘色虎斑，口鼻、胸口、肚子、四爪白色）」。只写「橘猫」会画成全身橘。
- 描述里写动作（「端杯喝茶」）会压过参考图的姿势。要保持原姿势就只写「保持参考图里的手势」。
- 要动的文字（年份、标题）让模型「去掉，留成干净背景」，交给代码画；画内装饰文字逐字写进 prompt。
- 批量生图串行跑；生成来源以实际工具调用记录、输入/输出关联和人工视觉核对为依据；PNG元数据不能证明是哪一个模型生成。素材接入见[图片能力指南](images.md)。

## 路线 B 的关键：绿幕素材保留原画面坐标

用设定帧当参考图，prompt：「只画参考图里的 XX……其余全部是纯平涂 #00FF00，没有阴影地面文字。位置、大小、朝向与参考图完全一致。」生成出来的角色已经站在原画面坐标上。抠图时**不要裁到主体边框就丢坐标**——`scripts/key_green.py` 裁边同时把左上角写进 sprites.json，合成时按原坐标贴回，一次对齐。

## 路线 C 的关键：首尾同帧

Seedance 2.5/2.0 支持 frames2video。首帧和尾帧给同一张设定稿 → 画里的东西动起来又回到原构图，片段首尾能无缝接转场。prompt 结构：①镜头完全固定（不推拉摇变焦晃）②全程保持构图/画风/配色，不写实化、不增删物体、不出新文字 ③逐条列「画里什么动、怎么动」（来自拆解的运动清单）。生成 5 秒取最好的 1 秒左右、按节奏变速。
通道：任何支持首尾帧（frames2video）的 Seedance 接入都行，要点在 prompt 本身；视频生成按次计费，先用短时长试一条。

## 路线 A 的关键

见 `04-纯代码绘制.md`。一句话（速通/穿越类）：同一场景骨架 × 共享编舞 × 每个风格一个渲染器 × 角色单独一层后画 × 最后补线。其它题材把前两项换成按题材设计的构图和动作。

# 04 · 纯代码绘制：用 Canvas 把一幅有艺术感的画画出来并让它活

本页以纯代码绘制为主线：场景和物件通过程序与风格渲染器实现；人、拟人角色和机器人不用代码画进成片，生成帧方案见10号，交付线见`角色精细度.md`。本页是第一次做完 16 种风格后的方法总结；每种风格的具体参数在 `风格配方/<id>.md`。

## 一、工程骨架（`scripts/engine/`，复制一份就能开新片）

```
index.html      加载顺序：lib/fonts → lib/util → lib/paint → lib/rig → eras → transitions → scenes/index → engine
eras.js         段落表：id、占几个八分音符(eighths)、转场{type,dur,delay,cx,cy}、年份牌样式
scenes/<id>.js  每段一个文件：SCENES['<id>'] = { draw(c, lt, t) }   ← 主要工作量在这里
transitions.js  转场库：(c, A旧, B新, p, o) → 画一帧
engine.js       节拍网格→各段 t0/t1；转场时新旧两段各画进离屏再交给转场；拍点镜头冲击；年份计数器（值只由全局 t 决定）
lib/paint.js    噪声、纹理、手绘沸腾线、风格渲染器、区域色板 swatch、共享编舞 choreo、热气、粒子
lib/rig.js      角色骨架：RIG.girl / RIG.cat → 各部位 Path2D ＋ 锚点；drawGirl/drawCat（mode: fill/line）；ik2、smooth、taper
render.py       无头 Chromium 逐帧调 renderFrame(t) → PNG 管道 → ffmpeg 60fps，可混音轨；--solo <id> 单段预览、--stills 出静帧
compare.py      原片｜复刻 同时刻并排拼图
```

渲染速度：15 秒 60fps 整片约 90 秒（M 系列 Mac）。单段每帧大多 5–40ms，最重的梵高 110ms。

## 二、一个风格怎么画（五层，标杆 `scenes/09_postimp.js`）

> 五层是油画/版画类的默认顺序，不是万能的：**水墨**倒过来（纸是底，墨只往上加，大面积留白，不先铺满）；**图案类**（草间、包豪斯）是「平涂上撒图案」，图案本身就是渲染器；**明暗法**是「先画亮版再乘光照图」。

1. **平涂底稿**：大面积（墙、地、天、窗外）先用纯色/渐变画对位置和明暗。这一层决定构图，风格还没出来。
2. **风格渲染器重画**：用底稿当取色源，按该风格的笔法整幅重画——梵高流场长笔触、印象派短点、马赛克石块、浮世绘套色错位＋纹样、立体主义切面、波普网点、8-bit 低分辨率逐像素、光追逐像素反射……渲染器决定「这是谁的画」。
3. **小物件单独一层**：桌椅、花瓶、画框这类小东西如果混在大面积里一起过渲染器，会被打碎成一团。单独画、单独用更细的参数，`source-atop` 只画在自身上。
4. **角色**：速通/穿越类片子用同一副骨架（RIG）、同一套编舞，换画法（其余题材按题材设计角色）——平涂后叠该风格的细肌理，最后补清晰的轮廓和五官。角色是观众视线的落点，必须读得出是谁。
5. **会动的高光**：时代母题的小循环（见 02 号）。连续运动用连续时间；手绘线条用 8–12fps 换种子「沸腾」，给手工感。

## 四、角色：同一副骨架，十几种画法

- 骨架坐标别拍脑袋写：拿一张 AI 设定稿（或任何参考图）叠 20px 网格，逐部位读关键点，Catmull-Rom 平滑成 Path2D（`RIG.smooth`）。第一版手写坐标的少女像男孩，量点之后一轮就读得出 17 岁金发少女。
- 坐姿把腿藏进长裙最自然；端杯用两骨 IK（上臂 165 / 前臂 122），肘向固定朝下。
- 锚点 `G.A`（头顶、额、颈、胸、腰、膝、手…）给各风格加服饰：埃及宽领、哥特光环、浮世绘岛田髻、包豪斯关节盘、波普大波浪。
- 各风格可以对骨架做程式化变形（埃及侧脸正面眼、黑绘剪影、立体主义半边蓝脸、像素化），但站位、动作节奏要和骨架一致——这是「同一对角色在穿越」的来源。
- 结尾表演这种大幅度动作（跳、趴、伸爪、惊呼）不必硬塞进通用骨架：16_2026 自建姿势库（每个姿势一组局部关键点，逐数值插值），挤压拉伸以脚底为轴，压到最扁那一帧翻面。

## 五、让画「活」：动作清单与量法

- 每段至少：主角一个连续动作（choreo.cup 端杯）＋ 2–4 个母题小循环。短段（<0.5s）节奏要快到 15–30fps 步进。
- 自检运动量：渲两帧（**避开转场后 0.35s 的镜头冲击**，否则全屏都算在动）做帧差。第一次做下来的数（缩放结束后 0.45↔0.9s）：洞穴 2.8%、埃及 3.4%、罗马 6.4%、希腊 9.9%；原片同段热图 6.9%、6.2%、17.3%、11.6%。偏静就加母题动作。
- 动的东西要在视线焦点上（速通示范里是人、猫、窗；新题材按你的构图定焦点）。

## 六、踩过的坑

- **合成模式**：逐个纹样 `source-in` 会互相清空（克里姆特金袍整件消失）——先把纹样画满一张 scratch，再按剪影 source-in 一次；在段画布上 `destination-out` 会挖出透明洞，进视频是黑的——在离屏里挖好再贴；往角色上叠纸纹/颗粒不能用 `source-atop`（纸色盖上去人物发白）——纹理层 `destination-in` 剪影后 `multiply` 叠回。
- 自画字形：同一条 path 里两条反向绕行的笔画按 nonzero 规则会抵消出洞，每个部件单独 fill。
- 「融化」类转场：让新画面带圆头液滴从上往下流（剖面 `(1-u²)^0.3`），旧画往下拖出来的是尖刺，不像液滴。
- 转场时长按「看得见的部分」定：inOut 缓动两头几乎看不出变化，复杂的签名转场 0.34s 只读得到 0.2s，会被读成普通擦除，给到 0.48–0.5s。
- 皮影/剪纸这类半透明叠片，重叠处相乘会发黑，叠片顺序和透明度要按材料调。

- `putImageData` 直接写到目标 canvas 会绕过引擎的镜头冲击缩放和转场裁剪——先写进离屏再 `drawImage`。
- 读像素的离屏 context 用 `{willReadFrequently:true}`；每帧用 `g.reset()`，不然上一帧的 lineJoin/状态会残留，第一帧和之后不一致。
- `drawGirl(mode:'line')` 叠在最上层会把被遮住的部件轮廓画穿（远侧袖子穿过躯干、帽檐后半圈穿过头发）。用 `RIG.visibleLines(key, (g, lineColor) => 完整画一遍, 真线色, box)`：同一画法画两遍、线色换成白色当哨兵，两遍不同的像素就是没被遮住的线（含五官线）。按「填色→风格肌理→visibleLines 补线」走。
- **镜头冲击要作用在新旧两层**：只冲新层时，转场刚开始新层还没露出来，拍点那一帧画面不动，听感上「声音先到画面后到」（v1 审片量到拖拍 0.1–0.17s）。
- **整屏笔触按 8fps 换种子 = 闪，不是活**：审片量到整屏跳变帧差 18–20，比转场还大。笔触位置固定，让方向场随时间连续变化（火苗般摇曳），沸腾只留给线稿。
- 动态区不要单独换参数（石块尺寸、笔触密度）——静止时就是一块补丁。
- 马赛克/像素这类粗颗粒风格里，字要用等宽粗笔画（每笔 ≥2 个颗粒宽），细字体会断。
- 小东西做得比你觉得的大：浮世绘浪爪 22–50px 读不出来，44–74px 才是「神奈川冲浪里」。
- 确定性：所有随机用种子；同一个 t 渲两次必须逐像素一致，否则渲染时会闪。

## 七、分工（多 agent 并行画）

先写好 `时代作者规范.md`（接口、可用库、标杆、硬要求、参考文件、自检命令、交付 notes），再按 4 个时代一组派 agent。规范里写清「不改 lib/ 和别人的文件」。每组 30–35 分钟交回，notes 直接沉淀成 `风格配方/`。第一次 16 段全部一次通过，主要靠规范＋标杆实现。

# 05 · 节奏与配乐

拆解方法与可复用规律：`风格配方/_音轨_艺术史速通.md`（第 5 节「可复用规律」可以直接照抄）；合成脚本模板（原创示例乐谱）：`scripts/audio/synth_艺术史速通.py`。

## 要点

1. **先定 BPM 网格，画面和音乐都落在网格上。** 128 BPM、八分音符 0.234s 适合速通/蒙太奇。`eras.js` 的 `eighths` 就是每段占几个八分。
2. **加速靠每段变短，不靠提速。** 6 → 4×5 → 3×4 → 2×3 → 1×3 → 结尾放长。
3. **一个三音动机，每段换该风格的代表乐器、随和弦移调。** 和声一个四和弦循环就够。
4. **段间硬起音，不交叉淡化，不加嗖声。**
5. **结尾音效：停—悬—砸—反应—收**（叮 → 滑哨坠落 → 碎裂 → 猫叫 → 低音拨弦），时间点对齐画面事件帧。
6. **响度**：对齐参考片的积分 LUFS 与真峰；逐段比相对差值。
7. 全模态模型听音只当候选：乐器可信，BPM、动机音数、音效时间都要用起音检测回校。

## 和画面的对位

- 转场起点 = 网格点；镜头冲击（场景层 1.03 → 1.0，20 帧）落在同一点，听感上的「咔」和视觉上的顿挫是同一下。
- 结尾表演的动作帧（拍杯 3、杯子落地）对齐音频 onset，误差 3 帧以内。
- 没有参考片时：先写段落表（每段多少八分），再同时生成画面时间轴和配乐；之后改节奏只改 `eighths` 一处。

# 06 · 口播驱动的艺术短片（方法草案，待第一支实片验证）

目标：根据口播表达，使用选定的时代或艺术家画风，制作镜头与画面连贯的动画。最新整片方法见`12-口播整片与经验回流.md`。

> ⚠️ 本页是从艺术史速通的引擎推出来的方案，**还没在真实口播上跑过**。第一支做完把这行删掉，把实测写回来。

## 和速通片的区别

| | 速通片 | 口播短片 |
|---|---|---|
| 时间轴 | BPM 网格 | 口播词级时间戳（来自你的转录工具，如 Whisper 一类的词级时间戳） |
| 风格 | 每段换风格 | **一个风格贯穿**（一位艺术家/一个时代） |
| 镜头 | 固定机位 | 要有镜头语言：推拉、摇移、切景别、跟随 |
| 叙事 | 骨架不变、风格变 | 风格不变、内容随口播变 |

## 流程

1. **口播 → 镜头表**：按句切，每句定「这句话画面上是什么」（具象物/隐喻/人物动作/文字），标镜头类型（全景/近景/特写/推/摇）和时长（来自词级时间戳）。先给花叔看 5–10 行镜头表再动手。
2. **定风格＝定渲染器＋色板＋线条**：从 `风格配方/` 选最接近的一张卡做起点；没有的风格按 04 号第三节新写一个渲染器。先出一帧（三方向硬门：同一句口播的同一帧，三种风格诠释给花叔挑）。
3. **世界而不是画面**：口播片要切镜头，所以把场景建成一个比画面大的「世界画布」（如 5760×3240），各元素有世界坐标；镜头 = 视口（中心、缩放、旋转）。渲染器作用在视口画出来的那一帧上，笔触大小按屏幕像素定，推镜头时笔触不会变粗——这是「画在动」而不是「图片在放大」的关键。
4. **镜头间的流动**：
   - 同场景内：视口插值（推拉摇），配缓入缓出。
   - 换场景：用该风格自己的语言做转场（梵高就是笔触漩涡卷走、浮世绘就是浪、水墨就是晕开）——02 号第 3 层机制。
   - 匹配剪辑：上一镜的形状对下一镜的形状（杯口 → 月亮）。
5. **字与口播**：关键词可以用该风格的字体/笔法写进画里（马赛克字、书法、霓虹），不做通用字幕条；字幕交给剪辑工程另轨。
6. **音乐**：05 号的网格法照用，只是网格让位于口播节奏（句间留白处放转场与音乐重音）。
7. **验收**：和口播并排看，每句话画面是否在讲同一件事；每镜是否在动；风格是否一眼可辨。

## 与视频管线的分工

口播的转录、时间轴、混音、交付走你的视频管线；本 skill 只负责「艺术动画画面」这一轨，产出一条无声 MP4 或 ProRes，给剪辑工程当画面轨。

# 08 · 风格作者规范（通用版，给写 scene 的人和派出去的 agent）

> 替代早期绑死在复刻项目上的 `时代作者规范.md`。派 agent 画风格时，把本页路径给它，再加上「本项目」那一节的具体信息。

## 接口

一个风格段 = `scenes/<id>.js`：

```js
SCENES['<id>'] = { draw(c, lt, t) { /* 画满 1920×1080 */ }, init(IMG) { /* 可选：一次性预计算 */ } };
```

- `c` 目标 2D context；`lt` 本段局部时间（秒，从该段转场开始算）；`t` 全片时间。
- 段落表 `eras.js`：`{ id, eighths 或 dur, transition: { type, dur }, counter: {...} }`。片长由段落表自动算。
- 转场 `transitions.js`：`TRANSITIONS.<name> = (c, A旧, B新, p, o) => {}`。
- 场景缺文件、语法错、没注册 → 引擎拒绝启动，render/qa 直接报错。不要靠「看起来渲出来了」判断成功。

## 先读（按顺序）

1. `references/02-机制.md`（五层机制，速通/穿越类片子才用）、`04-纯代码绘制.md`（管线、渲染器速查、坑）、`07-正面经验.md`。
2. `references/风格配方/INDEX.md`：找最接近的风格当起点，读那张卡。
3. 标杆实现 `scripts/engine/scenes/09_postimp.js`；最接近风格的 scene 源码。
4. `lib/`：`paint.js`（噪声/纹理/渲染器/色板/编舞）、`rig.js`（角色骨架、visibleLines）、`kit.js` 等工具库。**先找库里有没有，再自己写。**

## 两种起点

**有参考片**：先跑 `scripts/analyze/breakdown.py` 拿到参考帧（`ref/segNN.png`）、运动热图、转场接触表，按 01 号拆。参考帧决定构图、母题、配色，热图决定「画里什么在动」。

**没有参考片**（更常见）：
1. 写下该风格最有辨识度的 3–5 个形式元素（材料、笔法、配色、母题、媒介痕迹）。查一手资料（原作图像、美术史描述），不凭印象。
2. 给每个元素配一个「能动的方式」——它在那幅画的世界里本来会怎么动（水会颤、纸会飘、金会闪、版会错位、胶片会抖）。
3. 想清楚这种画在现实里是怎么做出来的（刷、刻、印、贴、镶、喷、渲），把那个物理过程写成渲染器。
4. 先出一帧：静帧拼图对照原作看，一眼认得出再让它动。

## 硬要求

1. **构图**：速通/穿越类片子按本项目给定的构图坐标摆（各段一致，转场和「同一角色在穿越」都依赖它）。其余题材按题材构图：风格决定怎么构图、怎么用光，不沿用示范房间的坐标。
2. **角色**：速通/穿越类片子用 `RIG` 骨架与共享编舞，换画法不换站位动作；其余题材按题材设计角色和站位（人用 AI 生帧，见 10 号）。**角色也要过该风格的材料处理**（笔触、颗粒、纸纹 multiply、墨晕边、网点、色版错位……），否则像贴上去的剪贴画——这是 36 种风格里最普遍的短板。需要线稿时用 `drawGirl/drawCat` 的 `mode:'line'`（内部已走 visibleLines，不会画穿）。
3. **画要活**：主动作＋2–4 个母题小循环，在停留窗口里看得出。速通/穿越片里角色动作用全片时间（`PAINT.cupCycle(t)` 这类），换段不重置。
4. **流畅**：不要整屏按低帧率换种子重洗（会读成闪）；沸腾只给线稿或母题区域。有意的「步进帧率」（橡皮管 12fps、皮影 10fps）用 `stepTime`，那是风格不是卡顿。滚动纹样的取模周期等于图案真实周期。
5. **确定性**：所有随机用种子；同一个 t 两次渲染逐像素一致。
6. **性能**：静态部分 `PAINT.cached`；读像素的离屏用 `willReadFrequently`、每帧 `g.reset()`；目标每帧 ≤150ms（qa 量的是带 GPU flush 的真实时间）。
7. **字**：风格里的字优先用路径画成该风格的材料；用字体时先 `U.assertGlyphs` 验证字形存在（缺字会静默回退系统字体）。
8. **做旧不上身**：剥落、污渍、划痕只在背景；角色区域设保护区（敦煌剥落斑落在背上读成「衣服破洞」）。

## 自检与交付

```sh
uv run --with playwright python <工程>/render.py --solo <id> --stills 0.4,0.6,0.8,1.0 --out <渲染>/<id>   # 静帧
uv run <skill>/scripts/qa.py --project <工程> --ids <id>                                                # 数字
```

每段至少 3 轮：静帧对照原作/参考拼图看 → qa 看运动/静止帧对/跳变/耗时/确定性 → 改。四问：①一眼认得出是哪个风格？②角色对、和背景融吗？③停留窗口里看得出画在动、而且不闪不卡？④有没有穿帮（遮挡、断线、错位、空白、叠字）？

交付：`scenes/<id>.js`＋配方卡（照 `风格配方/` 格式：管线、关键参数与色值、母题动画怎么做、签名转场、性能、坑、仍可改进），写具体、写数字。**多段的片子交付前派一个没参与制作的 agent 只看成片审片。**

## 三方向硬门在无人值守时

有花叔在场：新风格方向、角色诠释先在同一帧出三个给他挑。
没人可问（自动测试、夜间批量）：执行任务书写明的方向，同时在交付说明里列出「本可以给的另外两个方向」各一句，等他回来再挑。

# 10 · 角色：人用 AI 生帧，代码负责合成

涉及生图或角色图片时，先按[图片能力指南](images.md)选择当前可用工具或导入现有素材；私人角色素材和平台选择不作为所有用户的默认。

## 角色实现的选择

同一角色可用三种方式实现（A、B的并排图见`assets/角色/花叔形象_对比.jpg`；C的效果见Kurzgesagt与白板示范片）：
- **A 代码画**：只用于运动白模、预演和纯几何符号（方块、终端这类本来就是几何的东西）。人、拟人角色、机器人、长了脸的物不用代码画进成片，见`references/角色精细度.md`。
- **B 已定帧库直接贴**：容易保持角色一致，但需要协调帧库与场景的画风。
- **C 按该片画风生成动作帧再合成**：用参考图保持身份，绿幕抠图后交给代码控制动作与材质。

真人和拟人角色只用B或C，做完过`references/角色精细度.md`的交付线；没有生图能力就只出手和背影，或不出人。风格卡里保留了各类角色的已知短板。

## B：贴已定帧库

- 帧库：你自己已经定稿的角色帧（如挥手、拖拽等，每动作 8 帧透明 PNG；通用动作帧需自行准备；长卷示范附带的三段角色帧见`scripts/engine/demos/long_scroll/frames/`）。
- 引擎启动时作为图片资源加载；渲染按 `floor(t*9)%8` 换帧——有限动画，不做补间。
- 以脚底中心为锚点放置；`face=-1` 水平翻转。
- 给帧加所在片的材质（Vox 加白色剪纸边和投影；笔触类风格可在帧上再过一层细笔触 source-atop）。

## C：按画风生一版

1. **生图**：用 gpt-image 一类支持参考图的生图模型（prompt 写法可参考 [huashu-gpt-image](https://github.com/alchaincyf/huashu-gpt-image)），批量时串行跑。ref = 角色三视图设定稿或已定帧库的母版；prompt 写清：
   - 该画风的**造型语法**（不是只写「XX 风格」）：Kurzgesagt 纯色块不描边、同色相深一档做阴影；Vox 黑白网点剪报照片＋白色剪纸边；白板黑色马克笔线稿＋橙色排线；莫奈短笔触光斑……
   - **姿势与镜头调度对齐**（「侧身朝右伸手指向右边」）；要动就一张出多帧 sprite（4×2 八帧，帧数写在开头、「同一角色」锁一致性、只给关键姿势让模型补中间、「每帧站在单元格底部居中、大小一致」）。
   - 绿幕 `#00B140`（白帽白 T 不能用白底）。
   - 定规（以花叔形象为例）：**纯白**渔夫帽（模型爱画成浅灰，要写死）、圆框黑眼镜、白 T、卡其短裤、白洞洞鞋、左手腕黑手表、大头小身体。
2. **验真**：以实际工具调用记录、输入/输出关联和人工视觉核对为依据；PNG元数据不能证明是哪一个模型生成。素材接入见[图片能力指南](images.md)。
3. **抠图切帧**：`scripts/key_split.py`（去绿溢、按列切姿势；白板线稿用 `--white` 只裁不抠、贴进画面用 multiply）；需要保留原画面坐标时用 `scripts/key_green.py`。
4. **合成**：代码只决定位置、大小、朝向、换帧时机、材质；石子、涟漪、道具等互动物件仍用代码画并对齐到手的位置。

## 什么时候还用代码画

成片里：剪影、背影、手（照所在画风画到位），以及本来就是几何体的东西（方块、终端窗口）。机器人、Q 版小人、火柴人演故事、给物加脸，这几样停用，理由和替代做法见`references/角色精细度.md`。`lib/rig.js` 的少女/猫骨架与 `rig_huashu.js`、`lib/toon.js` 保留：用于运动参考（手在哪、脚在哪，给 AI 帧定锚点）、白模预演，以及艺术史速通这类风格示范里已经定稿的角色。

# 色板：一支片一套色

镜头表表前的「色板」一行，从这里挑一套写名字，或者按文末的规则自己定 3–6 个色值。所有参数化片段的 spec 写同一个 `"theme"`，scenes 里也只用这几个色（加减明暗、透明度可以，别引入新色相）。

## 先说禁区

**蓝紫渐变底、深紫星空底、霓虹青紫光效、紫色毛玻璃**：作者原话「我们需要规避下蓝、紫渐变的垃圾配色，这种非常ai slop」。这几样是 AI 做动画最常落进去的默认色，观众一眼就读成「AI 做的」。

`deliver.py` 会量出来：一帧里 30% 以上是蓝紫（色相 225°–300°、饱和度 ≥0.30）就算蓝紫帧，蓝紫帧占全片 30% 以上红灯，不出片。题材本身就要蓝紫时（用户点名的赛博朋克紫、梵高星月夜这类风格画面），交付时加 `--allow-blue-purple "理由"`，降为黄灯，理由写进交付说明的事实段。

海军蓝平涂（色相约 210°，见下面 navy）不在禁区里：它是有意图的单一底色，不是渐变也不发光。

## 八套现成色板

每套 6 个键：`bg` 底、`surface` 卡片／纸／面板、`ink` 主字、`sub` 次字和细线、`accent` 主强调、`accent2` 副强调。片段 spec 里写 `"theme": "wood"`，或者写成对象 `{"name": "wood", "accent": "#B8452A"}` 只改其中一个键。

| 名字 | 适合 | bg | surface | ink | sub | accent | accent2 |
|---|---|---|---|---|---|---|---|
| `paper` 纸本 | 人文、历史、读书、解释一个道理 | #F3EDE2 | #FBF8F2 | #1B1A17 | #6B655B | #C8402F | #2F5D62 |
| `poster` 海报黄 | 观点、冲突、要一句话砸进去的科普 | #FFD23F | #FFF6D6 | #111111 | #4A4433 | #FF5A36 | #14213D |
| `ink` 深墨 | 科技、夜景、严肃话题 | #121417 | #1E2226 | #F2EFE8 | #A39E93 | #F2B33D | #5FB3A1 |
| `navy` 海军 | 产品、数据、手机与电子设备（平涂，不渐变） | #0D1B2A | #16293D | #EEF3F6 | #8FA3B3 | #5CC8E0 | #F2A93B |
| `bauhaus` 包豪斯 | 设计、结构、几何、流程 | #EFE9DD | #FFFFFF | #111111 | #555555 | #D62828 | #1D4E89 |
| `snow` 雪原 | 冬天、医疗、清洁、实验室 | #E9EEF0 | #FFFFFF | #1F2A30 | #5E6B72 | #D9482B | #3E7C8C |
| `wood` 暖木 | 生活、厨房、手作、家里的事 | #EDE3D1 | #F7F1E6 | #2B2622 | #7A6E62 | #C4552D | #3F5B4B |
| `chalk` 黑板 | 课堂、推导、公式、讲题 | #23302B | #2E3D37 | #F1EFE6 | #A9B3AA | #F4D35E | #E87D5A |

## 自己定一套

- 3–6 个色：一个底，一个面，一个主字，一个次字，一两个强调。强调色一镜里只用来指一个东西。
- 底色先定：亮底（纸、雪、木）还是暗底（墨、海军、黑板），全片不在亮暗之间来回跳。
- 色值避开蓝紫区：色相 225°–300° 且饱和度 ≥0.30 的色不当底、不大面积用。`storyboard_lint` 查色板里的色值，落在这一区红灯。
- 不用渐变底，不加霓虹外发光。要层次就用纸纹、颗粒、明暗两层平涂。
- 有真实素材（截图、照片）时，从素材里取一两个色当强调，底色仍然用这一套。

## 自检

交付前把抽帧排成一排看：底色是不是从头到尾同一个亮度区间，强调色是不是只有那一两个，有没有哪一镜突然冒出白底柱状图、紫色星空、霓虹边框这种「别的片子的颜色」。有，就把那一镜按色板重画。

# 角色精细度：要么画到位，要么不出脸

画面里只要出现人、拟人角色、吉祥物、机器人，或者长了脸的东西，开工前读这一页。作者看过多个模型做的片子，原话是：

- 「很多视频里用到的小人和机器人角色都太差了，我们应该自己来定义一部分的精细度和用力的要求」
- 「颜色和人的风格形象都有些ai slop」「金币和小人形象的界面有些ai slop」

**粗糙的角色比没有角色更差。** 观众看见一个圆头豆豆眼的小人，第一反应是「AI 做的」，后面讲得再好也被这一眼拖下去。

## 先选路：三条路，只有三条

镜头表表前的「角色」一行，写的就是这里选了哪条：

| 角色行写 | 什么时候走 | 怎么做 |
|---|---|---|
| `帧库 <路径>` | 有生图能力（当前会话有生图工具，或用户给了角色图） | 按 `references/10-角色.md` 的 B／C 法做 AI 生帧帧库，过下面的「交付线」 |
| `只出手和背影` | 没有生图能力，但故事需要一个人 | 只画手（握着物、指着物、把物放进口袋）、背影、剪影、过肩；脸不出画 |
| `无` | 故事可以只靠物讲 | 物本身做主角：一块电池、一袋面包、一本书，靠形状、颜色、动作讲，不给它加脸 |

**停用的**（代码画出来就是 AI 味，lint 和评审都会拦）：

- 通用 Q 版小人：圆头、豆豆眼、腮红、没脖子、身体是一个圆角矩形。
- 白壳机器人：白色圆壳、蓝色面罩、一根天线，悬浮或喷火。
- 长了脸的东西：带笑脸的金币、会皱眉的锂离子、有眼睛的小球、表情包式的电池。
- 火柴人、哈林小人，用来演故事时（白板语法里画一个示意符号不算演故事）。

**例外：全片主角是一个拟物角色。** 一支会跳的画笔、一盏台灯，作为整支片的主角，按「三方向硬门」出过造型、用户挑定了，可以有脸和表情：作者做宣传片时，无脸画笔被判「太正式了太无聊了」，改成有脸的卡通画笔才过。区别在用力：主角是设计出来的（身份道具、身体结构、表演），过下面的交付线；停用的是顺手给金币、小球、离子画上的表情包脸。

`y4` 片段只接受帧库（`data.character.frames`），没有帧库启动就失败。引擎里代码画的角色（`lib/toon.js` 的 neutral／bun／author）不再给成片用。

## 交付线：帧库角色要过这八条

做出来先截一张角色特写（放大到 2 倍），对着下面逐条打勾，写进交付说明。过不了的，回到生图那一步重做，或改走「只出手和背影」。

1. **剪影认得出**：把角色涂成纯黑，还认得出是谁、在做什么动作。圆＋圆角矩形拼出来的人认不出。
2. **比例有骨架**：有脖子、肩膀、手肘、手腕；头身比按画风定，同一角色在全片里不变。
3. **手是手**：看得出手指或手套的形状，能真的握住物（物在手里，不是贴在手边）。
4. **至少两层明暗**：底色＋阴影，再加高光或边缘光；光的方向和场景一致。
5. **至少三处材质细节**：衣褶、缝线、发丝分组、布料纹理、鞋带、表带……挑这个角色身上该有的。
6. **表演是具体的**：每次出场有一个和这一镜内容对得上的表情＋姿势（皱眉看手机、松一口气把手机揣进兜里），不是只眨眼、只上下浮动。
7. **和画风同一套**：角色的线条、上色、色板和背景同一种画法，不是一张贴纸贴在别的画上。
8. **前后一致**：同一个角色每一镜的五官、发型、衣服、配色一致。

## 物不加脸：怎么让物「演」

把概念讲活不需要给它画脸。

- **用形状和动作**：锂离子在冷的时候挤成一团、走得慢；热起来散开、跑得快。电量条在冷风里一格一格缩下去。
- **用尺度**：一个东西从手心大小砸到铺满画面。
- **用对比**：同一个物左右两份，一份冻住、一份正常。
- **用真实的物**：真实的电池剖面、真实的冰霜纹理、真实的屏幕截图。

## 自检

交付前抽 6 帧有角色或物的画面并排看，问三个问题：

1. 有没有一眼像「AI 默认小人」或「白壳机器人」的东西？有，就换路。
2. 有没有给不该有脸的东西画了脸？有，就去掉脸，改用动作讲。
3. 角色和背景是不是同一种画法？不是，就按画风重做角色，或者让人只出手。

# 镜头表模板：先镜头表，再动手

轨道档的第 1 步。开阔档也建议先写一张，lint 可跑可不跑。

一张镜头表就是这支片子的分镜：先锁一套画风，再每行一镜，写清楚这一镜画面里**有什么物、它在做什么、镜头怎么动、屏上有几个字、用什么做**。写得出这张表，片子就不会变成一页越堆越长的 PPT，也不会变成每镜一种画风的拼贴；写不出某一行，说明那一镜还没想清楚，先别写代码。

## 怎么写

复制下面这段到 `<项目>/镜头表.md`，先填表前三行，再一行一镜往下填：

```markdown
画风：（一句话：一张风格卡或一种画法，全片只用这一种）
色板：（references/色板.md 里的名字，或 3–6 个 #色值）
角色：（无／只出手和背影／帧库 <路径>）

| 时间段 | 画面里的物 | 它在做什么 | 镜头 | 屏上字 | 做法 |
```

| 列 | 写什么 | 不要写 |
|---|---|---|
| 时间段 | `0–3`、`3–7.5` 或 `0:03–0:07`，前一镜的结束就是后一镜的开始 | |
| 画面里的物 | 名词，画面上能指着说「就是它」的东西：一片面包、一粒孢子、主角的手 | 标题、要点、文字、列表、标签、字幕、卡片、背景、画面、图标；空镜、纯色、黑场、渐变底（主角不在画里） |
| 它在做什么 | 动词，这个物自己的动作：飘进来、裂开、钻进去、被切掉 | 出现、显示、展示、淡入、逐条出现 |
| 镜头 | 这一镜的主动作，五选一：停／快推／横移／砸入／切 | 匀速慢推 |
| 屏上字 | 每镜 ≤8 字，可以空；口播原文交给字幕 | 整句口播、三行要点 |
| 做法 | 用什么做：哪个语法的参数化片段（写 spec 文件名）、`scenes/<id>.js` 代码画、真实素材满幅 | 每镜换一种语法 |
| 标签（可选列） | 这一镜贴在物旁边的小标签，用顿号隔开 | 一镜超过 3 个；一排发光胶囊 |

表前三行（画风锁）：

- **画风**：一句话写清全片用哪一种画法，例如「暖木色纸本插画，平涂加细铅笔线，厨房午后侧光」。换场景可以，换画风不行：卡通人、暗色代码屏、星空图标、白底柱状图、纸张、网页截图轮流出现，每一镜单看都不错，整片就是拼贴。
- **色板**：`references/色板.md` 里的一套，或 3–6 个色值。所有片段 spec 写同一个 `"theme"`，scenes 也只用这几个色。不用蓝紫渐变、深紫星空、霓虹青紫。用户点名要蓝紫（赛博朋克紫、梵高星月夜）才加一行「允许蓝紫：理由」。
- **角色**：画面里要出现人或拟人角色，先读 `references/角色精细度.md`。有生图能力就 AI 生帧，写「帧库 <路径>」；没有就写「只出手和背影」或「无」，用手、背影、剪影、物件讲故事。代码画的 Q 版小人、白壳机器人、长了脸的金币和小球已经停用。

五条要求，写完逐条对：

1. **开头 3 秒是一个具体的小场景，结尾也落在主角或主物的一个动作上**：开头是一个人或一个物在做一件和题目有关的事，不是标题，不是「今天我们来讲」；结尾是放进口袋、合上书、拉远看全貌这类动作，字可以写在画里的物上，不收在居中金句卡上。
2. **全片一个例子贯穿、一套画风到底**：同一片面包、同一双手、同一台机器从头走到尾，各镜讲的是它身上发生的事；每一镜都在画风锁那一行写的画风里。
3. **一镜 2–6 秒**：个别镜可以到 8 秒。
4. **文字主导的镜头 ≤30%**：物列是标题/字、屏上字 7 个以上、或用 y5 动态文字做的，都算文字主导。
5. **相邻两镜不用同一构图**：这一镜是满幅特写，下一镜就换成横移、换成另一个物、换个景别。换的是构图和镜头，不是画风。

做法列的两条硬线（轨道档第 3 步也写着）：**单个参数化片段最多撑 8 秒**（同一个 .json 在表里合计不超过 8 秒）；**一支片最多用 2 种片段语法**，所有 spec 写同一个 `theme`，其余镜头用 scenes 按同一套色板画，或真实素材满幅。

## 检查

```sh
uv run <skill>/scripts/storyboard_lint.py <项目>/镜头表.md --script <项目>/文稿.txt   # 有口播稿就带上 --script
```

逐镜给红黄绿和改法，有红灯非零退出。红灯就改镜头表、重跑，**红灯没清不许开始写代码**。黄灯可以做，交付说明里逐条写理由。lint 查的是：表前画风、色板、角色三行有没有写；色板里有没有蓝紫色值；角色行是不是代码画的小人，物列里有没有机器人、小人、火柴人而角色不是帧库，用了 y4 却没有帧库，有没有给金币、小球长脸；物列不能空、不能只是版面词、不能是空镜/纯色/黑场这类空画面；做什么列要有动作；屏上字 ≤8；第一镜和最后一镜都不能是文字主导；文字主导 ≤30%；给了 `--script` 时屏上字里的数字（百分数、年份、带单位的数）要在文稿里找得到（文稿写「百分之六十」也认）；有「标签」列时一镜超过 3 个标签报黄；单镜 2–6 秒（6–8 秒黄、超过 8 秒红）；连续三镜同一个镜头动作报黄；做法列里同一个片段合计超过 8 秒、片段语法超过 2 种报红。「一个例子贯穿」「每镜真的是同一种画风」「相邻构图不同」机器查不了，自己对。
