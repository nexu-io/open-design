01

真正在说的事

Markdown 的编辑前提,正在悄悄消失。

Markdown 之所以成为 Agent 的默认输出,是因为它易写、易读、易改。这三条里,真正决定它统治力的是"易改" —— 你随手可以打开一个 .md 文件改两行,这是它压过 PDF、HTML、Word 的护城河。

但作者的关键观察是:这个前提,在他自己的工作流里已经不成立了。

"我已经不再亲自编辑这些文件,我都是 prompt Claude 来改的 —— Markdown 最大优势之一已经消失了。" — Thariq · 原文意译

一旦你承认这件事,文档的角色只剩两种:给模型看(中间态),给人看(终态)。前者 Markdown 仍然合适,因为下一个 Agent 也得读它;但后者 —— 那个真正决定"你和你同事会不会读"的环节 —— Markdown 显得太朴素了。

这一段是全文最朴素也最锋利的洞察。它没有论证 HTML 多好,而是先撤掉 Markdown 站立的那块地。

02

表达力的代差

几乎不存在 Claude 能读懂、却不能用 HTML 表达出来的东西。

作者列了 HTML 能承载的内容种类 —— 表格、CSS 排版、SVG 插画、内嵌脚本、交互、空间布局、图像。这份清单几乎覆盖了所有的语义形态。结论是:模型可以贴着内容选媒介。

表格化数据 SVG 插画 交互组件 空间布局 代码片段 媒介贴着内容选

讲流程,就画 SVG;讲数据,就画图表;讲设计,就直接渲染组件;讲色彩,就别再用 unicode 字符模拟了 —— 后面这一条作者举了一张 Claude Code 截图为例,模型在 Markdown 里用 emoji 凑出色块,看着滑稽,但其实是 Markdown 时代默认的妥协式表达。

HTML 让这些妥协可以收回来。模型不再需要"在 Markdown 的语法约束里把意思塞进去",而是可以为每一段内容选择最贴近它本质的呈现方式。

六个理由 · 重新分组
表达 · Expression
信息密度 / 视觉清晰度 —— 模型可以贴着内容选媒介,不再被纯文本将就。
流通 · Distribution
易分享 —— 一个 URL 就能传开,Markdown 还得当附件发邮件。
协作 · Collaboration
双向交互 / 自定义编辑器 —— 文档可以是一次性的小工具,人和模型来回交换。
上下文 · Context
Claude Code 能拼上文件系统、MCP、git 历史 —— 这是 Claude.ai 做不到的。
体验 · Joy
"做 HTML 这件事本身就让我觉得更投入" —— 这条不是修辞,工作的愉悦感本身就是生产力。
观感 · Polish
指着自家代码库生成一份 design system HTML 当上下文,后续生成自动有品牌一致性。
03

文档变成小工具

最被低估的一段:一次性的、为这件事专门定制的微型软件。

文章里 Custom Editing Interfaces 和 Two-way Interaction 那两节,我认为是整篇里最有产业含义的部分。作者描述的工作方式不再是"写一份文档",而是 ——

"做一个一次性的、为这件事专门定制的 HTML 编辑器,带个把当前状态复制为 JSON 或 prompt 的按钮 —— 用完就扔。" — Thariq · 原文意译

把 30 张 Linear 卡片拖到 Now / Next / Later / Cut 四个分桶、tune 一段 system prompt 的同时三个 sample input 实时预览、调一条动画曲线、annotate 一份 diff —— 这些事过去要么靠通用工具凑合,要么自己写一段脚本(贵)。

当模型可以为这一次任务专门做一个带导出按钮的 HTML 编辑器,这些事的边际成本归零了。文档不再是文档,而是为这一次任务存在的微型软件。

  • 排序与分桶 —— 工单、测试用例、反馈,哪一份用一个拖拽 UI 都比写文字快。
  • 结构化配置 —— feature flag、env vars、有依赖关系的 JSON / YAML。
  • Prompt 调优 —— 左右分栏的实时模板渲染、token 计数、复制按钮。
  • 数据集策展 —— 一行一行 approve / reject、打 tag、导出选中行。
  • 难以用文字描述的取值 —— 颜色、缓动曲线、裁切框、cron 表达式、正则。
04

重新回到 loop

当文档好读到你愿意打开它,你才有机会保留判断权。

原文最后一段才是 Thariq 真正想说的话。作者承认:他曾经因为 Markdown plan 太长读不下去,担心自己不得不把决定权交给 Claude。换成 HTML 之后,反而觉得自己比以前更能跟上 Claude 的工作。

翻译成一句话就是:当文档好读到你愿意打开它,你才有机会保留判断权。 Markdown 的失败不是格式失败,是"读不下去"的失败 —— 而读不下去意味着你正在交出 review 权。HTML 解决的是这个问题,不是字体问题。

这件事比"换个文件格式"大得多。它在不经意间标记了一个相变点:Agent 输出的中位数复杂度,已经超过人类愿意线性阅读的承载力。 任何想继续 in the loop 的人,都得换一种方式才能继续负责 —— HTML 是 Thariq 给出的答案。
