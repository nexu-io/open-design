故事的起点

本地 Agent 的配置门槛会先劝退新用户。

Josh 关注非技术创作者和小企业。他们需要更好的设计，希望把第一次使用花在创作上。

他们可能已经会向模型描述想法，也需要品牌方案、落地页或社交媒体内容。本地 Agent、API Key、模型能力和命令行配置，容易把创作任务埋在一连串陌生选项里。Josh 先帮助对方获得有用结果，再解释背后的工作流。

他如何与 OpenDesign 结缘

Open Design Cloud Agent 让大使角色变得具体。

Josh 通过 OpenDesign 大使申请加入。当时团队正在介绍 Open Design Cloud Agent，它为本地 Agent 工作流提供了更简单的入口。

他的提案面向中小企业：从品牌方案开始，再把同一套方向延伸到落地页和社交内容。他希望参与者带着一个可用结果离开，并理解如何重复这条路径。对第一次使用体验的关注，让他进入了大使社区。

贡献如何发生 · 01

他的第一项贡献，是帮助别人跨过卡点。

在 OpenDesign Discord 社区里，Josh 开始回答具体的使用问题。他用简短、准确的回复帮助工作流继续向前。

贡献如何发生 · 02

他亲自测试希望别人能够信任的路径。

Josh 把自己的 Reasonix 本地 Agent 实例连接到 OpenDesign。推理视图没有按预期运行时，他在社区提出问题，继续测试配置，重启环境，并在恢复工作后反馈结果。

Josh 把排障当作产品工作。他遇到的每一个粗糙边缘，未来都可能再次挡住新用户。公开测试让团队和社区更清楚地看到真实的上手体验。

文档可以描述顺利路径；社区里的人能够发现某位用户在哪一步掉了出去，并帮助他重新回到路径上。
