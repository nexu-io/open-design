何が起こったのか

ワークショップはライブプロダクトラボになりました。

参加者は、プレゼンテーション、ダッシュボード、Web サイト、製品プロトタイプなどに取り組みました。既存のブランドやデザインシステムから始めた人もいます。他の人は外部データと API を接続し、その結果を視覚的でインタラクティブなものに形作りました。

仕事の範囲が重要でした。 OpenDesign が、ワンショット ジェネレーターとしてではなく、人々が構築、検査、改良、プレゼンテーションできるワークスペースとして、非常にさまざまなジョブにわたってコンテキストを保持できるかどうかをテストしました。

すべての成功とすべての摩擦が有益なフィードバックになりました。つまり、新しいユーザーがどれだけ早くモデルを接続できるか、編集がどの程度予測可能であるか、完成した成果物を他の人に渡しやすいかどうかなどです。

最強の瞬間は完璧なデモではありませんでした。 それは実際の作業が部屋との接触を生き延びる様子を観察していました。

基礎

デザイン システムにより、すべての新しいアーティファクトがつながっているように感じられました。

この部屋で最も明確な製品価値は一貫性でした。参加者はブランドの Web サイトやリポジトリを持ち込み、共有のタイポグラフィ、スペース、アセットを確立し、そのシステムをデッキ、ソーシャル コンテンツ、プロトタイプ、Web ページ全体で再利用できます。

それはAIの役割を変える。ワークスペースは、個別のビジュアルを生成するのではなく、モデルとエージェントに一連の境界を与えるため、チームは毎回ビジュアル言語をやり直すことなく、迅速に作業を進めることができます。

ライブビルド · 01

複雑なアイデアが、説明できるだけでなく探索可能になりました。

ある参加者は、システム思考プレゼンテーションの 2 つのバージョンを作成し、アニメーション要素とインタラクティブ要素を追加して、抽象モデルを理解しやすくしました。

もう 1 つは、香港のオープン データと地図 API を接続して、最初に API ドキュメントを参照することなく、ライブ天気ダッシュボードを作成しました。自然言語のインテントは、データと使用可能なインターフェイスの間の架け橋となりました。

ライブビルド · 02

ショーアンドテルは分析から雰囲気にまで及びました。

部屋は 1 種類の出力に収束しませんでした。構造化されたダッシュボードやプレゼンテーションと並んで、雰囲気を作り出し、注意を引きつけ、探索を促すために構築された表現力豊かな Web エクスペリエンスがありました。

その多様性がエージェント ワークスペースのポイントです。同じ基盤システムで、厳密な内部プロトタイプ、インタラクティブな説明、またはすぐに提示できるビジュアル コンセプトをサポートできます。

部屋が教えてくれたこと

強力なワークフローであっても、エッジでは楽に感じられる必要があります。

プロンプトの前に開始します。

初めてのユーザーが CLI ツールや API キーを理解していなくても開始できるように、接続、認証、およびモデルのセットアップが明確である必要があります。

AI ファーストにはまだ直接制御が必要です。

人々は、エージェント主導の編集と並行して、予測可能な画像生成と、ドラッグ、サイズ変更、位置合わせ、元に戻すなどの単純なアクションを望んでいます。

配信によりワークフローが完了します。

完成した成果物は、受信者に技術的な知識を求めることなく、共有リンク、PDF、Word 文書、Feishu、または Google ドライブに簡単に移動できるはずです。

私たちが学んだこと

OpenDesign は、デザイン システム、エージェント、データ、編集可能な出力が 1 か所に集まる場合に最も役立ちます。

一貫性は乗数です。

再利用可能なデザイン システムにより、すべての新しい成果物が適切な視覚的コンテキストから開始されます。

ライブ接続が素晴らしい瞬間を生み出します。

モデルやスキルは、実際のデータを人々が使用したり表示したりできるものに変えるときに具体的なものになります。

ラストマイルも創造の一部です。

編集可能性、エクスポート、共有が、印象的な結果が実際の作品の一部となるかどうかを決定します。
