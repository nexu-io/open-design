`ELECTRON_FIXTURE_ENDPOINTS` is the complete phase-one fixture surface: one bootstrap handoff, seven shared-lifecycle operations, one non-authoritative feedback observer, and four Shell-updater operations. Its name is a compatibility warning, not a production protocol promise. The fixture Sidecar uses correlated IPC only for its updater proof and runs under the verified official Node carrier, never Electron-as-Node. Placeholder rendering, presentation/focus, activation receipts, installer execution, and `od://` routing are Shell/Electron-internal and cannot add fixture messages.

## Current substitution seam

`ElectronFixtureBootstrapPort` and `ElectronFixtureLifecyclePort` are readiness-preserving stand-ins until the upstream Standalone and Sidecar tasks freeze. They are wired explicitly through `createFixturePorts` in `shells/electron/src/composition/definition.ts`. Production replacement must delete Electron-owned heartbeat, status/release/stop, transition renewal, transport identity and retirement; it consumes Standalone's logical handoff and Sidecar's guarded physical runtime handle instead of retaining the fixture registry. Installer execution remains Shell-owned and must preserve a guarded continuation across orderly Electron quit. Signing/notarization, publication policy, real candidate shell identity from release metadata, and native Windows refinement remain outside this local macOS foundation proof.

The concrete cold-start/warmup graph is declared by `shells/electron/config/runtime.json`. electron-kit validates dependency order, drives blocking/background lifetime, timeout, cancellation and progress projection, and supplies the Standalone/carrier atoms. The Shell owns labels and renderer behavior. The fixture placeholder's HTML, instance-scoped warmed value, protocol response and DOM readiness acknowledgement therefore live under `shells/electron/src/adapters/renderer/`, not electron-kit.

Ready-before policy is the separate `preflight` section of `shells/electron/config/runtime.json`. electron-kit accepts only its finite locale and connection-exemption atoms, rejects late application and arbitrary switches, and passes the resulting locale receipt to the renderer adapter. Concrete service hosts remain Shell-owned; future Web locale injection must be implemented by that adapter rather than electron-kit.

electron-kit intentionally exposes no Sidecar control-session API. Once upstream contracts freeze, `shells/electron` will compose product handlers against their public runtime handle; private IPC and physical lifetime remain in `packages/sidecar`. Until then, the fixture does not publish a temporary desktop handler protocol.

Windows integration follows the same declaration/execution split. `shell.json` is the single publisher/product identity source; `config/platforms/windows.json` owns install scope and product-data retention; `distribution.json` retains artifact and NSIS presentation choices. The pack atom derives electron-builder's `guid`, `perMachine`, and `deleteAppDataOnUninstall` values from the shared identity/policy. On Windows it renders a package-owned, scalar-only Mustache resource into an ephemeral NSIS include: install adds App Paths/protocol projections only after electron-builder commits files and uninstall identity; uninstall removes them only while their exact executable prefix is still owned. Runtime uses the same identity to reconcile only the already-installed `DisplayVersion`. The recursive HKCU/HKLM compatibility scan and the POC's full staging/rollback installer remain later layers rather than hidden behavior in this foundation atom.
