## 1. 要你拍板的

按影响从大到小。每条写明我建议什么、为什么、选别的会怎样。

### T3 · 一轮里出现多张执行记录,怎么呈现 —— **已拍板:F(D29),下面四个候选作废**

> 定下来的规则:第一张执行记录钉在本轮正文上方、收所有探路的 thinking / 工具(和 main 现状一样),正文在它下方;agent 一发清单才多出第二张,之后的输出(工具、thinking、正文)收进当前进行中的 todo,todo 全部关闭后工具接在 todo 后面、正文回到卡片外。一轮最多两张。

以下为拍板前的候选分析,留作记录。

**现象。**现行规则是「普通文本一来就封掉当前执行记录」。Claude 习惯边做边说,于是真实一轮出现 3 块执行记录,标题都是「已完成」(图 1)。

**场景稿怎么画的。**八屏每屏只有一块执行记录;过程中的叙述(「截图里是 4 列、24px 沟槽……」)放在执行记录**里面**,夹在步骤之间;只有开场一句和结论在外面。这和 D10「普通文本在壳外」是冲突的——D10 拍板时讨论的是结论性文本,没有讨论过程叙述。

**四个候选**(模拟器顶部可切):

| | 做法 | Claude 真实一轮 | 代价 |
|---|---|---|---|
| A | 文本一来就封口(现行) | 3 块 | 标题重复,没有信息 |
| B | 只有清单到达或轮结束才封口 | 1 块 | 文本之后的工具调用插回上面那块,新内容出现在已读文本之上 |
| D | 同 A,但中间块折叠成一行摘要 | 3 块 | 设计要补「中间块」这一态 |
| **E** | 文本先落在外面;后面还有动作,就收进执行记录里当叙述(场景稿的做法);清单到达也不封口 | 1 块 | 一段文本会从外面挪进里面一次 |

**建议选 E。**它就是场景稿画的东西,一轮一块,过程与结论分开;B 的「新内容长在已读内容上方」在流式里很难受;A 和 D 的多块标题对用户没有信息量。代价是那一次挪动,发生在 agent 说完一段话又去调工具的瞬间,幅度是一段文字上移进卡片。

**选 E 要同时做的事。**D10 改写为「开场与结论在外面,过程叙述在里面」;规格里「清单到达 = 封旧开新」(D12)作废,改成「接在已有内容后面」;不重叠的第二份清单按 D14 划线重规划,不开新块。

### T6 · plain 系 agent 的空壳

qwen / deepseek / aider 这 7 家只输出文本,没有任何工具事件。按「执行记录永远出现」(B1),它们的执行记录从头到尾是空的,轮结束后变成一张空的「已完成」(模拟器「plain 系」场景)。

**建议:运行中保留,轮结束时还是空的就移除。**运行中那块空态是用户唯一能看到的「它在干活」信号;结束后一张永远空的「已完成」没有任何信息。这是给 B1 加一条例外,不是推翻它。

### T2 · 提测范围

82 格 + 9 个动画 + 组装 + 录屏,6 天做完的风险高。

**建议分两批。**第一批 8 月 26 日:执行记录(7/9/10/11/12)+ 理解段(3/4/5/8)+ 产出(13/14/15/16/24),共 44 格,是主命题和降级形态最集中的地方;第二批 8 月 28 日:输入(1/2/21/23)+ 边界(6/17/18/19/20/22),共 38 格。8 月 24 日第二次纠偏点时再确认一次。

### T4 · 元工具那一行怎么写

`ToolSearch` 这类工具既不读也不写。**建议按工具名原样显示成一条普通行**(现状),不做语义归类——出现频率低,设计稿没有对应形态,不值得为它发明一种。

### 退掉钉在输入框上方的 TodoCard(B17)

设计稿里没有这张钉住的卡,任务清单只出现在执行记录里(「执行计划 · N 步」+ 每步一个折叠块)。同一份清单显示在两处会互相矛盾。**建议随本次一起退掉**,同一个 PR 改根 `AGENTS.md` 里那段约定。这条我已当作设计推导出的既定行为记进规格 §13,你不反对就不再讨论。

设计稿没画、实现时绕不过去的。每条写了我的默认做法:到时候没答复就按默认做,并在陈列页上标「待确认」。

| # | 事项 | 设计稿现状 | 我的默认做法 |
|---|---|---|---|
| S1 | 工具失败有两种写法:「读取 规范.pdf **失败** 1.2s」和「写 bundle.js **· 目录只读** 0.2s」 | 组件 9 / 10 各画了一种 | 有原因就写原因,没有就写「失败」 |

| S5 | 一轮多个产物,谁上大卡 | 组件 14 没画 | 最新的 HTML 上大卡,其余进执行记录 |

**S7(比 S6 更根本)**:设计稿里没有「没有清单」的执行记录。组件 7 / 9 / 10 / 11 的每一个状态,工具行和命令折叠行都嵌在一个步骤折叠块里;CSS 注释也写明,执行记录下直接挂的行只在「折叠头本身就是一个步骤」时出现。我们规格里「平铺是基线、分段是增强」是从 agent 能力推出来的,设计从没画过——而 Claude(没有 TodoWrite)和 Codex(没有 plan)现阶段全部落在这个没画的形态里。三条路:设计补一态;把没有清单的一轮合成一个匿名步骤(步骤名从哪来是问题);把 MCP 注入清单(B12)做成所有 agent 的前提,平铺只作兜底。我的默认:模拟器先借用「步骤子项」那一层的缩进和字重渲染、不加步骤头,等设计给一态。S6 是它的子问题。

**S8**:命令行没有 description 时怎么画。8/20 21:02 版在组件 7 给了「执行 <命令> 耗时」单行(命令是可点的链接,aria 写「查看 … 的输出」),组件 11 的折叠块(人话标题 + 命令与输出正文)也还在。我的默认:有 description 走折叠块,没有走单行;剩下只需设计答一句——单行的输出点开在哪里看。

极端内容四项,同样要设计给原则:意图澄清 12 个选项怎么排;单条任务标题很长、又要划线怎么处理;一轮工具调用 100 次以上怎么折;一轮产物 5 个怎么排。

## 4. 底层改动

都在客户端,不碰云端。

**工具耗时。**daemon 里每条事件本来就有时间戳,只是没发出来。改法:`tool_result` 加一个可选的 `completedAt`,在 daemon 发事件的唯一出口统一盖章,落库和 web 端透传,四个单点。27 家 agent 全部受益。老会话没有这个字段就不显示耗时,不用 `0s` 填;老客户端连新 daemon 会忽略多出来的字段(web 端是按字段名挑着读的,不会报错)。

**Claude 的清单。**Claude Code 的 `-p` 模式没有 TodoWrite(裸 CLI 对照实验已证,与我们无关)。给它注入一个 MCP 工具,写清单、标 done、作废带理由三种用法收成一个。两个要点:MCP 工具名是 `mcp__<server>__todo_write` 这种形式,现有的名字匹配认不出来,必须一起放宽;prompt 要写明「先调作废工具、再说后面的话」,否则理由落回旧步骤里。

**AMR 的清单。**ACP 把未知工具名首字母大写,`todowrite` 变成 `Todowrite`,web 端认不出。修一行映射。本地 AMR 账号余额不足跑不起来,这条只有代码推演——如果提测前拿不到有额度的账号,就标「未验证」交付。

**生图逐张计数。**`GET /api/projects/:id/media/tasks` 已经有,web 还没用。有生图任务时每秒轮询一次,没有就不轮询。

**命令解析。**9 条真命令 9/9 通过,两条易错点已固化成测试(管道取上游、顺序执行取权重最大)。要补的是 `sudo` / `env` 这类前缀剥离;shell 别名无解,客户端看不到环境,接受。

## 5. 性能

第 1 版担心「长会话里几十颗 canvas 球同时转」。看过设计稿之后这个前提不成立:**那颗球只在进行中的执行记录头上,一个会话同一时刻最多一颗**;已完成的块没有球。步骤前面那枚 15px 的球是纯 CSS 锥形渐变,也只在正在跑的那一步上。所以长会话的动画开销是常数,不随轮数涨。

真正要测的两条,在实现过程中测,不等提测:

- 推理流 2000 字流式输入时的重排次数(自动贴底用 rAF 不用 setInterval)
- 生图 20 张缩略图用懒加载
