# 同一次请求内合并 plan 与 production

## 目标与范围

以 2026-10-19 用户确认的范围为准：一次 query 对应一轮助手回答，只把自动衔接的 plan 与 production 合并展示。沿用现有状态、耗时、折叠入口、文案和样式。

- 使用现有「进行中 / 用时 / 运行失败 / 已停止 + 耗时 + 箭头」作为过程的折叠入口。
- 自动进入 production 时保持同一轮进行中，累计时间不归零，不出现 plan 单独完成的状态。
- plan 与 production 的思考、工具和自动规划说明按顺序放在同一份过程内容中；最终回答与产物继续使用现有展示。
- production 失败时，整轮沿用现有失败状态、错误说明和恢复动作。
- 折叠行为沿用现有组件：运行中展开，最终结论到达时收起，当前组件内尊重用户手动操作；取消时保留展开。刷新采用原有生命周期默认值。状态文案及耗时格式跟随当前 main 的通用组件。

## 不属于本次需求

不新增「执行记录」这一层、独立状态行或样式，不持久化折叠偏好。不新增「等待回答」「继续本任务」等状态或过程节点。

不跨用户消息合并问答、重试或继续执行，不改变这些操作的请求与恢复语义。普通单 Run 和纯文本回答沿用原有展示。

## 验收

自动 plan→production 只出现一个过程折叠入口，状态与累计时间连续；成功、失败、取消和重新进入会话后均沿用现有交互。无工具事件时不制造空过程记录。
