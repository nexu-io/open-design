# OD Next 任务展示实现建议

本文是产品方案的工程可行性建议，不是已完成的实现。范围以 od-next-task-display.md 为准，基线为 main 1343f374c6。

## 建议路径

保留 daemon 每次 Run 的持久化记录、底层执行任务 ID、状态、done_key、事件边界和现有续跑行为。增加宿主确认的展示任务关联及一份展示事实投影，由任务展示层提供唯一的状态、累计耗时与执行记录入口。各 Run 的思考、工具、步骤和自动规划说明汇总为一条有序过程时间线，不再保留逐 Run 的执行记录壳；物理边界仍用于完成判据与局部工具状态。

不能只删除前序“已完成”文字：后继边界延迟、任务等待回答、刷新回读与实时累积的消息形态不同，单靠最后一张执行记录无法稳定显示任务计时。

## 事实与所有权

| 内容 | 来源／负责方 | 边界 |
| --- | --- | --- |
| 展示任务归属、后继 Run、当前 Run | daemon 验证的操作来源与现有执行任务映射 | 不使用 analytics、文本相似度或单独的 continuedFrom 历史关系猜测 |
| Run 实际起止、物理结果 | daemon 实际进入 running／终态的持久化边界 | 现有消息 startedAt 为 run.createdAt，不当作实际开始；其原有含义保持不变 |
| 问题交接、自动续跑、最终结束 | 宿主已有 settlementReason、settlementFacts 与任务映射 | outcome=completed 只表示编排结束，不能直接映射成功 |
| 可继续工作与本轮完成结论 | 现有完成／问题／Todo 判据 | 保留最终 Run 边界；文件存在不能擦掉 pending Todo |
| 任务计时 | daemon 提供可恢复的累计执行段事实；Web 只插值显示 | 不从已拼接正文推算起止；历史证据不足时省略 |
| 过程块、用户展开状态 | Web 组件与现有纯函数管线 | 物理 Run 的边界与局部状态仍供工具、Todo 使用 |

## 最小数据增量

当前 marker 协议将提问记为 completed/question；回答经 resolveStrategyHandoff 创建新 taskExecutionId。普通新请求也可能有 continuedFromTaskExecutionId，因此不能按执行 taskId 或全部 continuedFrom 直接合并展示。

建议在 packages/contracts 定义一份可选的展示任务 DTO，并复用到当前 Run 状态投影及历史消息响应。概念字段为：独立展示任务标识、当前执行任务／Run、全展示任务范围内的 Run 顺序、当前展示状态、跨执行任务可比较的快照版本、计时是否可信、已冻结累计毫秒数、当前计时段的服务端起点和观测时刻。

- 使用现有创建／状态／结束响应承载，保持同一 HTTP 数据来源；不要建立第二套执行状态机。
- 自动后继继承展示关联。表单回答／继续剩余任务／重试／恢复由调用方提交操作用途和来源引用，daemon 验证来源消息、来源 Run、问题实例或可恢复状态与所有权后确认是否继承。客户端不得自行选择一个展示任务 ID 强行拼接。
- 普通新 prompt 始终创建新的展示任务；已有 continuedFrom 只保留上下文用途。旧记录缺少明确用途与可信来源时不猜测跨执行任务关联。
- 展示关联及全局 Run 顺序必须随现有幂等创建事务持久化。重复提交同一 clientRequestId 复用原执行与关联，不追加新的计时段；快照顺序不能因新的底层 taskRunIndex 从 0 开始而重置。
- 服务端返回当前任务整体事实，而不是仅返回“所查询旧 Run”所属的过期结束结论。
- 对历史消息在读取时按任务批量投影；避免逐行查库、逐条重放所有工具事件、或每秒写数据库。
- 精确计时必须新增持久化时序事实：首个实际进入 running 的时刻、问题 Run 的真实结束、恢复后的实际 running、最终结束。现有 ChatMessage.startedAt 取 run.createdAt，持久化 starting 事件也没有精确起点，不能用作本需求的替代事实。
- 可选字段缺失代表旧 daemon／旧历史。不得用任务 createdAt、updatedAt 或当前组件挂载时间冒充精确执行时长。
- 任务展示事实的读操作保持现有项目／会话权限；不得因为仅供展示绕过 task ownership 校验。

执行段模型：从实际 running 到等待回答／最终结束为一段；自动 Run 切换不切段。用户答案／显式恢复后，宿主接受但后继尚未 running 的区间显示 preparing、计时冻结；实际 running 时开启新段。累计时长为完成段之和加当前活动段，不把用户等待计入，不重复累加重连回放的同一段。中间失败被自动后继接续时不结算总体失败。

## 前端接入

1. ChatPane 使用新的展示关联分配唯一状态行，由首个可见助手回复承载。旧数据回退至现有执行任务分组；无归属则保持普通消息。后继边界尚未到达、物理消息仍为两行时，第二行不重复状态头，也不提前把旧事件串按新 Run 状态重算。
2. ProjectView 的首次运行、自动后继、重连、历史刷新和问题回答路径统一接受投影。原来的文本／事件前缀边界继续记录，完成判据只看当前最终 Run。
3. 任务展示层只渲染一个状态行和一个执行记录入口，将各 Run 的过程内容按顺序汇总，自动规划说明属于过程，不能只给多个 ExecutionShell 改同一个标题。其 running／stopped／failed 数据仍用于停止各自的工具动画和步骤状态；展开选择按展示任务持久保存。
4. 任务专用展示下，回答页脚仅保留操作，不再复述状态。错误卡保留原因与恢复操作；问题表单仍在时间顺序中的原位置。
5. 使用共享纯函数处理展示归属、状态／计时快照与失序保护；组件只负责显示。新展示事实覆盖 live／history 都共享，不把已累积的实时正文当作新的运行事实再累加。客户端接收旧源 Run 或旧版本快照时不能回退最新状态；新的权威结束时刻可校准离线高估。初次无法确定计时则不显示，不能先显示 0 再校正。
6. 任务状态行独立于空过程卡的创建和移除，避免最后一次纯文本回复让唯一状态行消失。普通无任务归属消息保持原来的展示路径。
7. 显式续做跨过可见用户消息时，共享展示状态、累计时长和过程汇总入口，在记录内保留等待／收到答复／恢复的时序节点。正式方案、问题、答案、错误原因与恢复操作、最终结论仍在记录外保留会话顺序；不能将后继正式回复搬到用户续做消息之前。表单答案继续复用原表单展示，不另造重复答案气泡。
8. 回答明确拒绝与传输结果未知分开处理。结果未知时沿原 clientRequestId 查询／幂等恢复；不能用 onError 判定未运行，不能盲目重发成新请求。宿主确认后更新状态、按真实 running 时刻续计。

所有变化只限会话展示及必要的事实与来源绑定。现有 CLI 和 Web 使用同一 daemon API、同一 DTO；CLI JSON 可读取新增展示字段。来源绑定若无法通过既有 CLI 请求入口表达，应同一改动补齐对应参数，不新建另一套执行流程。纯视觉布局不需要 CLI 控件，底层 CLI Run 状态含义保持原有语义；PR 列明 contract／API 和实际 CLI 影响。

## 风险与对应验证

| 风险 | 验证重点 |
| --- | --- |
| plan 结束后闪完成再回进行中 | 宿主后继声明与物理终态的事件顺序；延迟 done_key 的过渡帧 |
| 多 Run 拼接丢掉计时来源 | 新任务投影与每次 Run 原始起止同时保留，不改已有 stampRunSpan |
| 任务 completed 被当成成功 | failed／canceled／question／pending Todo 优先级，以及真实物理结果 |
| 刷新重复生产正文／重复累计 | ProjectView 的服务端刷新合并、任务计时按事实段幂等读取 |
| 问题表单被折进过程块 | cross-run-form-placement 与 question-task-live-fold 路径 |
| 回答创建新底层任务导致计时归零 | 真实 /api/runs 创建展示关联；不能只用模拟 clarification_required 且同 taskId 的旧前端夹具证明 |
| 新用户请求带历史关联被错误合并 | 普通新 prompt 与明确来源动作对照；跨项目／会话及伪造来源拒绝 |
| POST 已接受但创建响应丢失 | 原请求 ID 查询／幂等恢复，真实路由只产生一次执行，按实际时刻计时 |
| 旧快照覆盖当前状态 | 按任务归属、当前 Run 序号和快照顺序丢弃过期更新 |
| 用户等待进入耗时 | 问题 Run 结束、答复成功／失败、后继实际开始三个边界 |
| 浏览器时钟偏差或休眠 | 客户端用服务端观测的 elapsed 基数与单调钟插值；重新聚焦／重连时重新校准 |

## 验证与实施顺序

先锁定 contract 与可恢复的服务端时序事实，再实现纯函数投影及前端单一状态行；随后接入实时、刷新与回答路径，最后验证关键 UI。

- 纯函数：状态优先级、执行段累计、重复快照、旧版本和缺失事实；用虚拟时间检查秒数，不写墙钟 sleep 测试。
- daemon：首个实际开始／自动交接／问题交接／恢复／最终结束；历史与当前投影一致；跨项目／会话拒绝访问。必须覆盖真实问答新执行任务继承展示归属、普通新 prompt 不继承，以及 POST 被接受后响应丢失再幂等恢复。
- Web：保留 OPEND-3463 的后继边界防护、OPEND-3740 的最终 Run 完成范围，补单一状态行、连续计时与全任务单一过程入口；验证跨 Run 追加、展开选择刷新恢复、问答原位、无事件 Agent 和不同任务隔离。
- 浏览器：通过隔离 tools-dev 与生产 HTTP API 构造可审查夹具，检查运行中、交接帧、等待回答、成功、失败、取消和刷新后页面。夹具可证明宿主展示路径，不等同真实模型生成验收。
- 必需检查为 pnpm guard、pnpm typecheck 与对应 package 的定向测试。依当前仓库规则，不默认跑本地全量 daemon／Web 测试。

本建议尚未确定字段命名、存储方案和精确组件 API；这些由实现时的最小可恢复事实检查决定。方案评审通过只说明需求和实现路径可行，不能代替实现、浏览器验收或真实模型验证。
