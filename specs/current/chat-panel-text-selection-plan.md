# 组件 23「选中文字 · 添加到对话」技术方案

> 状态:**方案待评审**(2026-08-25 写)。规格主文件是 `chat-panel-next.md`,这里只解一个问题:
> 稿子那个结构直译不了,该怎么落。对应 84 格里的第 65–69 格,Plane OPEND-2199。

## 一句话

稿子把「添加到对话」那条浮条画进了 `<mark>` 里面 —— 也就是**把选区包成一个元素**。
我们的正文是 **markdown 渲染出来的 React 树**,往里插节点会被下一次 render 冲掉,
流式期间每一帧都在冲。所以**不能照着静态稿的结构直译**,要换一种落法。

这一条不是猜的:同一轮里逐字化开就踩过一模一样的坑 —— 把 React 建的文本节点换掉之后,
React 往一个脱离文档的节点里写字,**流式正文中途某一段就不再更新**。
证据留在 `apps/web/tests/components/chat/char-reveal.test.tsx` 的嵌套用例里(改回替换写法立刻转红)。

## 三个候选

| | 做法 | 好处 | 代价 |
|---|---|---|---|
| A | 把 Range 包成 `<mark>`(稿子的结构) | 与稿子逐字一致;浮条能跟着文字流走 | **和 React 打架**,流式期间必然出问题;要么禁用流式期取词,要么给正文加 key 每帧重挂(贵) |
| B | **不碰 DOM**:`Range.getClientRects()` 拿几何,浮条与高亮都画在**覆盖层**上 | 完全不动 React 的树;流式期间也安全;高亮样式随便调 | 覆盖层要跟随滚动与重排(`scroll` / `ResizeObserver` / `fonts.ready` 重算);跨行选区要画多个矩形 |
| C | 只做浮条、不画高亮(靠浏览器原生选区蓝) | 最省;零风险 | 与稿子差一截:稿子的高亮是产品自己的颜色,而且点完之后高亮要留着 |

**建议 B。** 理由:①它是唯一在流式期间也成立的;②几何法我们已经有现成的邻居 ——
`composer-flyout-placement.ts` 做的就是「浮层贴着一个矩形、贴边时翻面」,第 66 格
(选区贴着面板顶边 → 浮条翻到下方)直接复用它,不用另写一套翻转;③高亮是覆盖层上的
矩形,颜色形状随设计改,不受 markdown 结构限制。

B 与稿子的**唯一可见差别**:高亮是画上去的,不是 `<mark>`,所以**选中文字被复制走时不带标记**
—— 这反而更对(复制出去的是干净文本)。

## 契约缺口(必须先拍,不是实现细节)

点完「添加到对话」之后,那段文字要进 composer 的注释列表。现有的
`ChatCommentAttachment`(`packages/contracts/src/api/chat.ts:753`)**装不下它**:
它的字段是 `elementId` / `selector` / `pagePosition` / `htmlHint` —— 全是**预览 iframe 里的元素批注**,
描述的是「页面上那个 DOM 节点」。而这里要描述的是「某条回答里的一段文字」,没有 selector,也没有页面坐标。

两条路:

1. **扩 `ChatCommentSelectionKind`**,加一种 `'text'`,并把 `ChatCommentAttachment` 里
   那几个 iframe 专用字段改成可选 —— 好处是 composer 的注释列表、发送、回显全都不用动;
   代价是这个类型从此一半字段对一半场景无意义。
2. **另起一条通道**(`ChatTextSelectionAttachment`),composer 里两种注释并列 —— 类型干净,
   但 composer 的暂存、排序、发送、回显四处都要认第二种。

**我的默认是 1**,理由是第 67 格(点完之后输入框里多一枚芯片)在稿子里和现有注释芯片长得一样,
产品语义上它们就是一类东西。但这是**契约改动**,要产品 + 后端点头,已记进 §13 待决表。

## 分格落法(B 方案下)

| 格 | 状态 | 落法 |
|---|---|---|
| 65 | 浮条浮在选区上方、居中 | 覆盖层里一个绝对定位的条,位置取 `getClientRects()` 的并集矩形 |
| 66 | 选区贴着面板顶边 → 翻到下方 | 复用 `composer-flyout-placement.ts` 的翻转 |
| 67 | 点完之后输入框多一枚芯片 | 取决于上面的契约选择 |
| 68 | hover 芯片 → 上方浮出全文、右侧露出移除 | 与现有注释芯片同一套交互,跟着走 |
| 69 | 选了好几段 → 只是数字变 | 芯片计数,不新增形态 |

## 不做的

- **流式期间不禁用取词**。B 方案下没有必要禁,禁了反而奇怪(正在生成的段落也该能引用)。
- 不做跨消息选区。稿子没画,而且跨消息的「这段文字属于哪条回答」没有定义。

## 验收

挂上镜像陈列页第 65–69 格;覆盖层的几何跟随要有测试(滚动后矩形还对得上)。
