# 카드 해부 + cards.json / publish-history 스키마

> 채널 기술 규칙(규격·레이아웃 계약·12룰)은 `craft/instagram-cardnews.md`가 정본.
> 여기는 *구조 골격과 데이터 스키마*만. 브랜드 사실(훅 공식·핸들·면책)은 활성 DESIGN.md.

## 카드 골격 (기본 5~8장, 최대 10)

1. **표지 (cover)** — 훅 1개(브랜드 DESIGN.md 훅 공식: 오해/손해회피/시의성 계열) +
   서브타이틀("저장" 유도 태그 허용).
2~N-1. **본문 (body)** — 1카드 1메시지: 타이틀(≤2줄, 줄당 잉크 ≤912px) +
   본문 문단(렌더 5~7줄 — compose가 강제).
   권장 흐름: 핵심 답 → 근거/사례 → 함정·주의 → 해결/체크리스트.
   - **서술형 문단**: body_lines는 완결 문장을 이어 쓰는 문단 — 요약형 조각문
     나열(한 줄 = 한 구절, 의미 단위 개행) 금지. 수치·출처 1개 이상 권장.
   - **줄바꿈·정렬 = compose 소유** (2026-07-07 개정): compose가 문단을 폭 기준
     **글자 단위**로 자동 줄바꿈(어절 중간 개행 허용 — 레퍼런스 풀폭 스타일
     "과육이 푸/석해져요") 후 **양쪽맞춤**(마지막 줄만 자연폭 좌측 정렬)으로
     렌더한다 — 가용폭 912px(=1080−84×2), 좌우 잉크 한계 x=84/996. 금칙 2종
     자동 처리: 줄머리 구두점·숫자/영문 런 중간 개행("30%"는 안 끊김). 에이전트는
     줄 분할을 신경 쓸 필요 없이 **분량만** 맞춘다: 렌더 5~7줄 = 공백 포함 약
     150~220자. 미달·초과는 compose가 에러로 중단(카피 증감 후 재실행).
   - **예외**: 해결/체크리스트 스텝 카드는 넘버드 리스트("1. …") 허용 — 단 자동
     줄바꿈이 문단 흐름으로 잇는 점을 감안해 스텝당 문장을 짧게 완결한다.
N. **CTA (cta)** — 계정 핸들 + 팔로우/저장 유도 서브 문구(+브랜드 면책 축약, 브랜드 요구 시).

## cards.json 스키마 (compose_cards.py 입력 계약)

```json
{
  "slug": "환절기-비염-보험금",
  "body_layout": "basic",
  "cards": [
    { "index": 1, "role": "cover", "sub": "놓치기 쉬운 실비 청구", "hook_lines": ["환절기 비염,", "보험금 될까?"] },
    { "index": 2, "role": "body", "title_lines": ["결론부터,", "됩니다"], "body_lines": ["환절기 비염도 J30 진단 코드를 받으면 실비 청구 대상이에요.", "통원 진료비와 약제비 모두 해당되고, 병원과 약국 영수증만 챙기면 앱에서 바로 청구할 수 있어요.", "자기부담금 공제 후 남는 금액이 지급되니 진료 후 영수증은 버리지 말고 모아 두세요.", "청구 기한은 3년이라 지난 진료분도 소급 청구가 됩니다."], "bg": { "shot": "mid", "angle": "eye", "placement": "right", "view": "front", "pose": "point", "expression": "happy", "locale": "약국 카운터 앞" } },
    { "index": 3, "role": "cta", "handle": "@brand_handle", "sub": "저장해두고 청구 전에 확인하세요" }
  ],
  "caption": "…8블록 캡션 전문…",
  "hashtags": ["#실비보험", "#보험금청구"]
}
```

- `index`는 1부터 연속 — `<slug>-NN.png` 파일명과 배경 `bg-NN.png` 매핑 기준.
- **본문 줄바꿈은 compose가 소유** (2026-07-07 개정): `body_lines`는 문장 소스 배열일
  뿐, compose가 공백 연결 → 폭 기준 글자 단위 자동 줄바꿈(어절 중간 개행 허용) →
  양쪽맞춤으로 렌더한다. 결정성 계약은 유지(같은 입력+같은 폰트 → 같은 출력).
  단 `hook_lines`·`title_lines`의 줄 분할은 여전히 에이전트 확정 — 대신 줄당 잉크
  912px 초과 시 compose가 에러로 중단한다(커버 포함 — 글자수 축소 후 재실행).
- 필수 필드: cover = `sub`+`hook_lines`(1~2줄, 훅 줄당 공백 포함 ~14자 이내 안전) /
  body = `title_lines`(≤2)+`body_lines`(렌더 5~7줄 분량) / cta = `handle`+`sub`.
- `bg`(본문 카드 전용, 선택 아님 — 본문이면 필수): 배경 구도 플랜 선언. 아래
  "배경 구도 플랜" 절이 정본. **compose_cards.py는 이 필드를 읽지 않는다**(미지
  필드 무시) — 소비자는 imagegen 프롬프트 조립(imagegen-pipeline.md)과
  검수(review-subagent.md).
  `shot`·`angle`·`placement`·`view`·`locale`은 본문 필수. `pose`·`expression`은 **선택**
  (브랜드 cardnews 컨텍스트에 캐릭터 시트가 등재된 경우만 의미 — 생략 시 기본형 idle·neutral
  상당으로 렌더). 시트 미등재 브랜드는 두 필드를 넣지 않는다.
- CTA 카드 배경 = `bg-01.png` 재사용(재생성 없음 — 생성 호출 N-1회).
- `body_layout`(선택, 최상위): 본문 레이아웃 옵션 — `"basic"`(기본값, 생략 가능)만
  구현. `"free"`(자유형)는 예약 — compose가 명시 에러로 거부한다(후속 트랙).
- 슬러그 정규식 `[^a-z0-9가-힣]+` (가-힣 보존).

## 배경 구도 플랜 (bg 필드 — 본문 카드 전용)

배경 이미지의 카메라·배치·장면을 카드별로 데이터로 선언한다(2026-07-07 신설 —
도그푸딩-5 구도 단조 재발 방지). cover·cta에는 없다 — 커버는 고정 스캐폴드
(도미넌트 정중앙 전신 = 썸네일 임팩트 + 스타일 앵커 정보량), CTA는 bg-01 재사용.

| 키 | 허용값 | 의미 |
|---|---|---|
| `shot` | `"mid"` \| `"close-up"` | 카메라 근접도 선언 — mid = 전신, 프레임 높이 50~70% / close-up = 카메라 가까이·프레임 높이 70~90%. **close-up ≠ 상반신 크롭 강제**: 허리 위 크롭도, 가까운 전신(머리~발 보이되 크게)도 모두 close-up이다 — 핵심은 캐릭터가 프레임을 크게 채우는 근접감. 원경(50% 미만)·먼 느낌은 어느 값에서도 금지(도그푸딩-8: mid 전신 원경 세트가 "멀다" 반려 실측 — 세트 기본 톤은 근접 쪽) |
| `angle` | `"eye"` \| `"low"` \| `"high"` | 카메라 높이 |
| `placement` | `"left"` \| `"center"` \| `"right"` | 프레임 가로 1/3 기준 캐릭터 위치 |
| `view` | `"front"` \| `"three-quarter"` | 완전 측면·뒷모습 금지 — 눈·입이 보여야 카드 간 캐릭터 일관성 검증 가능 |
| `locale` | 자유 서술 1줄(한국어) | 주제 관련 실사 장소 — 프롬프트 조립 시 영어로 번역돼 Subject에 반영 |
| `pose` | `"idle"` \| `"point"` \| `"hold-prop"` \| `"crouch"` \| `"sit"` (선택) | 시트 포즈 섹션 매핑 — idle=IDLE, point=팔 뻗어 가리키기(ACTIONS), hold-prop=소품 들기(ACTIONS), crouch=웅크려 들여다보기, sit=앉기(SITTING). 시트 미등재 브랜드는 생략 |
| `expression` | `"neutral"` \| `"happy"` \| `"surprised"` \| `"worried"` \| `"wink"` (선택) | 시트 표정 매핑 — neutral=기본, happy=기쁨, surprised=놀람, worried=걱정, wink=윙크 |

**다양성 제약** — cards.json 확정 시점에 데이터로 체크, 위반 시 스스로 재배정 후 진행:

1. 인접 본문 카드 간 `(shot, angle, placement)` 튜플 동일 금지
2. 세트 내 동일 튜플 최대 2회
3. 본문 3장 이상이면 shot·angle·placement 각 축에 2종 이상 값 등장
4. `locale` 동일 최대 2회
5. `pose`·`expression`을 쓰면 각 축: 인접 본문 카드 간 동일 금지 + 세트 내 2종 이상.
6. `locale` 강화 — 문자열 상이만으로 불충분. 서로 다른 **공간/셋팅**이어야 하며, 동일
   배경 지배요소(예: 큰 창가·같은 방)가 세트를 지배하면 위반. `close-up` 카드는 창·광원이
   프레임 지배요소가 되지 않게(소품·캐릭터가 프레임을 채운다).

**선택 기준 = 콘텐츠 매칭**: 카드 메시지에 어울리는 조합을 고른다(경고 →
클로즈업·로우앵글, 보관 팁 → 냉장고 앞 미드샷, 요약 → 하이앵글 등). 제약은
하한선이지 순번별 로테이션 표가 아니다. 라이팅 무드는 세트 앵커가 소유
(imagegen-pipeline.md) — locale이 바뀌어도 세트 톤은 묶인다.
(경고 → `worried`/`surprised` + 클로즈업·로우앵글, 핵심 답 → `neutral`/`happy`, 보관·
체크 → `point`/`crouch` + 소품 인터랙션.)

**정서 우선 룰** (2026-07-14 도그푸딩 실측): 표정·장면 기호는 구조 역할(핵심 답/
함정/체크)이 아니라 **카드 텍스트의 정서**에 매칭한다 — 둘이 충돌하면 정서가
이긴다. 위 매핑의 "핵심 답 → `neutral`/`happy`"는 내용이 중립·긍정일 때만이다:
핵심 답 카드라도 내용이 위험·경고·주의면 `happy` 배정 금지(`worried`/`surprised`
계열로), 메시지의 위험 기호(폭염 → 작열 태양·아지랑이, 식중독 → 여름 상온의
음식 등)가 프레임에 보이게 locale·Subject를 잡는다. 위험을 말하는 카드가 쾌적한
장면 + 웃는 표정으로 렌더되면 카드가 딴 메시지로 읽힌다(실측: "가장 위험한
시간" 폭염 경고 카드가 시원한 그늘 산책 무드 + `happy`로 나와 반려).

**소품·히어로 매칭 2룰** (도그푸딩-8 실측 — 위반 시 카드가 딴 주제로 읽힘):

- **소품은 메시지 의미와 일치**: 소품의 시각 기호가 카드 텍스트의 핵심 개념을 가리켜야
  한다. 예: "식중독은 7월 최다"(통계) 카드의 달력은 **7월이 보이는 평범한 월간 달력** —
  비구름 아이콘 달력을 쓰면 날씨 예보 카드로 오독된다. 추상·통계 카드에 리터럴 소품을
  쓸 때는 프롬프트에 "무엇이 보여야/보이면 안 되는지"를 명시한다(no weather icons 등).
- **주제가 기기·사물이면 그것이 프레임 히어로**: 카드 메시지의 주인공이 냉장고·기기·
  사물이면 그 사물이 프레임을 지배하고(발광·디테일 강조) 캐릭터는 그것과 상호작용하는
  보조 위치로. 단 캐릭터 얼굴(눈·입)은 항상 보여야 한다 — 텍스트 오버레이 존(하반부)에
  얼굴이 가려질 배치는 금지.

## publish-history.md 스키마 (dedup 소스)

`{cwd}/publish-history.md` — 로컬 발행 이력이 유일한 dedup 소스(라이브 조회 없음).
스킬은 **Read만** 하고 자동 append 하지 않는다(발행은 스킬 밖 사건 — 핸드오프에서
수동 추가를 안내).

```markdown
# publish-history — 인스타 카드뉴스 발행 이력

| 날짜 | 주제 | 핵심소재 |
|---|---|---|
| 2026-06-20 | 도수치료 실비 청구 기준 | 도수치료 |
```

- **핵심소재** 컬럼이 dedup 판정 기준(제목 글자 일치가 아님) — topic 서브에이전트의
  60/90 규칙이 이 컬럼으로 판정한다.
- 파일이 없으면 이력 "미확인"으로 정직 표기하고 진행한다.
