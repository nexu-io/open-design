# Braze IAM — 비주얼 레이아웃·컴포지션 문법 (레퍼런스 보드 정본)

> 정본 근거 = 실사용 IAM 레퍼런스 보드 25핀 전수 분석 (2026-07-13, 한국 프로덕션
> IAM 실캡처 — 네이버 생태계·커머스·핀테크/페이·구독 유틸·에듀·채용). 보드 지배
> 문법: **화이트/뉴트럴 카드 + 글로시 3D 단일 의미-지시 소품 히어로 + 초대형 숫자
> 타이포 + 풀폭 비비드/블랙 CTA + 텍스트-비주얼 존 수직 분리**. 초기 24장 분석은
> 보조 근거로 병합. Step 3 기획안의 `image.composition` 설계와 Step 4b 빌더의
> 레이어 배치가 본 문서를 따른다.
> 원본 스크린샷·핀은 repo에 없다 — 패턴은 본 문서의 워딩이 정본이며, 생성 프롬프트의
> view_image 앵커로 타사 레퍼런스를 쓰는 것은 금지 (IP·캐릭터 오염).
>
> **번역 규칙 (가장 중요)**: 레퍼런스는 텍스트·배경·오브제가 한 장의 이미지로 구워진
> 완성 크리에이티브다. 우리 파이프라인은 기획안 `image.mode`(`"layer"` 기본값 |
> `"scene"`, 빌더·검수 dispatch 입력명 `{image_mode}`, SKILL.md Step 2 인터뷰에서
> 선택)에 따라 두 갈래로 재현한다:
> - **`layer` 모드(기본)**: 텍스트·배경·오브제를 3레이어로 분해 — 텍스트는
>   **HTML 텍스트**(이미지에 굽지 않음), 배경은 **CSS**(단색·그라디언트·장식),
>   오브제만 **투명 PNG 에셋**(library/generate).
> - **`scene` 모드**: 배경+오브제가 **생성 씬 1장**으로 통합된다 (§10 씬 카드
>   문법 참조). **텍스트=HTML만 불변** — 씬 안에 글자를 굽지 않는다.
> 어느 모드든 이미지 안에 글자가 들어가는 순간 로컬라이즈·수정·접근성이 전부 죽는다.

## 1. 존 스택 고정 — 7단 수직 분리 (기본형)

보드 ~22/25가 센터 단일 컬럼 + 동일한 수직 존 스택을 따른다. **텍스트-비주얼
존은 수직으로 분리한다 — 비주얼 위 텍스트 오버레이 금지** (보드에 오버레이 0.
scene 모드의 씬-오버레이 문법은 §10, 존치 보류 중):

```
┌─────────────────────┐
│              [✕]    │
│  아이브로우 필 (1줄)  │  ← 시점·자격 라벨: "매월 1일부터 10일까지", "회원님께만"
│  헤드라인 (1~2줄)     │  ← 악센트 키워드 정확히 1개 (§7)
│  서브카피 (0~2줄)     │  ← 선택 슬롯
│    ╭─────────╮      │
│    │ 히어로 존 │      │  ← 단일 소품 or 초대형 숫자 (카드 높이 30~45%)
│    ╰─────────╯      │
│  가격·조건 (선택)     │  ← 취소선 원가→할인가, 카운트다운 칩 (§7)
│  [   주 CTA 풀폭  ]  │  ← 행동동사, 브랜드 비비드 or 블랙
│   보조 dismissal    │  ← 회색 텍스트 링크 "다시 보지 않기"
└─────────────────────┘
```

서브카피·가격/조건은 선택 슬롯 — 없으면 접는다(순서는 불변). 컴포지션 스케치는
전 존을 나열한다 (존 누락 시 병렬 빌더 발산 실측 2026-07-13).

**변형 2종** (24장 보조 근거 — 드물지만 유효):
- **오브제-톱 역전**: 오브제가 상단, 헤드라인이 아래 (하단시트에서 관찰 — 3D 앱 아이콘 히어로 → 텍스트 → CTA). 오브제가 자기설명적일 때만.
- **CTA-미드**: 헤드라인 직후 CTA, 오브제가 하단 장식 (세리프 타이포 중심 멤버십 카드에서 관찰). 오브제가 무드 장식이고 결정이 가벼울 때.

## 2. 레이아웃 유형 5형 (관찰 빈도순)

| 유형 | 구조 | 적합 | 보드 빈도·관찰 사례 |
|---|---|---|---|
| **센터 모달 (라이트)** | 화이트/오프화이트 카드 중앙 (§5 기본 배경) | 혜택·알림 범용 **기본값** | **보드 지배형** (~16/25 화이트·오프화이트). 설문 클립보드, 마이데이터 아이콘 클러스터 |
| **센터 모달 (다크)** | 블랙/딥컬러 bg + 고채도 오브제·악센트 | 임팩트·긴급·프리미엄 | 보드 2/25. 쿠폰 슬롯머신, "혜택 못 받으셨어요?" 쿠폰, 스포트라이트 토글 |
| **투톤 카드** | 상단 = 컬러 이미지존, 하단 = 화이트 CTA존 | 브랜드 컬러 강한 캠페인 + 명확한 행동 | 채용 공고(오렌지+화이트), 멤버십 선물(블랙+화이트) |
| **풀시트** | 화면 전체 점유, 배경도 크리에이티브 | 온보딩·시즌 캠페인·상담 전환 몰입 | 설맞이 봉투(크림), 보험 3D 달력, 브랜드 콜라보(포토 상단+시트 하단) |
| **하단시트** | 하단에서 60~70% 상승 | 업데이트 소개·가벼운 발견 | 앱 리뉴얼(3D 아이콘 + 질문형 CTA) |

포맷 선택 자체는 `format-design-guide.md` §0 매트릭스가 우선 — 본 표는 각 포맷 안에서의 비주얼 처리를 정한다.

## 3. 히어로 유형 — 히어로 존에 무엇을 넣는가

기본값 = **단일 의미-지시 소품** (보드 ~14/25 최다). 소품 어휘(빈도순): **쿠폰/
티켓(최빈) · 코인 · 기프트박스 · 메달 · 봉투 · 벨 · 클로버 · 배지 · 물음표 ·
토글 · 달력 · 자물쇠**. 렌더는 글로시 3D 고정 문구(`imagegen-pipeline.md` 스타일
스캐폴드, 사용자 지정 2026-07-14 — 보드 클레이 질감 대체)를 따른다.

| 히어로 유형 | 문법 | 파이프라인 매핑 |
|---|---|---|
| **단일 의미-지시 소품 (기본)** | 소품 1개 중앙, 크게 — 위 어휘에서 캠페인 의도로 선택 (§4 매핑표). 글로시 3D, 비비드 단일 색군, 살짝 기울여 부양 | `generate` 1건 (`3d-icon`/`flat-icon`) |
| **초대형 숫자 타이포 히어로** | 할인율·금액 숫자가 곧 히어로 (보드 ~11핀 — 숫자 > 헤드라인 다수). **HTML 대형 타이포 + CSS**, 이미지에 굽지 않음 (§7 숫자 위계) | 생성 0건 — 빌더가 HTML/CSS로. 소형 소품 보조 병치 가능 |
| **오브제 클러스터** | 주 오브제 + 의미 있는 위성 소품 ≤2, 단일 색군 (서류+카드+지폐) | `generate` 1건 (클러스터로 한 번에) or 주 1 + `css` 장식 |
| **쿠폰 티켓** | 절취선·스텁·다운로드 아이콘이 있는 티켓 그래픽, 기울여 배치 | `generate` (`3d-icon`/`flat-icon`) — 단 숫자·문자는 HTML 오버레이로 |
| **앱아이콘 배지** | 스쿼클 앱아이콘(그라디언트 면 + 화이트 글리프)이 히어로 — 기능·설정 소구(알림 켜기 등, 하단시트 실캡처 관찰). 알림 도트는 CSS 원으로 얹는다 (색·위치·정원 결정성 — 생성에 맡기지 않음) | `generate` 1건 (`3d-icon`, front-on 덧붙임) + `css` 도트 |
| **UI 프리뷰** | 실제 앱 화면·기능 카드 목업이 히어로 (보드 3핀) | 브랜드 제공 스크린샷만 (`library`) — UI 목업 생성 금지 (허구 UI 오독) |
| **캐릭터 히어로** | 브랜드 캐릭터가 소품을 들거나 입고 중앙 | **사용 금지 — 2026-07-13 사용자 결정** (라이브러리 컷 포함 IAM 전면 미포함). 근거: 생성 캐릭터의 캐논 얼굴 재현 불가 — 등신비 강제·이중 앵커·헤어 핀을 다 걸어도 3연속 얼굴 드리프트 실측 (재도그푸딩 v2~v4). 레퍼런스 보드 25핀에도 3D 인형 캐릭터 씬 0핀 (blob 마스코트 액센트뿐). 대체 = 단일 의미-지시 소품. 캐릭터는 타 채널(카드뉴스 등) 전용 |
| **타이포-오브제 (생성)** | 풍선형 3D 레터링을 이미지로 생성 ("10x10") | **회피** — 글자를 이미지에 굽는 문법이라 번역 규칙 위반. 대체: 초대형 숫자 타이포 히어로 (위 행) |
| **실물 콘텐츠 콜라주** | 실제 상품 사진·콘텐츠 썸네일을 그래픽 프레임에 합성 (선물상자 속 상품, 부채꼴 웹툰 커버) | 브랜드 보유 실물 에셋 있을 때만 (`library`) — 생성 금지 |
| **포토 히어로** | 스튜디오 실사 or 모델 포토 | **생성 전면 금지** (스타일 4종 계약). 브랜드가 실사 자산을 제공한 경우만 `library` |

## 4. 오브제-메시지 메타포 정합 (핵심 룰)

관찰된 전 사례에서 오브제 = 메시지의 시각 은유. 장식이 아니라 의미다:

| 캠페인 의도 | 관찰된 오브제 |
|---|---|
| 쿠폰·할인 발급 | 절취선 쿠폰/티켓 (보드 최빈 5핀), 퍼센트 배지 |
| 적립·캐시백·페이백 | 코인 스택·동전 (보드 3핀) |
| 선물·보상 | 뚜껑 열린 선물상자, 봉투에서 나오는 쿠폰, 복주머니 |
| 초대·메시지 도착 | 봉투 (열리는 중) |
| 리마인드·알림 켜기 | 벨, 3D 토글 스위치 (ON 상태) |
| 등급·달성·랭킹 | 메달·트로피·배지 |
| 행운·랜덤 보상 | 클로버, 랜덤 캡슐 |
| 궁금증·미확인 혜택 | 물음표 오브제 |
| 점검·진단·설문 | 클립보드+체크/펜, 말풍선 |
| 마감·날짜 | 3D 일력/달력 (해당 숫자) |
| 혜택 잡기 | 낚싯바늘에 걸린 쿠폰 태그 (2개 앱에서 독립 관찰 — 검증된 은유) |
| 할인 규모 | 프레임을 압도하는 숫자 (200,000 / 75% / ~20%) — HTML 타이포 히어로 (§3) |
| 보안·잠금 해제 | 자물쇠 (열림 상태) |
| 약속·신뢰 | 새끼손가락 건 두 손 |
| 여행 | 미니어처 랜드마크 + 맵핀 |

기획안 `image.assets[].concept`에는 "무엇이 보여야 하고(오브제·상태) 무엇이 보이면 안 되는지"를
명시한다. 소품이 메시지와 어긋나면 오독을 만든다 — 의미 없는 소품은 빼는 쪽이 낫다.

## 5. 배경 = CSS 문법 (이미지 배경 금지) + 팔레트 공식

**기본 = 플랫 화이트/오프화이트 카드** (보드 ~16/25 지배). 배경은 무대일 뿐 —
위계는 오브제와 타이포가 전부 만든다. 변형 3형 (기본이 약할 때만):

| 변형 | 처리 | 적합 맥락 |
|---|---|---|
| (a) 상단 브랜드 워시 | 상단에서 소멸하는 브랜드색 미세 그라디언트 (동일 색상군 톤온톤만) | 화이트 기본에 브랜드 기운만 얹을 때 |
| (b) 비비드 단색 카드 | 브랜드 비비드 1색 solid 전면 + 텍스트 화이트 반전 (보드 4/25) | 브랜드 컬러가 강한 캠페인 |
| (c) 다크 + 오브제 글로우 | 딥컬러/블랙 + radial-gradient 스포트라이트, 오브제에 글로우 (보드 2/25) | 임팩트·긴급·프리미엄 |

- 장식 오브 (말풍선·컨페티·별 = CSS 도형 급 소형 요소, 4~6개 이하)는
  `image.assets`의 `source:"css"`로 선언 — 생성 비용 0, 빌더가 CSS로 그린다.
  동심원 리플 링(히어로 중심 radial-gradient 스텝, 화이트 저알파 밴드)도 CSS
  장식 어휘 — 알림·브로드캐스트 의미 캠페인의 배경 처리로 유효 (하단시트
  실캡처 관찰 2026-07-13). 톤온톤 계열이라 (a) 변형과 병용 가능.
- **대비 요건: 오브제 채도 > 배경**. 배경이 오브제보다 튀면 위계 역전 —
  파스텔 배경 + 파스텔 오브제(파스텔-온-파스텔 워시)는 금지 (§11, 재도그푸딩
  반려 2차 원인 — 유아톤).

**팔레트 공식** (보드 전수 관찰): **뉴트럴 바탕 + 브랜드 비비드 1 + 악센트 ≤1**.
히어로 오브제 = 비비드 필수. 고대비 기본 (파스텔 톤온톤은 보드 2/25 소수 예외).
브랜드 토큰 매핑은 활성 DESIGN.md 기준.

**그라디언트 취향 룰** (프로브 실측 2026-07-10): 웜→쿨 투컬러 수직 스윕 금지
(1차 프로브 크림→블루 배경, 사용자 판정 "촌스러움" — 도그푸딩 반려 원인 중 하나).
허용 3형: ① 단색 솔리드 ② 동일 색상군 톤온톤 그라디언트 ③ 다크 +
radial 스포트라이트. 팔레트는 항상 브랜드 토큰 기반.

## 6. 컴포지션 룰 (레이어 배치)

- **히어로 스케일**: 오브제 폭 = 프레임 폭 40~60%, **히어로 존 높이 = 카드 높이
  30~45%** (보드 관찰 밴드). 그보다 작으면 아이콘(§format-design-guide 모달
  문법)이지 히어로가 아니다.
- **카드 프레임**: radius 20~28px (브랜드 radius 위계가 있으면 활성 DESIGN.md
  우선), 닫기 ✕ 우상단, 텍스트·CTA 콘텐츠 폭 = 카드 폭 ~80% (좌우 여백 확보).
- **기울임**: 쿠폰·태그·티켓류는 5~15° 기울여 다이내믹하게. 정직한 수평은 정적 오브제(달력·토글)만.
- **콜라주 금지**: 분리 생성된 복수의 투명 PNG를 CSS로 겹쳐 물리적 상호작용(들다·
  얹다·기대다 등)처럼 조립하는 것은 **P0** (2026-07-10 도그푸딩 반려 원인 —
  원근·스케일 부정합으로 "콜라주 티", 물리 상호작용은 CSS 레이어로 재현 불가).
  물리적으로 맞물린 복합 오브제는 반드시 생성 단계에서 통합한다
  (`imagegen-pipeline.md` 통합 컴포지션 경로).
- **겹침**: 위 콜라주 금지와 별개로, 오브제-텍스트존처럼 **비물리적** 겹침(z-index로
  살짝 겹치는 배치)은 허용 — 단 헤드라인 가독을 해치는 겹침 금지. 오브제 상단이
  텍스트존 뒤로 지나가면 CSS mask 수직 페이드(하단 불투명→상단 투명)로 가독을
  확보한다 — HTML 레이어 처리라 "생성 후처리 금지" 계약과 양립 (pin-22 복제
  실측 2026-07-13). 물리 상호작용이 필요하면 위 통짜 통합 생성 경로로.
- **radius 스케일 잠금**: 카드·CTA·필·아이콘의 radius는 한 스케일 체계로 —
  혼합은 문서화된 위계(활성 DESIGN.md radius 위계)가 있을 때만 허용. 필 CTA +
  샤프 카드 같은 무근거 혼재 금지 (design-taste 흡수 2026-07-13).
- **부유감**: box-shadow 부드럽게 + `interaction-standard.md`의 float 애니메이션. 그림자를 PNG에 굽지 않는다 (배경색 바뀌면 깨짐).
- **산개 소품**: 위성 소품은 메시지 의미가 있는 것만 **≤2**, 히어로 대각 배치,
  크기 차등 (원근감). 전 코너 채우기 금지 — 여백이 히어로를 만든다.
- **시선 흐름**: 아이브로우 → 헤드라인 → 오브제 → CTA 수직 단일 흐름. 오브제가 CTA를 가리키듯 아래로 무게중심.

## 7. 텍스트 위계 (HTML 렌더)

- **아이브로우**: 12~14px, 시점·자격·긴급 ("매월 1일부터", "회원님께만", "곧 사라지는"). 악센트색 or 필 배지.
- **헤드라인**: 큼 (모달 20~26px, 풀시트 28~32px), 1~2줄. **악센트 키워드 정확히
  1개** (보드 ~9/25 관찰 — 2개 이상이면 위계 붕괴, 0개면 시선 앵커 부재).
- **숫자 = 최상위 위계**: 숫자 소구(할인율·금액·기간) 캠페인이면 숫자가 카드 최대
  타이포다 — 헤드라인의 ≥1.5배 허용 (보드 ~11핀: 숫자 > 헤드라인 다수). 단
  이미지가 아닌 HTML 대형 타이포로.
- **가격·조건 슬롯** (선택): 취소선 원가→할인가 병기, 카운트다운 칩 — §1 존
  스택의 가격·조건 존에 배치 (보드 취소선 3핀·카운트다운 2핀).
- **서브카피**: 1~2줄, secondary 색. 날짜·조건 등 구체 정보에 악센트색 부분 강조.

## 8. CTA·dismissal 문법

- **풀폭 필 단일 프라이머리가 기본** (보드 ~20/25): 주 CTA 풀폭 1개, 행동동사
  ("받기", "잡아보세요", "열어보기", "연동하러 가기"). 필 or 라운드 사각, **브랜드
  비비드 1색 or 블랙**.
- 질문형 CTA도 유효 ("어떻게 좋아졌을까?") — 호기심 전환, 업데이트 소개 맥락.
- 게임화 CTA (슬롯 STOP 등 인터랙티브)는 brazeBridge 제약 안에서만 — `interaction-standard.md` 준수, 과욕 금지.
- dismissal: **회색 텍스트 링크가 기본** (보드 ~14/25) — "다시 보지 않기"·"N일간
  보지 않기", 무게 최소화. 유머 톤 dismissal ("아니, 귀찮아")은 브랜드 보이스가 허용할 때만.
- 닫기 ✕ 우상단 상시 (`iam-close`).

## 9. 시즌·캠페인 스킨

시즌 캠페인은 배경·장식·소품만 갈아입고 문법은 유지: 설날 = 복주머니·소나무·학·기와 실루엣,
봄 = 꽃잎 그라디언트, 연말 = 컨페티·폭죽. 시즌 요소는 `css` 장식 or `generate` 소품으로 선언.
시즌에도 히어로는 단일 의미-지시 소품 — 캐릭터는 IAM 미포함 (§3), 배경은 §5 문법 유지
(시즌이라고 환경 묘사 씬으로 가지 않는다).

## 10. 씬 카드 문법 (scene 모드)

> **존치 보류 (2026-07-13)**: 레퍼런스 보드 25핀에 "카드 전체 생성 씬" 문법이
> **0핀** — scene 모드는 보드 문법 개정 후 재도그푸딩(소품 히어로) 실무 판정을
> 거쳐 존치/축소/폐지를 결정한다. 그 전까지 신규 캠페인 기본은 layer 모드.

`image.mode: "scene"`일 때 §1~§9의 존 스택·텍스트 위계·CTA 문법은
그대로 유지되지만, 배경 처리와 히어로 생성 방식이 layer 모드와 갈라진다.

- **카드 전체 = 생성 일러스트 씬 1장** — 배경까지 포함해 통짜로 생성한다 (`imagegen-pipeline.md`의
  알파 검증은 이 경로에서 skip — 씬은 불투명 배경이 정상이므로).
- **텍스트 절대 금지**: 씬 안에 글자·숫자를 굽지 않는다. 텍스트는 여전히 **HTML
  오버레이** (인트로 번역 규칙 불변).
- **STRICT 세이프존** (생성 프롬프트에 명시 강제 — 미지정 시 CTA가 히어로를 덮는
  결함 실측, 1차 프로브):
  - 상단 ~32% = 순수 배경 여백 (헤드라인 오버레이존 — 아이브로우+헤딩+본문 3줄
    실소요 ~32% 실측 2026-07-13, 구 계약 28%는 본문-히어로 충돌 발생)
  - 하단 ~22% = 플랫 지면·저디테일 장식만 (풀폭 CTA 오버레이존)
  - 히어로 클러스터 = 중간 밴드(32~78%), 캔버스 폭 ~60%
- **히어로**: 단일 의미-지시 소품 (§3 — 캐릭터는 IAM 미포함, 씬에서도 동일).
- **미니멀 씬 미학** (재도그푸딩 반려 실측 2026-07-13): 씬 배경은 "장소"가
  아니라 추상 컬러 필드다 — §5 그라디언트 허용 3형 팔레트의 스튜디오형 배경.
  환경 묘사(하늘·구름·수풀·나무·언덕·지평선·스파클 씬)와 스토리북/유아
  일러스트 톤은 금지(사용자 "동화책 같다" 반려). 위성 소품은 메시지 의미가
  있는 것만 ≤2. 구 계약의 "엣지 블리드 장식(폴리지·구름·컨페티)"은 이 반려로
  폐기 — 프레임 경계 장식이 필요하면 브랜드 토큰 색 추상 도형(블러 오브·기하
  실루엣)만 (`imagegen-pipeline.md` 씬 스캐폴드가 프롬프트 정본).
- **그라디언트**: §5 그라디언트 취향 룰(웜→쿨 투컬러 스윕 금지, 허용 3형)을 그대로
  따른다.
- **발송본 HTML**: `background: url(<씬 에셋의 Media Library CDN URL>) center / cover`
  (placeholder 폴백 시 `url(__BRAZE_MEDIA__/scene-<id>.png)` + 프리뷰
  make_preview.py 기계 변환) + HTML 텍스트존(상단)·CTA존(하단) 오버레이.
- **캔버스**: 세로 1024×1536 생성 (모달 카드 aspect).
- **§2와의 관계**: scene 모드는 주로 센터 모달·풀시트 유형에 적용되지만, 레이아웃
  유형 선택 자체는 §2 5형 표를 그대로 따른다 — scene은 새 레이아웃 유형이 아니라
  해당 유형 안에서의 비주얼 처리 방식이다.
- **레퍼런스 근거**: 24장 중 풀시트 일러스트(설맞이 봉투류)·다크 히어로 블리드·
  풀이미지 카드 유형이 이 문법에 해당한다.
- 근거 아티팩트(프로브 3회차 채택안): `.tmp/braze-iam-probe/scene-a3.png`(채택
  씬), `probe-a3.png`(HTML 오버레이 최종 렌더) — 리포 외 로컬 프로브 아티팩트,
  저장소에 없음.

## 11. 안티패턴 (보드 25핀 + 24장 대조로 확정)

- 이미지에 텍스트 굽기 — 레퍼런스는 굽지만 우리는 금지 (번역 규칙, 양 모드 공통). 생성 프롬프트에 `no text` 상수 유지.
- 실사 생성 — 스타일 4종 계약 위반. 실사는 브랜드 제공 자산 한정.
- 히어로 없이 소품만 산개 — 시선 앵커 부재. 반드시 주 오브제 1개.
- 오브제-메시지 불일치 소품 — 오독 유발 (cardnews 소품-의미 룰과 동일).
- **풀 일러스트 씬을 layer 히어로에 생성** — layer 히어로는 투명 배경 단일
  소품이다. full illustrated scene·storybook 스타일은 생성 프롬프트 금지어
  (`imagegen-pipeline.md` Constraints 상수).
- **캐릭터·마스코트가 행동하는 히어로** — character doing action, mascot
  holding object 전부 금지 (캐릭터 IAM 전면 미포함, §3. 보드 25핀에도 0핀).
- **파스텔-온-파스텔 워시** — 파스텔 배경 + 파스텔 오브제 저대비 조합 (재도그푸딩
  반려 2차 원인 — 유아톤). §5 팔레트 공식(뉴트럴+비비드 1, 오브제 채도 > 배경)
  위반. 생성 프롬프트 금지어 `pastel-on-pastel wash`.
- **텍스트-비주얼 오버레이** — 히어로 비주얼 위에 헤드라인·본문을 얹는 배치.
  보드는 존 수직 분리 (§1) — 카드 표면이 배경이고 텍스트존과 비주얼존은 겹치지
  않는다 (scene 모드 세이프존 오버레이는 §10 별도 계약, 존치 보류).
- **layer 모드에서 배경 포함 생성** — layer 모드의 배경은 CSS 전용. 배경 포함 통짜 씬은 **scene 모드가 정식 경로**(§10 씬 카드 문법 참조)이며, layer 모드에서도 캐릭터-오브제 물리 상호작용이 필요한 히어로는 통짜 투명 생성(`imagegen-pipeline.md` 통합 컴포지션 경로)이 기본이다 — 이때도 배경은 투명, 배경 처리는 여전히 CSS.
- **콜라주 조립** — 분리 생성된 복수 투명 PNG를 CSS로 겹쳐 물리 상호작용처럼 조립 (2026-07-10 도그푸딩 반려 원인). 상호작용은 생성 단계에서 통합한다 (§6).
- **웜→쿨 투컬러 수직 스윕** — 배경 그라디언트에 크림→블루 등 웜→쿨 스윕 사용, 사용자 판정 "촌스러움"(1차 프로브). §5 그라디언트 취향 룰의 허용 3형만 사용.
- **환경 묘사 씬 (스토리북)** — 구름·수풀·언덕·지평선·스파클로 "장소"를 그리는 씬 배경 (2026-07-13 재도그푸딩 반려 — 사용자 "동화책 같다·유아틱"). 씬 배경은 §10 미니멀 씬 미학의 추상 컬러 필드만.
- **캐릭터 치비화** — 시트 캐논(~6등신 성인 비율)을 4등신 치비 마스코트로 재해석 (2026-07-13 재도그푸딩 반려, 양 모드 공통 드리프트). 생성 프롬프트 등신비 강제(`imagegen-pipeline.md`) + 검수 등신비 실측이 방어선.
- 모달 안 콘텐츠 과적 — 목록 4개면 하프시트 (`format-design-guide.md` §0).
